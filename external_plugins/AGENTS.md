# 独立插件开发约束

本文件约束本目录中的独立插件实现；接口与分发说明见[插件开发指南](../docs/guides/plugin-development/README.md)。插件业务保存在各自包内，不能为了外置插件继续在宿主保留对应业务服务。

## 配置入口

- 普通持久化配置默认通过 `settings.define` 声明，由宿主的专用插件设置全屏弹窗统一展示、校验和保存。
- 插件不得自行实现配置弹窗、设置页或一套配置保存表单。确有标准设置中心不能表达的业务需求时，先说明具体原因并获得用户明确确认，不因方便而绕开默认入口。
- 插件页面需要设置入口时，调用该插件绑定的 `SDK.ui.openSettings()`，打开同一个设置中心并选中自身；不要实例化或复制宿主设置组件。
- 单行值使用 `string`，多行文本使用 `text`，有限选项使用 `select`。不为单个插件增加宿主中的专用字段或特殊渲染分支。
- 配置值只有改变后才提交；使用宿主确认的内容身份、定义版本和值版本，失败保留用户输入并允许重试，不把提交受理当成保存完成。
- 房间码、端口等当次操作参数仍属于业务流程，可放在业务页面；它们与需要长期保存的插件偏好分开。

## 依赖与边界

- 声明实际所需能力，选择资源须经用户批准；配置声明本身不要求主窗口注入权限。
- 可选兼容能力通过公开跨插件契约接入，不把可选插件写成硬依赖。
- 不导入宿主私有业务模块。Worker 隔离不是恶意 Python 的操作系统沙箱，主窗口注入也不能描述成受限 iframe。
- 子进程、线程、网络和页面监听有明确关闭路径；禁用、卸载、撤权及失败清理不得遗留活动资源。
- 插件有自己的版本、作者、依赖锁、许可证和包；本地构建不代表跨平台或外网端到端验收。

更改配置、界面或生命周期后执行对应的定向测试和真实界面检查，提交当前插件及确有必要的通用接口修改，不夹带无关宿主重构。
