# 可访问性定位重绑与扫描一致性复核（2026-11-08）

处理 [#100](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/100)：主分支工程治理门禁持续报告“当前范围存在无匹配的失效例外”。

本轮不改界面，只解决两件事：例外定位随界面改版失效，以及基线在 Windows 生成、门禁在 Linux 执行导致场景节点数不一致。使用真实 Vue 页面、Playwright 1.58.0、Chromium 145.0.7632.6 和 axe-core 4.11.1，在 Windows 完成全部 31 个场景。原始报告位于 `output/governance-accessibility-2026-11-08/frontend-accessibility.json`，SHA-256 为 `5d730ae3ecdae6c86a12c7d2730bebedd69b3300b4c31c0008c5225527a44290`。

## 根因

1. **定位依赖构建期噪声**：axe 原始定位包含 `data-v-*` 作用域哈希和整链 `nth-child`，任何组件样式或结构改动都会让全部定位失效。上一轮 747 个定位中有 142 个已失配、130 个当前位置无批准。
2. **两端扫描的不是同一份 DOM**：`InstanceDetailOverviewTab.vue` 按 UA 判断 `isWindows` 决定是否渲染“快捷方式”区块。Linux CI 扫描到 735 个位置，Windows 本机扫描到 747 个，差集正好是该区块。例外在 Windows 生成，门禁在 Linux 执行，因此无论怎样重绑都会继续失败。

## 本轮处理

- 扫描器改为生成语义锚点定位：优先 `data-testid`、`data-theme-component`、`aria-label`、`title`、`name` 与稳定类名，其次以最近的唯一祖先为锚点拼接相对路径，最后才退回完整结构链。定位不再包含 `data-v-*`，并逐节点验证唯一性。
- 扫描上下文固定为 Windows UA，Linux CI 与 Windows 本机扫描同一份 DOM；Windows 专属区块因此也进入 CI 覆盖。
- 例外表按新报告重绑 747 个定位，保留规则、场景、仓库、原因、关联问题、责任人与风险分类。

## 验证与遗留

- 当前 Windows 报告通过主仓库治理工具校验，检查数量为 31，`exceptions.json` 中该范围共 31 条、747 个定位。
- 固定 UA 后的 Linux 扫描结果需要在本轮推送后核对。平台字体渲染差异仍可能影响个别位置的测量状态，出现新发现时按实际报告处理，不接受自动放行。
- 本记录只覆盖普通文字的当前背景对比度，不外推为全部 WCAG 合规；真实启动器 WebView2、辅助技术和其他滚动状态仍按 `accessibility.md` 单独验收。
