# ADR-005：插件 API 版本契约与分域兼容承诺

- 日期：2026-11-13。
- 状态：待用户确认，未实施。

## 问题

平台化要求对插件作者给出可依赖的兼容承诺，但当前版本机制只有形态没有策略：

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `plugin_api/contracts.py` | `ProtocolPolicy.api_version: ClassVar[int] = 2` | 单一常量，无支持集合 |
| `plugins/installation_store.py` | `api_version: StrictInt = Field(ge=2, le=2)` | 唯一合法取值，v3 插件无法安装 |
| `plugins/runtime/supervisor.py` | 握手时 `api_version != 2` 直接拒绝 | 宿主无法同时运行两个契约版本 |
| `plugins/runtime/broker.py` | `runtime.info` 已返回 `launcher_version` | 能力已具备，但没有消费方 |

同时 `AGENTS.md` 第 2 节规定"不默认承诺内部配置、IPC、自有持久化格式和模块接口的历史兼容"，这是早前未发布阶段的合理默认，但作为平台的基础前提是直接冲突的。

本 ADR 决定两件事：版本如何声明与协商，以及哪些面进入承诺范围。

## 选择

### 1. 三个正交的版本维度

插件清单声明三个字段，各管一件事情：

| 字段 | 类型 | 语义 | 决定方 |
| --- | --- | --- | --- |
| `api_version` | 整数，单调递增 | 契约主版本。宿主必须**完整支持**该版本才能加载 | 宿主发布时确定 |
| `min_launcher` | 可选字符串，PEP 440 | 启动器版本下限，仅用于依赖某个具体修复 | 插件声明 |
| `features` | 字符串数组，白名单 | 使用的**可选能力**，例如 `panels`、`webview`、`hot_reload` | 插件声明 |

`min_launcher` 与 `api_version` 必须解耦。启动器每个小版本都会发，但契约一年可能只变一次；若以启动器版本作为兼容依据，每次发版都会变成兼容性事件。

**不设 `target_api_version` / `target_launcher`。** 安卓的 `targetSdkVersion` 行为分叉要求宿主为每个目标版本长期保留旧行为分支，这与第 2 节"不为兼容保留废弃实现"直接冲突，也无法在现有维护能力下逐个版本验证。需要改变行为时走显式的方法增补与废弃，不靠包级开关。

`features` 是对安卓式 `@RequiresApi` 的替代：版本号无法表达"我只用了可选的 panels、没用 webview"，宿主只能整包拒绝或整包放行。显式能力声明让老宿主精确拒绝、新宿主精确放行，并且错误信息可以直接告诉用户缺哪个能力。

### 2. 协商发生在两个时点

安装期（`WorkerManifest` 校验）与引导期（`hello` 握手）都必须校验，两处都失败即不加载，不允许"先装后用时报错"：

| 条件 | 错误码 | 安装期行为 | 引导期行为 |
| --- | --- | --- | --- |
| `api_version` 不在宿主支持集合内 | `PLUGIN_API_VERSION_UNSUPPORTED` | 拒绝安装，保留已下载文件 | 拒绝加载 |
| `min_launcher` 高于当前 `__version__` | `PLUGIN_LAUNCHER_VERSION_UNSUPPORTED` | 拒绝安装并提示所需版本 | 拒绝加载 |
| `features` 含未知能力 | `PLUGIN_FEATURE_UNSUPPORTED` | 拒绝安装并列出缺失能力 | 拒绝加载 |
| `features` 声明合法但该能力在本运行未启用 | 不报错 | 安装通过 | 由能力自身 API 返回既有错误码 |

宿主维护 `supported_api_versions: frozenset[int]`，运行会话记录该插件协商到的契约版本，门面据此决定可用方法集。首个支持集合为 `{2}`；引入 v3 时扩展为 `{2, 3}`，v2 插件行为不变。

### 3. 兼容承诺按域划分

不是"全都承诺"，也不是"全都不承诺"，而是按域区分：

| 域 | 位置 | 承诺强度 |
| --- | --- | --- |
| 插件 API 门面 | `ECL/plugins/api/` 六个门面 | **承诺**：方法名、参数结构、返回结构、稳定错误码 |
| 插件清单字段 | `WorkerManifest` | **承诺**：只增不删；新增字段必须有默认值 |
| 插件包与实例目录格式 | `.eclplugin`、实例目录 | **承诺**：生态地基，变更须走迁移 |
| 权限标识与语义 | 权限声明 | **承诺**：标识稳定，语义可收紧不可放宽 |
| 扩展面方法签名 | `tools.` / `crash.` / `compat.` / `auth.` / `plugins.` | **弱承诺**：只承诺"存在且不静默失败"，签名可变 |
| 前端 IPC 命令 | `ECL/api/registry.py` 241 个命令 | **不承诺**：仍属内部契约 |
| 内部模块、类、日志文本 | `ECL/plugins/`、`ECL/services/` | **不承诺** |

前端 IPC 有意排除在承诺之外。第三方插件的界面能力只能经 Worker API 与声明式面板获得，不允许直连这 241 个命令；一旦承诺，等于把 241 个命令的方法面全部冻结，且把宿主内部结构变成对外接口。

### 4. 废弃流程

新方法先增后删，不原地改语义：

1. 新增替代方法，旧方法保留并在文档标注废弃，起始 `api_version` = N+1。
2. 废弃期至少一个大版本，期间两条路径都可用、都有测试。
3. 移除只能在 `api_version` 主版本递增时发生，并在发布说明列出。

废弃期内并存的是**两个显式方法**，不是同一个方法按版本切换行为，因此不产生隐藏分支。

## 与 `AGENTS.md` 的冲突

第 2 节现有表述需要修订为分域承诺，建议改动三处：

1. 开头段的"不默认承诺内部配置、IPC、自有持久化格式和模块接口的历史兼容"改为按上表分域：插件门面、清单字段、包与实例格式、权限标识进入承诺；前端 IPC、内部模块不进。
2. "内部契约变更同步更新生产方、消费方…并移除废弃入口；不得主动增加旧字段别名"需要为承诺域增加例外：承诺域内的废弃必须保留一个主版本，不允许随改随删。
3. 新增一条：承诺域的破坏性变更必须在发布说明中单独列出，并同步提升 `api_version`。

第 2 节其余条目（不覆盖用户存档、不为旧格式新增后台清理流程、备份与回滚属于数据安全）继续有效，不受本 ADR 影响。

## 验证

- 清单校验：`api_version` 越界、`min_launcher` 过高、`features` 未知三种情况分别返回既定错误码，且不留下半安装状态。
- 握手校验：伪造不兼容 `api_version` 的 Worker 被拒绝，错误码与安装期一致。
- 多版本并存：`supported_api_versions = {2, 3}` 时，同一宿主分别加载 v2 与 v3 测试插件，两者都可用，且 v2 插件看不到 v3 新增方法。
- 门面稳定性：契约测试固化六个门面的方法名与参数结构快照，任何非预期变更导致测试失败。
- 文档一致性：`protocols/eclplugin-package-format.md` 与 `guides/plugin-development/` 同步列出三个字段与错误码。

## 影响

- 插件侧：清单增加两个可选字段与一个可选数组，无破坏性改动；现有 v2 插件无需修改。
- 宿主侧：`ProtocolPolicy` 从单常量改为支持集合，`supervisor` 与 `installation_store` 的校验改为查集合，改动集中在 3 个文件。
- 工程约束：承诺域内的改动从"随时可改"变成"需要版本与废弃周期"，这是本次最主要的成本。
