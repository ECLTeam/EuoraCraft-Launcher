# 第三方插件 Worker 管理器接入实施方案

日期：2026-10-20（Asia/Shanghai）。状态：用户已明确确认“开始实施”；本轮管理器接入已实现，验收记录见第 10 节。

本方案细化已批准的 [Worker/API v2 总体设计](plugin-worker-api-v2-implementation-design.md) 中 P06 尚未接线的管理流程，并纳入这一流程必需的安装身份、授权管理入口、短操作提交控制和最小权限界面。既有总体设计的批准不因本文失效；本文用于确定本轮具体交付边界，不代表整体首版完成。

现行入口统一采用 `ECL.bootstrap`、`ECL.plugin_api` 和 `--headless --role plugin`，以 [无头运行说明](headless-runtime.md) 为准。原生自定义前端继续按 [原生隔离增补方案](plugin-native-webview-isolation-design.md) 暂缓。

## 1. 目标与范围选择

本轮目标：真实第三方示例插件完成“安装但不执行 → 审阅授权 → 启用 Worker → 调用命令和修改自身设置 → 撤销授权 → 拒绝新调用并清理运行资源 → 重新审阅后可再次启用”。目录和 `.eclplugin` 归档均通过同一运行边界。

此前讨论的路线与取舍如下：

| 路线 | 交付内容 | 取舍 |
| --- | --- | --- |
| 运行流程接通，本方案采用 | 安装身份、授权、管理器分流、最小 Host API、生命周期及必要管理界面 | 可以验证真实使用流程，改动同时涉及安装、运行及可信入口 |
| 完整管理界面优先 | 权限展示、状态展示和界面交互 | 运行层未接通前，难以验证实际启停、撤销和恢复 |
| 原生自定义前端优先 | 受限窗口、frame 与网络原生控制 | 需要独立原生构建链和真实 WebView2 安全验收，不能消除当前管理流程缺口 |

本轮只开放自身命令、设置、自查询和自身设置事件。实例、账户、Java、游戏、文件、网络、工具、联机、认证提供方、跨插件互操作及声明式页面按总体方案后续切片推进。不得因为这些方法暂未接线而从总体首版目录删除它们；依赖未实现必要能力的插件保持不可启用。

## 3. 安装身份、清单与数据保护

### 3.1 安装身份

- 由宿主生成随机安装身份，建立与安装来源和活动代码目录的持久对应。显示名称、版本号、客户端字段均不能替代安装身份。
- 同一仍存在的安装更新保留安装身份，但新的代码、权限、锁和 ABI 联合摘要必须重新审阅；不自动继承新内容的授权。
- 卸载成功后使该安装身份失去活动资格；重新安装生成新身份。保留的授权文件不能让同名重装获得旧许可。
- 启动时发现现存目录且尚无身份时，只登记一个未审阅安装，不转换旧权限，也不执行入口。记录损坏时保留原文件并明确失败，不能偷偷生成身份绕过故障。
- 身份与安装事务共同提交、恢复；目录替换成功但身份未提交不能误报安装完成。失败恢复磁盘内容，不自动恢复第三方旧进程内执行。

### 3.2 清单与版本边界

- 拟在 `plugin.json` 明确要求 `api_version: 2`，权限使用既有 `PermissionDeclaration` 契约；目录及归档共用严格校验，不通过入口 import 探测版本。
- 不支持或缺少版本声明的第三方插件显示明确不可运行原因，不增加旧 SDK 适配或主进程回退。系统插件依发行资源来源识别，不允许清单自选系统身份。
- `.eclplugin` 归档容器保持 v1，SDK 版本与归档版本分别校验。
- 旧第三方设置和授权原文件保留，不转换成 v2 默认许可，也不覆盖为新格式。v2 设置按安装身份维护明确版本和 revision；现有系统插件配置保持所属契约。
- 沿用完整锁、Wheel 校验、共享缓存和原子依赖安装。第三方依赖按 Worker 策略校验，不因宿主或另一 Worker 使用不同包版本而统一拒绝；标准库、API 和非法导入冲突仍拒绝。

本轮没有历史格式迁移，也不扫描删除用户存档、账户、缓存或插件私有文件。安装备份、事务恢复及失败回滚继续保留。

## 4. 运行状态与管理器归属

管理器是每个第三方安装运行状态的唯一维护者，持有 WorkerSupervisor、PluginGrantSession、Broker 和清理回执。系统插件实例继续留在系统路径；不得把远程插件伪装成旧 Plugin 对象。

安装状态、审阅状态、运行状态、清理状态分别表达，不用单个 `enabled` 字段掩盖实际情况：

- 新安装提交成功：已安装、待审阅、未运行。
- 审阅已保存但必要权限不足：已审阅、不可启用，并列出具体缺少能力。
- 启用：复核内容与授权，创建并认证 Worker，许可加载后调用生命周期，实际成功才报告已启用。
- 禁用或撤销：先拒绝新请求，再使注册和回调失效，启动停止流程。进程树尚未回收时显示正在清理或清理失败。
- 重载：旧运行确认停止后才创建新 run；旧会话许可及对象引用不可用于新 run，永久许可仍受内容复核约束。
- 宿主退出：按依赖逆序关闭全部运行，清理订阅、回调与句柄；退出清理不把所有插件写成用户手动禁用。

每安装生命周期操作串行化；重复启用、重载和卸载不会创建多份运行。等待方超时或取消不等于线程、Worker 或宿主任务已停止。其他平台第三方入口明确拒绝，系统插件及普通桌面启动继续保持可用。

## 5. 最小 Host API 与提交控制

新增职责明确的插件 Broker，当前调用方为 WorkerSupervisor 的 `host_handler`。它把已有 RPC 接到授权服务和本安装命令、设置、事件服务，不暴露 FrontendApi 命令表，不使用反射转发任意方法。

| 方法 | 本轮行为 |
| --- | --- |
| `runtime.info`、`permissions.list` | 返回本运行必要摘要和实际权限，不能查询其他安装 |
| `commands.register/unregister` | 校验名称、基础字段 schema、回调标识；注册归属本安装、本内容、本 run |
| `commands.call` | 仅本插件已登记命令；校验输入输出、授权和调用存活状态；跨插件能力仍不开放 |
| `settings.define/get/set` | 仅自身设置；类型校验、expected_revision、原子提交及明确存储失败 |
| `events.subscribe/unsubscribe` | 仅自身 `settings.changed`，有界队列和递增 sequence；其他宿主事件待对应业务切片验收后开放 |

其余方法明确返回未实现或拒绝；不会返回空成功。只有通过功能验收的方法对应能力进入 `implemented_capabilities`。

每个请求使用连接绑定的主体，拒绝额外 owner、run 或安装字段。对变更请求沿用 HostClient 的 mutation_key，提供本运行内有界去重记录；同键不同载荷拒绝，超时不能自动重放已接受副作用。达到去重容量时拒绝新变更，不通过随意淘汰有效记录造成重复执行。

注册、设置写入和命令结果交付必须有授权 epoch 检查。注册与短写的提交准入按总体设计第 15 节处理：使用每安装锁明确撤销与提交接受的顺序，不在全局锁中等待磁盘、RPC 或插件回调。已获接受的单次提交可能完成，界面报告真实结果；撤销后不得接受下一次提交。此处只落实本轮短操作，不宣称完整 OperationManager 长任务改造已完成。

## 6. 可信管理入口与最小界面

- 接入总体设计的 `plugin_permissions_get`、`plugin_permissions_update` 和 `plugin_runtime_info`。请求 DTO、返回 DTO、稳定错误码、命令注册、IpcLogPolicy 与前端类型同步更新。
- 管理身份来自真实主 WebView 调用上下文及宿主登记。Worker、插件窗口、Dev Channel、未知入口和请求体伪造的 main 分类均拒绝；不能把 body 中的 `caller` 或 `window_label` 当成证明。
- 现有可信主界面可调用本安装命令和设置，第三方窗口不能借旧管理命令绕过 Broker。旧脚本、Vue、HTML、CSS 的提供及注入路径只接受系统可信来源；阻止第三方伪造宿主注入事件。
- 管理页复用现有 Naive UI、API、store 和模态机制，增加权限审阅、必要/可选说明、会话/永久选择、撤销入口与运行/清理状态。保存授权与启用分开操作，安装完成不代替运行授权。
- 安装依赖所需的 `allow_network` 与插件运行权限分别展示。未实现能力明确不可授权执行，不用勾选框制造可用假象。
- 本轮自定义窗口及声明式页面不开放。主界面权限页属于可信宿主界面，不加载插件提供的页面代码。
- 保存失败报告未持久化，清理结果单独展示；内容切换及页面卸载使旧请求失效。提交期间去重，失败后允许重试，关闭弹窗恢复焦点。
- 所有新增用户文案同步六种语言；主题和窗口验收统一遵循根目录 AGENTS.md 第 6 节。

## 8. 测试与验收

每个修复先建立可在接线前失败的回归，围绕下列行为验证，不以仅断言存在某个类或方法替代功能测试。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 插件顶层含写标记、安装或启动发现但未审阅 | 标记不存在；没有宿主 import、插件构造和生命周期执行 |
| 空权限插件、必要拒绝、必要能力未实现 | 空权限也须审阅；必要拒绝或未实现时不执行入口 |
| 目录与归档首次安装、重复安装、更新、重装 | 身份按规则保持或重建；摘要变化须重新审阅；安装成功不自动执行 |
| 同名系统/用户插件、SDK 缺失或错误、POSIX 平台 | 不可伪装系统来源；第三方明确拒绝；系统功能继续工作 |
| 真实主窗口、插件窗口、Dev Channel、伪造 body | 仅可信主窗口管理授权；伪造及非主入口无授权副作用 |
| 命令同步/异步、嵌套反向 RPC、错误 schema | 可正确返回；无双向死锁；错字段和错误结果被拒绝 |
| 重复 mutation_key、同键不同载荷、响应超时 | 单次提交；载荷冲突拒绝；不会因重试重复副作用 |
| 设置 revision 冲突、落盘失败、撤销与提交竞态 | 不丢失并发修改；保留原文件；按接受顺序报告真实效果 |
| 跨安装/跨 run 引用、迟到回调、事件队列满 | 拒绝错归属；迟到结果失效；有界且不静默丢可靠事件 |
| 禁用、崩溃、断连、必要/可选撤销、重载 | 新请求被拒绝；按撤销范围清理；停止结果和回执真实；旧 run 不污染新 run |
| 系统 QomicEX、启动钩子、插槽、普通启动和退出 | 系统插件既有行为不受第三方运行切换影响 |

检查命令及真实界面门槛统一引用 [AGENTS.md 第 6 节](../AGENTS.md#6-测试与验收)，不在本文另建简化标准。检查范围包含相关插件回归、完整后端 CI、主仓库与子模块集成、前端 check/build 和实际启动器验收；本机无法执行的 POSIX 分支须由对应环境验证并明确报告。

真实 Windows 验收使用专用临时数据目录和本轮测试插件，记录插件 PID 与宿主 PID 不同、进程树回收、命令结果、权限落盘及重启后状态。至少以真实 PyInstaller 与 Nuitka 发行物回归本次改动的管理器接线；先前冻结引导通过不代替本轮结果。不得通过批量终止本机其他启动器或游戏进程清理测试。

## 9. 阻塞、回滚与交付

- 若无法证明管理调用来源、撤销与提交顺序、进程树停止或冻结依赖实际来源，保持对应第三方能力关闭，报告具体证据；不通过旧主进程路径兜底。
- 安装回滚保留用户代码、设置、授权和事务备份；磁盘恢复与运行恢复分别报告。已提交设置不因撤销授权自动删除，已发生副作用不因 Git 回滚被宣称撤销。
- 本方案未扩大 OS 沙箱承诺，也未恢复原生自定义前端工作。若需要修改 Core、Florolding 公开接口或原生绑定，先说明超出本轮范围的位置。
- 用户审阅本轮范围后实施；完成的功能切片通过适用门禁后提交中文 Conventional Commit。涉及前端先完成子仓库交付，再提交主仓库指针。
- 完成时按 AGENTS.md 第 7 节检查 worktree 和原本地 main，保护无关改动并安全本地集成。分别报告提交、本地集成、远端推送和发布状态；本轮不执行远端推送或发布，历史文档中的授权记录不代替当前变更的推送确认。

## 10. 实施与验收记录

本轮由 `PluginInstallationStore`、`PluginWorkerService`、`PluginHostBroker` 分别维护安装身份、实际运行资源和最小 Host API。管理器按真实发行来源分流，第三方入口不能在宿主实例化。目录安装只登记，归档沿用活动版本指针与重启流程；卸载重装生成新身份，更新内容重新审阅。授权和设置原文件保留，不迁移旧 SDK 数据。

权限管理仅接受原生注入的已登记主 WebView。命令、设置、自查询和自身设置事件经过严格输入、所属运行、授权 epoch 与结果校验；变更回执有界去重，可靠事件溢出触发可观察的运行回收。撤销阻止新提交，已接受写入按真实落盘结果完成；Worker 已退出但宿主写入未结束时仍报告清理 pending。

前端新增六语权限审阅和撤销入口，保存审阅与启用分开，失败可重试。修复管理页/设置页将内容放入不渲染插槽的 Loading 组件、设置列表在 CSS 变量主题下触发颜色解析异常，以及受控文本输入失焦丢失修改的问题。设置提交验证 revision，失败不显示成功；列表清除已恢复的授权错误并显示监管服务的实际运行故障。
