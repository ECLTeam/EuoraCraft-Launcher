用户要求联机设置像其他配置项一样保存，节点链接的验证交由联机部分负责，并移除多余文字和独立的表单逻辑。本次与下述日志 B 方案共同实施。

截图中的“仅自定义”空地址在选择模式时便被拒绝保存，设置页展示了包含模型名、输入内容与文档链接的原始 Pydantic 错误。当前联机组件还自行实现保存快照、修订号、串行队列、成功提示、错误面板、失败重试按钮和卸载收尾；这些与其他配置项共用的设置流程重复。

调研基于本工作树的前端 `b9d4f4a`、后端 `bb4b81f`，并核对了日常 main 已完成同步的主仓库 `e08b1bb` 与前端 `999a0b3`。日常 main 已有工具页改动需要保留。

## 3. 设置页行为

- 页面只保留“联机”分组标题、“节点策略”选项、“自定义节点地址”输入区及地址示例占位。
- 移除策略下方说明、地址输入说明、底部自动保存与生效说明、成功状态、独立错误面板和重试按钮，清理无使用者的六种语言专用文案。
- 自动模式隐藏地址；切回其他模式保留已填写地址。设置模式时不清空节点，也不换成“最近一次验证成功”的旧节点。
- 模式选择和地址输入均调用共享 `settingsStore.patchConnector`，经现有按配置分区串行队列保存；不新增组件私有队列、修订号、恢复默认、手动保存或卸载保存机制。
- 空地址、尚未输入完整的地址和格式错误的地址均可以作为配置保存，不在设置页校验 URI、端口、节点可用性或“仅自定义必须非空”。
- 地址按行存储，保存时保留输入文本对应的行和空白；避免输入中的换行、光标和未完成内容被规范化回填改变。运行时再清理空行、修剪、校验和去重。
- 读取及磁盘写入失败复用其他设置已有的错误通知；读取未成功时不写默认配置，真实写入失败也不得显示成功。
- “联机设置”入口继续位于加入房间卡片标题行最右侧，导航定位和活动房间行为沿用现有实现。

## 4. 配置保存与联机校验的职责

### 配置保存

- 为前端增加明确的 `ConnectorConfig` 类型，字段仍为 `mode` 和 `nodes`，不改变已有 setting.json 的存储结构。
- 在 settings API / Store 加入 connector 分区读取、保存和局部更新，复用当前 `settings_get/set` 与共享写队列。
- 后端保存时仅验证配置结构和字段类型，不执行 URI 业务校验、节点去重、大小写规范化或非空策略校验。
- 移除 `ConfigStore.save_config` 对 connector 的运行时节点模型校验，改为配置结构校验。
- 现有 `connector_nodes_get/set` 暂保留为兼容的薄读写入口，遵循同一配置结构规则，不继续调用运行时 URI 校验器；新设置界面不使用它们。

### 联机使用节点

- 在联机领域区分“保存的原始配置”和“实际可用的节点”，原始配置通过轻量类型模型进入服务，地址解析和验证集中在服务使用节点的路径。
- 创建或加入房间时，自动模式直接使用公共节点，忽略隐藏的自定义地址草稿；公共与自定义、仅自定义模式才处理自定义节点。
- 处理节点时修剪并过滤空行、验证协议与地址、规范化和去重；仅自定义没有有效节点时拒绝连接，不隐式回退公共节点。
- 保留现有 URI 规则，不在设置页、通用配置存储和联机服务中重复执行同一套校验。
- 失败转换为简短的联机领域错误，例如“仅自定义模式尚未填写节点，请在联机设置中添加地址”或“第 2 行节点地址格式无效，请检查协议、地址和端口”。不直接返回原始 Pydantic 错误、输入字典和文档链接。
- 校验失败时保留已保存的原始配置，不回写规范化结果；当前房间不受设置修改影响。
- 当前 `join` 在进入 starting 状态后，于 try 范围外调用 `fetch_nodes`。移入连接准备的异常清理范围，或在状态迁移前完成节点准备，保证验证失败后不会卡在 starting 或留下迁移占用。
- 首屏预热只准备公共节点缓存；仅自定义模式跳过公共节点预热。预热不校验用户节点、不建立连接、不弹出地址错误。

## 8. 合并实施的日志 B 方案

### 目标和具体范围

- 沿用标准库 logging、当前完整日志 / 错误日志、轮转和前端终端协议，不引入新的日志框架或独立日志产品。
- 为注册表的全部正式命令定义中文操作名称和明确的业务操作、查询、轮询、日志通道策略；测试检查命令与策略完整对应，禁止新增命令后遗漏分类。
- 在注册用的最外层 `guard_ipc_handler` 统一记录开始、完成、失败响应、超时与取消。内部 `_ipc_handler` 不重复生成操作开始与完成记录；异常堆栈沿用实际异常捕获边界，只写一次。
- 后台任务返回时记录“任务已提交”，任务真实完成、失败或取消由执行方记录；取消请求不等同任务已经停止，线程中的超时不宣称线程已经终止。
- 日志通道命令不记录自身调用，轮询成功不逐次输出；重复轮询失败限频，恢复时记录一次，避免文件日志和前端事件循环刷屏。普通查询使用 DEBUG。
- 增加类型明确的操作上下文与日志辅助接口，使用操作编号和已有任务 / 进程标识关联阶段日志，记录耗时。跨手动线程、线程池和退出回调显式传播或保存关联上下文。
- 为 OperationManager 补提交、执行、阶段、完成、失败、请求取消、实际取消和归档失败记录；进度按阶段变化或固定时间间隔采样。
- 为账户切换 / 删除 / 刷新、配置保存、进程生成 / 停止 / 退出、游戏启动和命令执行、联机退出 / 踢人、插件命令与安装执行等补执行阶段或结果。已有完整更新 / 安装日志只调整文案与关联，不重复堆叠同一生命周期日志。
- 扫描主仓库项目日志消息模板，逐项把 `字段=值`、英文状态和装饰分隔改成中文说明。地址、协议、命令和外部程序原始输出中的合法符号保持原样，不全局替换日志内容。
- 业务摘要仅记录白名单字段；不遍历或输出完整 IPC body、账户文件、配置值、令牌、完整启动命令或标准输入内容。共享日志层为项目异常文本提供脱敏处理，保留有用堆栈。
- 将覆盖、级别、文案、后台任务和敏感信息规则写入 AGENTS.md。

1. 增加共享操作日志工具及 IPC 日志策略，策略映射归属类属性，不定义模块级脱类映射。生产 Python 新模块遵循标准文件头、类型和中文多行 docstring。
