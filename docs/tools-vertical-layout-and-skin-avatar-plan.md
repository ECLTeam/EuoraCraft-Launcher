## 当前项目情况与影响分析

当前主仓库前端指针为 `1696dc09207a0dea476b078e59adc8e3251ad842`。本工作树的前端子模块尚未检出，本次从共享主检出的前端 Git 对象读取该指针对应源码，未以其他分支的工作区内容代替当前版本。

`ConnectToolsTab.vue` 使用 `connect-tools-grid` 组合 `CustomDownloadCard` 与 `NatToolCard`。`Connect.css` 使用最小 300px 列宽的自适应网格，并将卡片靠上对齐。下载卡片比 NAT 卡片高，当前截图窗口中并排排列后形成右下方空白；新增工具后继续使用网格还会使阅读顺序随窗口变化。

下载卡片已经具备地址、保存目录、命名模式、覆盖保护、UA、请求头、进度、取消和重试。只有 UA 与请求头处于默认折叠区，其他保存选项占据主要操作区域。下载状态存放在现有 Pinia store，应继续复用。

`useAvatarRenderer.ts` 已通过 Canvas 提取脸部和帽子层，但现有展示渲染包含边距及帽子层放大，并非精确尺寸的方形头像导出。头像工具应独立定义导出规则，复用已验证的纹理区域处理思路，避免改变账户与联机头像展示。

文件 IPC 已提供 `select_image` 的 skin 用途，以及受大小限制的 `fs_read_file`。`image_save_as` 当前包含背景图标题、默认名称和取消错误语义，不适合直接作为头像导出入口。计划新增用途明确的 `skin_avatar_export` 命令，复用原生保存对话框和 `atomic_write_bytes`；不重写旧背景图接口。

布局与折叠调整难度较低；头像的像素处理、异步替换保护、真实桌面保存和 IPC 输入校验是主要实施与测试工作。影响范围包括前端工具页、文件领域 IPC、请求模型、命令注册与操作日志声明，不需要修改 Core、Florolding 或账户业务。

折叠的是设置与详情，三项工具的卡片标题和主要操作始终可见。下载选项只使用一层折叠，不把原有高级设置再嵌套进去。

采用原生 `details/summary` 或项目已有等价组件，支持键盘切换与可见焦点。下载执行中沿用字段禁用规则；折叠与展开不会停止轮询。NAT 检测状态与失败原因不会藏进详情；重新检测时清理旧结果，并保持既有重复请求及迟到响应保护。

## 皮肤头像裁剪规则

### 导入与预览

1. 使用现有 `select_image`，请求用途为 skin，原生选择器仅筛选 PNG；选择取消保留已有有效预览，作为正常取消处理。
2. 通过受限文件读取接口获取字节；本工具限制输入不超过 5 MiB。必须根据实际字节、PNG 签名与解码结果验证，不能只相信扩展名。
3. 兼容标准 64×64、旧版 64×32 及其整数倍纹理：宽为 `64 × scale`，高为 `32 × scale` 或 `64 × scale`，scale 为正整数，宽高不超过 1024。范围与现有衣柜策略一致。
4. 使用前端 Canvas 生成预览与导出 PNG，关闭图像平滑，以最近邻方式缩放并保留透明度。
5. 按当前项目纹理区域约定提取脸部：标准坐标 `(8, 8, 8, 8)`；帽子层为 `(40, 8, 8, 8)`，高清纹理按 scale 放大源区域。帽子层按相同输出范围进行 alpha 叠加，关闭时只绘制脸部。
6. 默认开启帽子层，输出尺寸默认 128×128；折叠设置中提供 64、128、256、512 像素四种方形尺寸，不引入自定义尺寸和额外缩放算法。
7. 无有效皮肤时导出按钮禁用；无效导入显示具体原因并保留上一个有效结果。设置修改后即时更新预览和摘要。
8. 快速连续选择文件或切页时，通过请求版本与卸载清理忽略过期解码结果，释放生成的 Object URL，不允许旧文件覆盖新选择。

首版仅处理本地皮肤文件；没有普通图片自由裁剪、账户皮肤抓取、衣柜写入、皮肤上传或 3D 头像渲染。

### 原生保存与边界

1. 新增 `skin_avatar_export`，接收有界 PNG Data URL 和输出尺寸，由请求模型校验字段类型、长度与允许的尺寸。
2. 后端严格解码 Base64，限制解码后内容不超过 2 MiB，并校验 PNG 格式、完整解码、单帧及实际宽高与声明尺寸相符。解码前限制图像尺寸，不仅依赖前端校验。
3. 校验有效后打开 PNG 专用原生保存对话框，标题为「导出皮肤头像」，默认名称为 `skin-avatar.png`；保存扩展名必须与 PNG 内容一致。
4. 保存目标以用户在原生对话框中的选择为准，IPC 不接受任意目标路径；覆盖已有目标沿用原生确认，并禁止选择本次输入文件作为输出目标。为执行输入保护，前端传递源文件路径，由模型及后端规范化并比较路径。
5. 使用 `atomic_write_bytes` 保存，失败保留已有目标；读写和图像校验放到明确的线程边界，保持事件循环可响应。
6. 用户取消返回成功响应且路径为空，不显示失败提示；真实写入失败返回稳定错误码。前端防止重复导出，结束后恢复按钮状态。
7. 在 `IpcLogPolicy` 声明中文操作名「导出皮肤头像」及操作分类，交由统一入口记录开始、结果和耗时。日志不输出 Data URL、文件内容、个人路径或内部编号。

后端验证及保存逻辑放到独立的小型服务模块，文件 IPC 仅负责请求转换、原生对话框与响应。新模块遵循主仓库 Python 文件头、类型、中文多行 docstring、原子写入及异常规范。
