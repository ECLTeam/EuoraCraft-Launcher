# 模组列表行高与运行实例空状态修复方案

状态：用户已确认开始实施。两项修复、完整检查、生产构建、实际 Windows 启动器验证及原项目目录本地同步均已完成。

## 1. 需求与当前问题

用户反馈实例管理模组列表在大量模组时出现文字重叠，并指出“已启动实例”无运行实例时的手柄占位没有符合统一列表空状态。

调研基线：主仓库 `caff2b4`，前端 `b1a2d53`。

- 模组列表是纵向 flex 容器，行默认允许收缩，仅设置了 58px 最小高度。名称、原名、文件名、版本作者四行信息超过这个高度，列表超出可用高度后文字溢出。
- 使用项目现有 CSS 和相同内容层级在 Chromium 中复现：960px 视口、400px 内容区，1 项模组行高约 89px；10 项及 272 项时行高压缩为 58px，文字区域约 73px，并溢入下一行。在浏览器临时禁止行收缩后，所有条目恢复自然高度且没有文字溢出。800px 视口下加载器标签换到第二行，同样会被压缩。
- `RunningInstancesTab.vue` 仍使用自定义 `.running-empty`、手柄图标及标题样式，没有采用资源包页及实例管理弹窗的默认 `NEmpty` 空箱。
- 原综合实施文档 R08 完成记录写为“使用同一空状态组件”，与当前代码不符，实施后需更正并补充可核验记录。

## 2. 方案与取舍

调研时提出两个可选方案，用户已确认按本文件实施方案 1：

1. 禁止模组行纵向收缩，行高按内容自然撑开，保留现有信息和省略规则，超过可用区域正常滚动。代价是同屏条目减少，但文字不会重叠。
2. 改为固定高度紧凑列表，将部分信息移到悬浮详情。代价是改变当前信息展示及交互，需要额外设计。

运行实例空状态按用户已指定的资源包页空箱基准处理：复用 `InstanceContentState`，使用默认 `NEmpty` 图标、颜色、字号和间距。原提示及刷新入口保留，加载、空状态和列表互斥。

以下步骤按已确认的方案 1 执行。

## 3. 具体修改

### 模组列表

- 在 `frontend/src/styles/views/instances/InstanceDetailModal.css` 禁止 `.mod-list-row` 收缩，保留自然行高及现有最小高度。
- 保留列表滚动及窄窗口网格布局，核对带译名与无译名、长文件名、加载器标签、图标和右侧操作的边界。
- 不通过裁切溢出文字掩盖行高问题。

### 运行实例空状态

- 在 `frontend/src/views/instances/RunningInstancesTab.vue` 用共用 `InstanceContentState` 替换内容区的 overlay 加载包裹及自定义空状态。
- 空状态描述沿用“当前没有运行中的实例”，提示说明及刷新按钮放入已有空状态操作插槽；仅为这些附加内容设置布局，不覆盖 `NEmpty` 图标及描述样式。
- 删除不再使用的手柄占位、粗体标题和专用图标容器样式，使空状态在工具栏下方剩余内容区居中。
- 保留顶部计数、刷新、实例终端、运行表格、退出确认、事件订阅、请求失效保护及错误提示逻辑。
- 首次读取及手动刷新期间只显示共用加载指示器，请求结束后显示列表或标准空箱；退出按钮的行内加载指示不变。
