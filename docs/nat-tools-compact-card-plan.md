# NAT 工具小卡片重建实施方案

> 日期：2026-10-01
> 状态：用户选择方案 1 并确认实施，已完成代码、自动测试、构建和运行验收。
> 第 1 至 9 节保留实施约定；实际结果与验收边界见第 10 节。

## 1. 目标与范围

移除「更多 → 工具」现有的大型 NAT 面板，重新构建紧凑的小卡片，直接调用现有真实检测接口。在同一卡片内展示空闲、检测中、结果和失败状态。

- 工具路由仍为 `/more/tools`，不新增弹窗或重复入口。
- 保持工具页与联机房间状态机解耦，不改创建、加入、退出房间的业务流程。
- 继续使用内置 EasyTier STUN 探测，不引入新检测库或外部安装流程。
- 修复本次相关的重复检测状态、错误反馈和探测资源清理问题。
- 不新增取消接口、历史记录、自动检测、权限设置或网络配置功能。
- 保留工作区现有的无关修改，不推送远端。

## 3. 选定布局

### 3.1 卡片结构

- 桌面卡片目标宽度约 340px，不铺满工具页、不居中。
- 工具布局使用网格，单列宽度最多约 340px；窄窗口缩至可用宽度，禁止横向溢出。
- 复用 `UiCard`、`UiIcon`、`UiButton`、`UiTag`、`UiLoading` 与当前主题变量，不重写通用组件。
- 使用 NAT 专属类名，避免继承 `connect-main-card` 的大面板样式。
- 标题行：小图标、NAT 检测标题和紧凑的检测按钮；按钮使用图标加简短命令文本。
- 空闲主体仅显示「尚未检测」状态，不放大图标、长篇说明或占位段落。
- 结果主体使用紧凑标签及无额外边框的字段行，不在卡片内部再嵌套卡片。
- 卡片圆角不超过 8px；保留当前主题透明度和颜色语义。
- 标题和按钮布局允许窄窗口换行；长地址、错误和较长语言翻译必须换行，不能互相遮挡。
- 检测中与空闲区域保持适当的稳定最小高度；结果和错误内容自然增高，不使用会截断文本的固定高度。

### 3.2 结果展示

- 优先显示详细 NAT 类型；锥形、对称、UDP 阻断和未知状态使用已有语义色。
- 显示公网地址及端口或端口范围，保留 IPv6 地址括号格式。
- 缺失地址显示「未获取」，不伪造地址或端口。
- IPv6 仅根据探测数据展示「已检测到公网 IPv6」或「未检测到公网 IPv6」，不把未检测到直接等同于不支持 IPv6。
- 未确定 NAT 类型但取得有效探测信息时显示「未能确定类型」，不把未知类型当成良好直连能力，也不宣称必然无法联机。
- 检测结果不承诺实际可直连，不改变既有房间。

## 4. 前端状态与接口对接

采用明确的互斥状态：`idle`、`detecting`、`success`、`error`，避免多个布尔值与结果组合出现不一致。

1. 用户点击检测才请求真实接口，不在页面进入时自动请求。
2. 请求开始时清除当前显示的旧结果及错误，优先展示检测中状态。
3. 请求进行期间禁用按钮，函数入口同样防止重复请求；不显示虚假的百分比进度。
4. 成功后展示最新结果，按钮允许再次检测。
5. 超时与失败在卡片内给出简短反馈并允许重试，不使用成功样式展示失败。
6. 组件卸载后不再写入该页面状态；返回工具页重新处于空闲状态，不新增持久化缓存。
7. 切页不会强制取消原生探测；依靠后端现有有界轮询及清理结束任务。不得把前端停止等待当成已经停止节点。
8. 使用既有 IPC 错误边界和前端错误处理，补充六种语言所需短文案，不增加全局错误机制。

成功响应保留 `NatTypeResult` 的现有字段，避免无关调用方与展示模式协议迁移。

## 5. 后端检测边界

### 5.1 结果与失败

- 沿用当前 25 秒轮询等待窗口，不在未验证的情况下随意缩短探测时间。
- 取得已知类型，包括 UDP 阻断，按正常结果返回。
- 轮询结束仍只有未知类型但存在有效地址等探测信息时，允许返回未知类型结果，前端明确显示未能确定。
- 没有可用探测信息而等待窗口耗尽时抛出 NAT 领域错误，由 IPC 返回 `CONNECTOR_NAT_TYPE_TIMEOUT`。
- 创建、启动或读取节点失败时保留日志与异常上下文，由 IPC 返回 `CONNECTOR_NAT_TYPE_FAILED`，不吞异常后伪装为成功。
- 并发检测采用服务级非阻塞锁；已有检测时返回 `CONNECTOR_NAT_TYPE_BUSY`，避免切页重进或其他调用方重复创建探测节点。
- NAT 专属错误放在 NAT 所属服务模块，遵循现有异常属性和 IPC 转换约定，不改所有联机错误的基类行为。

### 5.2 资源清理

- 锁在所有退出分支中释放。
- 临时节点的创建、启动与轮询纳入统一异常边界；已经创建的节点在 `finally` 中尝试停止。
- 停止异常需记录，不覆盖前面的检测失败原因。
- 复用房间节点时绝不主动停止该节点，不改变房间状态。
- NAT 并发锁只保护检测，不在整个探测期间持有房间状态锁。
- 现有轮询时间限制不能强制打断卡住的原生调用。本次不承诺硬取消或原生运行时故障后的强制回收；若实际验收发现该问题，单独报告并确认扩大范围。

## 8. 测试与验收

### 8.1 自动测试

- 前端：初始空闲；真实 API 调用参数；检测中禁用与重复点击；首次成功；再次检测不展示旧结果；失败重试；未知类型；缺失地址；IPv6 地址；端口范围；离页后忽略迟到响应。

### 10.3 验收边界与注意事项

- 原生窗口验收使用真实启动器服务、真实 Tauri IPC 和 EasyTier 探测。生产前端由临时回环 HTTP 服务托管，通过仅用于验收的临时 capability 允许该回环来源；未修改或提交生产 capability、启动适配器及安全配置。不是新的安装或运行要求。
- 实际网络探测返回了有效 NAT 类型；布局边界使用明确标记的前端结果替身，不把替身结果当作真实网络探测。
- 启动器原生窗口现有最小宽度为 960px，整页 CSS 另有 820px 下限。未把 390px 浏览器整页视为支持目标，也未扩大范围改全局响应式；小卡片的窄容器适配通过独立 200px 容器验证。
- 浏览器通过开发者通道进行快速切页时观察到连接关闭，原生 IPC 路径验收通过。本次未修改开发者通道传输代码，不宣称已解决该通道问题。
- 房间验收覆盖真实创建、探测时保持及退出，不代表已验证两台机器上的 Minecraft 游戏联机。
- 25 秒限制仍是轮询窗口，不能强制中断卡住的原生节点调用；没有新增取消能力。
- 测试截图、辅助脚本和构建产物位于仓库忽略的 `build/` 下，未纳入提交；隔离的测试数据目录在验收退出时清理。未创建仓库外的测试环境目录。
- 无关的 `docs/launch-advanced-options-plan.md` 修改保留，不纳入本次提交；本次仅本地提交，不推送远端。
