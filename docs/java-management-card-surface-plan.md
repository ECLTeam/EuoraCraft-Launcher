## 1. 问题与选定方案

Java 管理页直接渲染 `JavaManagerPanel`，组件根节点只有布局，没有卡片背景、边框或内边距。已安装条目和下载条目有各自底色，但搜索、扫描提示、空状态和下载来源说明直接叠在壁纸上；清单为空时尤其明显。

启动器、外观和游戏设置使用 `SettingSection` 的主题表面；工具页使用统一的 `UiCard`。本次采用一张 `UiCard` 承托整个 Java 管理区，保持项目已有卡片的背景、圆角、边框、透明度与主题效果。相比工具栏、结果区分为两张卡片，单卡片占用的间距更少，两个视图的整体边界也更清楚。

目标布局：

1. 卡片头左侧为「已安装 / 下载」，右侧为当前视图已有操作，底部使用现有分隔线样式。
2. 卡片体包含提示、搜索或下载筛选、内容列表、空状态与任务进度。
3. 无条目时卡片仍然完整显示，空状态在有内边距和适当高度的内容区域内居中。
4. 长列表沿用设置页面的滚动容器；窄窗口工具栏可换行，按钮、筛选与路径不产生横向溢出。

## 2. 修改范围与实现方式

| 文件 | 具体调整 |

| `frontend/src/features/java/components/JavaManagerPanel.vue` | 保留现有工具栏，将工具栏后方的可见内容整理进独立的内容容器，为页面提供明确的头部、内容区样式入口；确认弹窗保持原位置和交互。 |

| `frontend/src/views/settings/JavaTab.test.ts` | 补充页面卡片容器回归，覆盖空清单及视图切换后内容仍在同一卡片内。 |

卡片由 `JavaTab` 提供，`JavaManagerPanel` 继续只负责 Java 管理内容。全局、实例和缺失 Java 的恢复入口使用 `JavaManagerModal`，已有弹窗承托其内容；这条路径不增加嵌套卡片。新增内容容器在弹窗内保持原有内容间距，并核对新增包装不会影响原选择器、样式选择器与测试定位。

使用现有 `--card-bg`、`--ecl-surface-backdrop`、`--ecl-border`、`--divider` 和间距变量，不设置固定白色背景或新增透明度配置，不调整通用 `Card.vue` 及全局主题。页面无需重复增加「Java 管理」标题。

本次只调整页面容器和布局，保留现有标签、按钮与业务行为；不修改 Java 登记、下载、更新、选用、移除、IPC、持久化和文案。
