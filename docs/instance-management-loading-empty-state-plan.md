# 实例管理弹窗加载与空状态统一实施方案

状态：用户已选择方案 1、确认资源包页现有的空箱图标，并明确要求开始实施。代码、完整检查、生产构建和真实 Windows 桌面验收已完成。

## 1. 目标与验收标准

实例管理弹窗中的内容区采用互斥的加载、列表、空状态，统一使用现有资源包页的 Naive UI `NEmpty` 空箱图标及文字样式。

- 首次加载和手动刷新期间，内容区只显示项目现有的居中 `UiLoading`，没有遮罩、旧列表、空箱图标或无内容提示叠加。
- 请求完成且有匹配内容时显示列表；无匹配内容时才显示 `NEmpty`。
- 模组页的自定义拼图图标占位改为与资源包页一致的空箱图标，保留原提示及“添加模组”操作。
- 模组不受当前实例支持时也采用同一空状态样式，保留“不支持”的具体说明，不能显示一直加载。
- 各页加载图标和空状态在工具栏下方的可用内容区水平、垂直居中；窗口变化时不溢出，不因内容区变空而收缩到工具栏旁。
- 保留搜索、筛选、排序、刷新、导入安装、管理模式、启停、删除确认和下载导航行为。

## 2. 已调研的现状与方案选择

以主仓库 `eaa6973` 和前端 `d0a2297` 为调研基线。

| 位置 | 当前行为 |

此前对全局加载遮罩已移除模糊效果，但遮色层仍是 `overlay` 模式的正常功能。本次问题来自管理页的状态组合，而不是加载图标本身。

用户已选择：

1. 采用方案 1：加载、列表、空状态互斥，刷新时也暂时隐藏旧内容。
2. 空状态采用资源包页现有的 `NEmpty` 默认空箱图标，替换模组页自定义占位。

保留列表并叠加刷新遮罩的方案 2 不采用。

## 3. 修改范围与具体实施

### 3.1 共用实例内容状态组件

新增 `frontend/src/components/instances/InstanceContentState.vue`，负责实例管理内容区的状态切换及布局。

- 接收加载状态、是否为空及空状态说明，不负责请求、缓存、资源类型判断或业务操作。
- 加载优先：使用 `UiLoading` 的 `block` 模式，沿用默认 24px 图标和主题颜色；不使用 `overlay`，不新增自定义加载动画。
- 加载结束且为空：使用默认 `NEmpty`，不覆盖它的图标绘制、颜色或文字样式；提供操作插槽保留模组添加按钮。
- 有内容：呈现原列表插槽，保持业务组件状态；切换视觉状态不清空搜索、管理选择或已加载数据。
- 使用正常文档流和弹性布局占据剩余内容区，提供最低可视高度；避免靠空内容撑起遮罩高度。
- 保留加载指示器的无障碍说明，不同时宣告加载与“无内容”。

### 3.2 统一各管理页

| 文件 | 具体改动 |
| --- | --- |
| `InstanceDetailModsTab.vue` | 使用共用状态组件取代 `mods-spin` 遮罩；将无模组和不支持的自定义占位改为默认空箱样式；保留“添加模组”按钮和原说明。 |
| `InstanceResourcesTab.vue` | 替换遮罩结构，四类资源统一采用加载优先的互斥状态；保留数据包选存档、管理开关、批量删除和逐项操作。 |
| `InstanceWorldsTab.vue` | 存档列表采用统一状态；同文件游戏设置子弹窗存在同样的叠加问题，一并使用互斥状态和现有空箱样式，保留编辑、保存行为。 |
| `InstanceServersTab.vue` | 替换列表加载遮罩；服务器在线状态刷新仍通过原按钮指示，不将状态探测误判为整页列表加载。 |
| `InstanceScreenshotsTab.vue` | 替换截图列表加载遮罩；等待列表及缩略图处理完成后显示截图或空状态。 |

首次有效请求开始时立即进入加载状态，数据尚未返回时不显示空提示。没有有效目标或不支持模组管理时，遵循原业务判断，不创建无法结束的加载状态。

共用状态组件只呈现各页已经拥有的加载与内容状态。请求缓存、错误提示、请求失效保护和操作完成后的刷新逻辑继续由原业务组件负责。

### 3.3 弹窗布局与样式清理

修改 `frontend/src/styles/views/instances/InstanceDetailModal.css`：

- 将管理页内容伸展、居中规则对接新共用组件，移除对 `.ui-loading--overlay:has(.n-empty)` 的依赖。
- 清理不再使用的 `mods-spin`、`mods-empty` 等模组专用占位规则。
- 检索通用 `.empty-state`、`.empty-icon`、`.empty-text` 的真实使用范围，仅移除本次已失去使用者的弹窗规则，避免影响其他页面。
- 保留原有列表滚动、工具栏和窄窗口布局；有内容时仍按原列表规则排列，不使用空状态居中样式排列列表。

全局 `Loading.vue`、`Loading.css` 和实例列表的 `EmptyState.vue` 不需要改变语义。其他表单的遮罩及弹窗外的空状态不在本次范围内。

## 5. 测试与实际验收

新增或更新前端组件回归测试，用未完成的 IPC Promise 验证加载期间，而不是只验证请求完成后的页面。

- 首次加载时仅存在块级加载指示器；不存在 `NEmpty`、模组自定义占位、列表行和遮罩模式。
- 请求完成返回空集合后，加载图标消失，显示标准空箱图标及正确说明。
- 请求完成返回非空集合后显示原列表；筛选为零时显示标准空状态。
- 已有内容刷新时旧行暂时隐藏，空提示也隐藏；完成后恢复新结果，保留搜索及管理状态。
- 四类资源分别验证，并覆盖数据包选择存档、目标变化和原有失效请求保护。
- 模组不支持时显示标准空状态及原说明；无模组时“添加模组”按钮仍可导航。
- 存档页游戏设置读取期间不显示“没有检测到可编辑的游戏设置”，返回后显示原编辑器或标准空状态。
- 服务器状态探测不隐藏已加载列表；截图缩略图处理期间保持加载状态。
- 对失败请求验证加载状态按既有逻辑结束，错误反馈及已持有数据的处理不被呈现组件改变。
