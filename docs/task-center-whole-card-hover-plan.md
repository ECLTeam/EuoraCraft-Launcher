# 任务中心整卡悬停效果实施方案

日期：2026-10-13。

状态：用户已选择方案 A「整卡边框强调，阴影跟随主题」并确认实施；样式修改已完成。实施期间用户明确要求「不要测试了，直接修改」，因此本次跳过测试、构建和实际启动验收。

## 1. 需求与当前实现

任务中心的任务项由 `.tq-task` 包含标题、操作按钮、进度、统计和展开详情。当前 `.tq-task-header:hover` 仅改变标题区域背景，在卡片内部形成突兀的局部色块。

本次将悬停反馈移至整个任务卡片：鼠标位于标题、进度、统计、操作区或展开详情时，整卡边框轻微强调，阴影沿用主题效果。当前前端和主仓库工作区在调研时均干净。

## 2. 已选方案与视觉要求

此前比较了 A「整卡边框强调，阴影跟随主题」与 B「整卡底色轻微变化」；用户选择 A。

- 删除标题区域的悬停背景变化，卡片底色和展开详情底色保持现有主题表现。
- 为 `.tq-task:hover` 增加整卡边框强调，使用现有短时过渡，不增加位移、缩放或边框宽度变化，避免列表跳动。
- 待执行、已取消等普通状态沿用主题悬停边框；运行中保持主色，完成保持绿色，失败保持红色，通过适度增强同色边框的可见性表达悬停，不统一覆盖为主色。
- 整卡悬停阴影使用现有 `--control-glow`：Classic 按现有主题无额外阴影，Folia 使用现有轻微光晕。边框反馈在两种皮肤下均有效。
- 仅在本组件样式作用域内组织必要的任务状态边框变量或选择器，不调整全局主题变量和其他卡片。
- 卡片内部取消、刷新、移除按钮保留自己的悬停反馈；标题保留手形光标和键盘焦点轮廓。整卡仅增加视觉反馈，不将整张卡片改为展开按钮。

## 6. 风险与处理

状态边框与悬停规则可能因选择器优先级相互覆盖，真实浏览器测试必须检查各状态的最终颜色。主题阴影可能被滚动容器边缘裁切，实际窗口验收需检查首末任务卡片的边缘；反馈以整卡边框为基础，不通过扩大边距或增加位移补偿。展开详情保留独立底色，整卡外边框及阴影仍统一响应悬停。
