## 1. 需求与现状

当前问题已经通过源代码核实：

- 在线存档下载也使用 `_import_world_source`；本地选择器和文件名策略不能破坏在线下载临时归档的处理。

## 2. 可选方案

### 方案 A：按资源类型统一后缀与目录规则（推荐）

由后端资源策略提供各类型允许的后缀，原生选择器、安装入口和列表扫描使用同一规则。扫描时先过滤，再读取元数据、图标及哈希；文件后缀比较不区分大小写。资源目录只有符合明确包结构的目录才显示。

这种方式直接解决无关文件显示及错误类型安装问题，扫描开销可控。符合后缀但内容损坏的文件仍可显示并由已有解析流程报错，方便定位、删除和重新安装。

### 方案 B：在方案 A 基础上严格校验每个文件的内部结构

除后缀外，扫描及安装都检查 ZIP 内容或 NBT 格式。可以识别伪装后缀文件，但需要处理更多格式差异，增加读取开销；损坏的包可能从列表消失。第三种投影格式的结构识别也会扩大本次修改范围。

用户已选择方案 B。以下具体步骤执行后缀和内部结构两层校验；安装拒绝无效内容，列表不显示不符合规则的内容，磁盘上的文件保持原样。

## 3. 已确认的类型规则

| 页面 | 本次本地安装接受的内容 | 列表扫描规则 |
| --- | --- | --- |
| 光影包 | 有效 `.zip` 光影包 | 仅后缀和光影结构均符合规则的 ZIP |
| 数据包 | 有效 `.zip` 数据包 | 有效 ZIP 及含有效 `pack.mcmeta` 的文件夹包 |
| 投影／原理图 | 有效 `.litematic`、`.schem`、`.schematic` 文件 | 仅后缀与对应投影结构符合规则的文件 |
| 资源包 | 保留现有有效 ZIP 及目录包兼容能力 | 有效 ZIP 及含有效 `pack.mcmeta` 的文件夹包 |
| 存档 | 存档文件夹、`.zip` 文件 | 列表继续表示已导入的世界目录；ZIP 导入后解压成目录 |

用户已确认：数据包列表保留含有效 `pack.mcmeta` 的文件夹包，新安装入口只接受 ZIP。资源包不新增目录选择按钮，已有拖入／IPC 的有效目录包安装能力保持兼容。

后缀规则不接受 `.zip.bak`、`.schem.txt` 或用资源后缀命名的文件夹。点开头的临时文件继续跳过。此次不调整模组的安装、禁用后缀及列表协议。

投影的安装和列表识别三种结构，不等于三种文件都新增启动器内预览。现有预览解析器主要面向 Litematica 与 Sponge；传统 `.schematic` 的预览兼容属于另一个解析功能，保持现有错误提示与解析能力。内容校验不能调用预览入口来判断文件是否有效，避免把预览暂不支持或超过预览体素数量的有效文件误判为无关文件。

### 3.1 ZIP 与包元数据校验

- ZIP 必须能读取中央目录，参与结构判断的成员必须能够解压、通过 CRC 检查；不能把改名后的文本、其他格式文件或损坏 ZIP 当成包。这里校验的是包结构，不逐个解析所有材质、数据 JSON 或编译着色器，也不全量解压大型包。
- 光影 ZIP 中存在可识别的 `shaders/` 目录，兼容 ZIP 根目录及外层包装目录内的 `shaders/`；不强制存在 `shaders.properties` 或固定着色器文件名。此规则参考 [Iris 官方的光影包识别实现](https://github.com/IrisShaders/Iris/blob/1.21.1/common/src/main/java/net/irisshaders/iris/Iris.java)，避免只检查 ZIP 根目录而隐藏现有有效包。
- 资源包、数据包的根目录 `pack.mcmeta` 必须是可解析 JSON 对象，包含合法 `pack` 对象和描述；兼容传统 `pack_format` 以及新版 `min_format`／`max_format` 表示，不硬编码当前游戏的版本号，也不因兼容版本范围不同而隐藏包。新版元数据规则参考 [Minecraft 官方格式变更说明](https://www.minecraft.net/en-us/article/minecraft-snapshot-25w31a)。
- 有效文件夹包使用同一元数据规则，不能仅凭目录名或 `pack.mcmeta` 文件存在就通过；不强制包必须包含非空 `assets/` 或 `data/`，避免额外限制仅元数据、覆盖层等包结构。
- 缺少元数据、非法 JSON、错误字段类型等拒绝安装，并从扫描结果中过滤；图标缺失、图标损坏或无法解码仍沿用占位图，不能作为隐藏一个有效资源包的原因。

### 3.2 投影内容校验

使用现有 NBT 读取能力，在构建预览体素之前识别文件结构；不能把普通 NBT 存档或 ZIP 改名当成投影。保留 gzip 和项目现有未压缩 NBT 的读取兼容。

- `.litematic`：检查 `Regions`、区域 `Size`／`Position`、`BlockStatePalette`、`BlockStates` 的类型及尺寸、存储长度关系；兼容负方向区域尺寸及项目已有坐标表示。主要字段依据 [Litematica 官方读写实现](https://github.com/maruohon/litematica/blob/master/src/main/java/litematica/schematic/LitematicaSchematic.java)。同时保留项目现有可解析的简化根元数据表示，不为本次过滤强制补齐作者等非结构字段。
- `.schem`：识别 Sponge v1／v2 的尺寸、调色板和 `BlockData`，以及 v3 的 `Schematic` 包装与 `Blocks` 数据容器；校验版本、字段类型、数据数量及索引范围，避免只支持项目测试中带 `Size`／`Blocks` 的简化布局。保留该已有简化布局兼容。结构依据 [Sponge v2 规范](https://github.com/SpongePowered/Schematic-Specification/blob/master/versions/schematic-2.md)及 [Sponge v3 规范](https://github.com/SpongePowered/Schematic-Specification/blob/master/versions/schematic-3.md)。
- `.schematic`：识别传统 MCEdit／WorldEdit 的 `Materials: Alpha`、`Width`／`Height`／`Length`、`Blocks`、`Data`，并检查可选 `AddBlocks` 与体积的关系；不把 Sponge 数据仅换成这一后缀就视为传统格式。依据 [WorldEdit 官方传统格式读取实现](https://github.com/EngineHub/WorldEdit/blob/master/worldedit-core/src/main/java/com/sk89q/worldedit/extent/clipboard/io/MCEditSchematicReader.java)。
- 损坏、缺少必要结构、后缀与结构不匹配的投影不显示，并明确拒绝安装。对于现有 NBT 读取预算无法校验的超大文件，安装显示“文件过大，无法校验”，不谎称格式错误。

### 3.3 校验开销与结果处理

- 后缀、文件类型先过滤，符合后再检查 ZIP 元数据或 NBT。扫描不生成 3D 体素数组、纹理或预览会话。
- NBT 读取沿用已有 `load_limited`，初始解压预算为 64 MiB；超出预算的文件不会进入本次严格过滤后的列表。该限制属于内容校验预算，与预览体素预算分开，并纳入验收。
- 包元数据使用有界读取，初始预算为 1 MiB；图标的现有独立限额和降级行为保持不变。
- 对列表内容校验使用有界的短时结果缓存：最多 512 项、最多 10 秒；键包含资源类型、绝对路径及文件大小、纳秒修改时间等状态。目录包的键包含 `pack.mcmeta` 的状态。文件变化、过期、安装或删除后重新验证，缓存只存校验结论，不长期保留 NBT 或归档句柄。
- 安装预校验及提交前检查绕过列表缓存；复制到临时目标后再次核对内容，在通过前不替换正式文件，防止预检后源内容变化。
- 单个条目校验失败不阻断整个列表；过滤日志仅记录类型、文件名及稳定原因，不记录完整隐私路径。通过“打开目录”仍能找到被过滤的文件。

## 4. 具体改动点

### 4.1 后端资源策略、扫描和安装

- 在现有 `ResourceCatalogPolicy` 中集中定义后缀及目录规则，使用独立的内容校验职责实现 ZIP／NBT 结构识别；避免依赖预览协调器形成 `resources` 与 `schematics` 循环导入，不增加脱离领域类的模块级映射。
- `list_resources` 在原有元数据解析或哈希前执行后缀及内容校验，保证搜索、批量管理和计数都基于同一份已过滤列表；同一次扫描复用已经读取的元数据。
- `install_resources` 在提交复制任务前校验整批来源；混合选择中只要含不支持的类型或无效内容，就明确报错并列出允许格式或结构错误，不静默跳过，也不先复制其中的合法文件。
- 对错误类型不创建资源副本；已存在的无关文件只从列表排除，不自动删除或移动。
- 保留原有同名冲突、临时文件原子替换、取消、图标降级、数据包所属世界及资源启停处理。

### 4.2 文件选择器与前端 API

- 为资源文件选择请求增加受限的资源类型字段，由后端根据类型选择过滤器，不接收任意扩展名白名单。
- 更新 `FileSelectionRequest`、前端 IPC 类型及 `instanceWorkspaceApi.chooseResourceFiles`；资源页选择文件时传入当前类型。
- 光影和数据包选择器仅提供 ZIP；投影提供三种已确认后缀；资源包仅提供 ZIP 文件选择。
- 拖入与直接调用沿用同一个后端安装校验，展示已有错误消息通道。
- 通用文件选择和整合包、插件、崩溃日志的既有选择器用途不受影响；缺少资源类型的旧调用如何兼容在实现时按现有调用点与测试确认，不能回退成光影等页面的混合后缀。

### 4.3 存档导入

- 实例存档页的“导入”使用现有组件库下拉选项，提供“ZIP 文件”和“存档文件夹”。保留工具栏位置及主按钮样式。
- ZIP 入口打开仅接受 ZIP 的文件选择器；文件夹入口调用原生目录选择器；取消任一选择均不调用导入。
- 本地导入后端接受目录或 `.zip` 文件，并继续执行现有真实世界内容校验；拒绝其他后缀文件。
- 文件名后缀限制放在本地导入入口，在线下载共用解压助手仍按照归档内容处理。
- ZIP 不是已运行世界目录，导入后仍显示实际世界目录；本次不增加 ZIP 直接运行或 ZIP 列表条目，也不改动下载存档页。
- 保留世界校验失败、压缩包包含多个世界、重名、取消和解压失败的既有反馈及清理行为。
