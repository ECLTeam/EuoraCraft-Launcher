## 3. 方案取舍与用户交互

用户已从 A「仅补可选下载」和 B「完善安装向导」中选择 B。B 增加后端准备阶段，才能在安装前展示真实文件列表，并在确认时复用同一份计划。

### 3.1 选择与解析

1. 本地按钮与拖放进入同一个向导；在线资源详情预填来源、项目、版本和标题。
2. 选择文件后点击「解析整合包」，在线入口点击「读取安装信息」。保持目录和实例名可编辑。
3. 在线 Modrinth / CurseForge 需要先下载整合包压缩包，才可读取清单。这一步可能已包含包内 overrides 内容，但不下载清单引用的模组文件，也不安装基础版本。提示「先读取整合包，再选择安装内容」。FTB 读取版本清单。
4. 解析中展示局部进度，允许取消；失败展示明确原因和「重新解析」。目录与实例名保留。

### 3.2 预览与可选文件

- 摘要展示包名、格式、来源、Minecraft 与加载器版本、必需和可选文件数，以及包声明的简介；没有的信息直接省略，不用实例名推测版本。
- 文件按必需、可选、客户端不适用分组；默认展示可选组，必需和不适用组可以展开查看。
- 可选文件默认全部勾选，提供搜索、全选和全不选；可选组不按文件扩展名限制为模组。必需文件不能取消，不适用文件不能选中。
- 文件行至少显示文件名或相对路径、已知大小和选择状态；长文本提供完整内容查看。没有大小的文件标为未知，绝不按 0 字节计算。
- 下载摘要随选择更新，区分「已知文件大小小计」和未知大小文件数；不将其标成完整安装空间或总网络流量，基础游戏、加载器、压缩包和解压空间另有开销。
- 没有可选文件时跳过选择页；全部清单文件均不适用时明确说明，保留基础版本与包内覆盖文件的安装确认。
- 警告显示简短摘要和详情入口；可能导致安装不完整的已知格式限制在确认区可见。不向用户声称超出当前解析器能力的支持。

### 3.3 确认、后台执行与结果

- 确认区显示目标目录、实例名、版本与加载器，以及选中/跳过数量。检测目标已存在时禁止覆盖，提示修改实例名。
- 确认后提交一次后台安装；界面禁用重复提交，后端也锁定准备记录及目标实例。提交回执只表示任务已创建。
- 向导可收起，安装在切页或关闭向导后继续；仍由既有任务面板展示进度和取消状态，不因关闭界面取消安装。
- 任务面板为整合包安装提供「查看结果」，打开专用结果视图，显示完成/失败/实际取消、安装文件数、用户取消选择数、客户端不适用数和警告。正常完成后提供查看实例入口。
- 保持界面打开时展示同一份结果；事件先于命令回执、关闭后重开等情况只对应一个任务。不在后台强制弹窗夺取焦点。
- 解析失败可原地重试。安装失败或取消后保留当前向导输入和选择，提供重新准备并确认的入口；重新解析后的选择按新计划初始化，明确提示重新检查，不自动重复安装。

## 4. 后端模型与准备资源

### 4.1 职责与文件划分

- `modpack.py` 保留格式解析、基础版本保障、文件下载校验和实例创建。把当前「读包后立即安装」拆成准备计划与执行计划。
- 新增 `ECL/services/game/modpack_preparation.py`，由 `ModpackPreparationService` 维护本次进程的准备记录、临时文件、状态与释放；当前调用方仅为 `ModpackCoordinator` 和 `_GameState` 生命周期。该服务用于两个 IPC 阶段间持有同一份解析结果，不作为通用缓存或插件资源框架。
- `_GameState` 创建服务并在应用关闭时释放，公开接口采用明确模型，不把内部裸 JSON 或临时路径交给前端。
- 准备过程中的网络和解压在既有 `OperationManager` 工作线程内执行；IPC 不直接执行阻塞工作。

### 4.2 类型与文件身份

使用不可变 dataclass 或 Pydantic 模型表达 `PreparedModpackFile`、`ModpackPreview`、`PreparedModpack` 和 `ModpackInstallResult`。输入 JSON 在解析边界完成类型、枚举、哈希、大小和路径校验。

- 每个清单条目在一次准备记录内获得固定 `fileId`；同一条目重复渲染时 ID 不变，重新准备后为新的计划。ID 不由数组下标、CF 的临时 `mods/` 路径或前端随机数产生。
- 后端为内部条目生成随机标识并保存 ID 到条目的对应关系；前端只提交这些 ID，不能提供下载地址、解压目录或替换清单。
- 展示模型包含 `requirement`（required / optional / unsupported）、显示名称、已知相对路径、大小及来源；不暴露下载签名 URL、凭据和临时目录。
- Modrinth 沿用客户端环境标记，CurseForge 沿用 required 字段。MCBBS 的可选语义在实施时用真实格式样本核对，不能仅凭当前 force 字段映射宣布支持；无可靠可选声明的格式只提供预览和确认。
- 文件名和大小需要远端查询时复用已有文件详情接口。查询失败保留原因并阻止使用不完整的预览安装，不静默丢失必需项；未勾选项不产生内容下载。
- 固定相对目标路径冲突的清单在准备阶段报错，不用路径去重擅自合并不同条目。准备阶段取得 CF 等来源的真实文件名后，保存规范化目标路径；overrides 与清单条目指向同一文件时在预览中说明覆盖关系。安装时将被排除及客户端不适用条目的目标路径同步用于过滤覆盖文件，避免文件从另一来源重新进入实例。

### 4.3 生命周期、过期与并发

1. 准备服务创建私有临时根目录；本地包先复制为私有快照再解压，在线包仅下载一次。安装复用保存的计划和解压内容，不重新读取原始本地文件或获取另一个在线版本。
2. 状态为 preparing → ready → installing → consumed；失败、取消、释放和过期进入对应终态。记录操作 ID，状态变更由同一锁保护。
3. 预备记录最多保留 4 份；ready 状态无访问 30 分钟过期。超过数量明确提示关闭旧预览或重试，不淘汰正在使用的记录。安装期间不执行过期清理。
4. 由服务拥有一个到期清理定时器；在新建、查询、释放时也检查到期，关闭时停止定时器。只处理自身当前进程创建的临时目录，不扫描用户历史目录。
5. 关闭、切换来源或再次解析时显式释放旧记录。准备中释放会先请求取消，实际 worker 结束后再删除资源；延迟到达的准备回执也必须释放，不留下孤立记录。
6. 安装开始后准备资源归安装操作持有，释放界面预览不能删除执行中的资源。安装结束或失败后释放归属，再清理临时文件。
7. 关机先停止接收准备请求并请求取消，等待正在使用临时目录的 worker 完成安全清理后再删除目录；不能把发出取消等同于已经停止。
8. 临时清理失败记录脱敏日志和可查询的清理状态，保留本进程内有上限的重试；不因此谎报安装失败或启动无界后台重试。硬退出可能留下操作系统临时文件，本次不实现跨进程恢复或历史文件清扫。

- 前端排除列表必须经过后端逐项校验：只接受该记录中的 optional 文件 ID；未知、重复、必需或不适用 ID 均明确拒绝，不悄悄忽略。
- 安装时再次检查记录 ready、目标目录合法且不存在，原子占用记录及目标实例，两个窗口/两个准备记录提交同一目标最多成功一次。失败提交释放本次占用，不删除他人的目录。
- 安装原子提交接入 `OperationContext.finalize`；按 `canCancel` 和实际终态显示取消。基础版本安装可能保留可复用的共享文件，取消说明不承诺整次操作完全没有磁盘副作用。
- 在线压缩包获取接入有取消支持的共享下载路径，取消检查覆盖包下载、解压阶段边界、元信息解析、基础安装、文件下载和复制；不能沿用不可感知取消的独立包下载等待。
- 保留现有操作种类 `instance_import` / `modpack_online_install`，由后端根据准备来源选择；新增 `modpack_prepare` 用于准备进度。任务面板可显示准备进度，但准备任务不触发实例列表刷新。
- 删除 `game_instance_import`、`game_modpack_online_install` 及旧请求模型，不保留转发入口。同步更新 registry、中文日志声明、API 公开接口列表、前端命令/请求/响应类型、showcase transport、runtime 命令映射、store、测试和现行接口文档。历史方案文档可保留当时记录。
- 当前检索到的运行消费方为前端 import store 和 runtime，另有后端测试与 showcase；实施时再次检索插件、脚本和独立 API 文档，发现实际外部使用者时先报告范围，不偷偷增加旧契约适配。
- 增加明确错误码，例如 `PACK_PREPARATION_EXPIRED`、`PACK_PREPARATION_NOT_READY`、`PACK_PREPARATION_IN_USE`、`PACK_FILE_SELECTION_INVALID`、`PACK_TARGET_BUSY`、`PACK_PREPARATION_LIMIT_REACHED`；保留已有格式、网络、校验和目标已存在领域错误。

## 6. 安装执行与结果模型

1. 校验并占用准备记录及目标，将排除集合转换为确定的安装文件清单。
2. 先去除用户取消的 optional 项及 unsupported 项，再保障基础版本、解析最终下载元信息、下载与校验。必需项失败不能转为成功。
3. 复用 staging 和安全路径处理；复制覆盖文件时按第 4.2 节的规范化路径过滤排除项及不适用项。文件选择范围是清单中明确标记的可选条目，不提供任意包内文件删除；无法确定目标路径的条目必须在准备时明确失败，不能用模糊名称匹配覆盖文件。
4. 原子写入实例描述并落位；终态提交与取消使用统一任务机制，失败只清理本次 staging。
5. 返回结构化结果：versionId、format、downloadedFiles、excludedOptionalFiles、unsupportedFiles、overridesFiles、baseVersion 和 warnings。旧 skippedFiles 的生产方与实际消费方同步替换，不增加双字段兼容。
6. 结果警告优先使用稳定 code 与参数，前端六语言翻译；外部包简介、文件名和外部原始错误保留原文。不能直接将原始清单字典或含隐私路径的异常作为可展示警告。
7. 日志遵循 IpcLogPolicy，记录中文阶段、耗时和白名单数量；不记录完整输入、源路径、完整清单、签名下载地址和凭据。

## 7. 前端改动位置与交互约束

- `modpackImportStore.ts`：状态扩为选择、解析中、解析失败、预览、提交中、跟踪安装、结果；准备状态、任务状态各有唯一维护者，最终任务状态来自 applicationOperationStore。
- 使用请求 generation 或既有 `useRequestScope` 隔离来源切换与重试；迟到响应不能覆盖新输入、打开旧向导或污染新选项。只修改目录/实例名不重下包，修改来源/项目版本才使准备记录失效。
- `ModpackImportModal.vue`：保留公共 Modal，增加步骤、预览、可选文件列表、确认区和结果入口；复杂内容拆为有实际展示职责的局部组件，不建立通用向导框架。
- 可选列表使用后端 fileId 作为 key；单一主滚动区，底部操作可达，大包列表可按已有性能方案虚拟滚动。搜索只改变可见项，不丢失隐藏项的勾选状态。
- `applicationOperationStore.ts`、`useAppRuntime.ts`：接入新命令，继续按 operationId 合并回执和事件；先到终态不能被迟到 pending 覆盖。任务面板仅为整合包操作增加结果入口，不改其他任务结果语义。
- 新增带运行时校验的整合包 API/结果模型，避免通过 `as` 断言把 operation.result 直接当成结果对象。
- `TaskQueuePanel.vue` 及必要的结果组件：支持键盘打开结果、焦点返回和独立结果查询失败重试，任务查询失败不伪装为安装失败。
- 六语言同步按钮、状态、错误、计数插值和可访问名称。沿用主题变量、公共 UiLoading 和 Naive UI，不叠加整页加载遮罩。
- Esc/关闭：准备时退出并释放；安装提交请求未返回时阻止重复关闭/提交导致操作归属丢失；已确认提交后可收起，关闭不取消安装。
