# 资源搜索十页翻页与来源切换修复

## 已确认方案

用户于 2026-10-24 选择方案 A：全部来源及单一来源均显示前／后十页按钮；聚合搜索按顺序读取中间页，单次最多前进十页；切换来源后自动重新查询第一页。

## 问题与改动位置

- `frontend/src/components/mods/OnlineModSearch.vue` 原先仅在单一来源下显示十页按钮；筛选变化时清空列表，但只有已有结果且关键字非空时才重新查询。
- 仅调整该组件的按钮显示、分页边界、聚合取页过程和筛选状态失效处理。复用既有 `SearchPageCache` 与 IPC，不修改后端或缓存模型的公开接口。
- 前十页不足时回到第一页；单一来源后十页超出总页数时停在末页。
- 聚合前进逐页读取并复用已缓存页面；提前到末页、结果截断或后端未推进页码时停止，不虚构总页数。保留既有后续五页预加载规则。
- 连续取页期间保持原页，整个操作完成后才提交新结果；中途失败保留原页并允许重试。操作中禁用分页，来源变化或组件卸载后停止后续派发，旧响应不得覆盖当前来源。
- 切换来源清空旧会话、分页摘要、来源错误及旧结果，并在页面就绪后重新查询第一页；空关键字、原先无结果的情况也必须查询。

## 实施步骤与验证范围

1. 先增加缺陷回归，确认旧实现下按钮缺失和空关键字来源切换用例失败。
2. 修改组件内部流程，覆盖顺序翻页、末页边界、失败重试及切换来源时的旧请求失效。
3. 执行改动文件的 Prettier、ESLint 和相关 Vitest；通过 `pnpm build` 完成类型检查和构建。
4. 使用生产组件和有顺序限制的演示响应进行真实浏览器验收，覆盖全部来源 1→11→1、单一来源 1→11→末页，以及来源切换回到第一页。
5. 检查六语言、Classic / Folia、亮暗主题和默认、最小及放大视口；在 Windows 启动器中检查受影响流程。
6. 提交前端、本实施记录及主仓库指针，集成本地 main，保留原有无关修改，不推送远端。
