# 配置仅在值变化时保存与重复刷新合并方案

日期：2026-11-02。状态：用户已选择方案 1，本文等待实施确认；尚未实施功能修改。

关联问题：[未修改配置仍请求保存 #104](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/104)、[插件列表重复查询 #105](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/105)。

## 1. 目标与验收标准

采用用户选定的“统一保存入口判断变化”方案。用户继续使用现有自动保存交互，无需增加手动保存按钮。

1. 只聚焦、失焦、重复选择当前值或改动后恢复原值，不发送配置保存请求。
2. 真实修改正常保存；相同目标、相同待保存内容的重复触发不重复提交。
3. 保存期间继续修改，最终以最后一次实际修改为准；失败保留待保存内容并允许重试。
4. 配置事件和保存响应不会覆盖尚未提交的编辑，也不会触发保存循环。
5. 插件授权并启用等操作结束后合并列表刷新；仍需补读时保证读取最终状态。
6. 验收通过实际 IPC 调用次数和持久化结果确认，不以隐藏日志作为修复。

## 3. 保存状态与比较规则

### 3.1 状态归属

- 复用 `configQueries.ts` 的已校验查询快照、配置事件和写入响应，作为全局配置已确认状态的唯一来源。
- 表单编辑值、提交时冻结的内容和后端已确认值必须分开；快照独立复制，不能与 Vue 可变对象共用引用。
- 优先将游戏设置的编辑状态放回页面草稿，通过所属 store 的 patch 提交，避免修改查询快照或已确认状态。
- 读入、有效配置事件和成功写入响应更新已确认快照；失败、排队和本地预览不提前更新已确认值。
- 默认值使用已有领域定义。缺省字段与已有界面默认值的比较保持一致，避免仅打开页面就补写整组默认值。
- 命令行、环境变量覆盖仍按当前后端有效配置契约处理，不把显示覆盖值作为其他字段编辑时需要整体写回的内容。

### 3.2 统一变更判断

- 全局配置沿用现有分区串行队列，在真正执行前将提交内容与最新已确认状态比较。
- 比较使用明确类型的纯函数；对象按键和值比较，不依赖对象键插入顺序，数组保留顺序语义。
- 遵守实际 JSON 传输规则处理可选字段，不随意将 `null`、缺失字段、空字符串或不同数组顺序视为相同。
- 局部 patch 只判断其涉及字段；嵌套主题、背景和下载映射按既有合并规则处理，保留不相关字段。
- 没有可信快照或快照已失效时，复用领域读取获取当前状态；不凭默认值跳过保存，也不每次保存前固定新增一次后台读取。
- 同一目标的重复待提交内容复用已有请求结果；保留不同内容的顺序，例如 A → B → A 不能直接删掉最后一次 A。
- 请求成功后以后端确认值更新快照；失败保留旧确认值，后续提交相同失败内容仍须允许执行。
- 仅保存被跳过时，不产生“已保存”反馈、失效通知和额外读取；“显示调试窗口”等复合操作仍执行其本来需要的界面动作。

## 5. 插件列表刷新规则

1. 现有插件 store 统一持有刷新需求、活动读取和本地操作状态，不为每个调用方建立独立刷新器。
2. 授权并启用的连续流程中，合并本地操作、弹窗完成和状态事件的刷新需求；本地流程完成后读取最终列表，取消已被该次读取覆盖的计时器。
3. 并发读取相同状态时共享请求；读取期间确有新变化，只要求一次取得最终状态的补读，不按每条事件分别排队。
4. 外部插件变化、操作失败和用户显式重试继续可见；避免为了减少次数而长期保留过时列表。
5. 页面退出释放订阅与计时器，迟到读取不能复活已释放状态；通过状态版本保护避免遗漏新变化。
6. 对一个已稳定完成的本地操作，自动列表刷新目标为一次；操作返回后仍有真实后续变化时允许必要补读，并在测试中区分两者。

## 7. 测试与真实验收

### 7.1 回归场景

| 场景                                   | 必须验证的行为                                                       |
| -------------------------------------- | -------------------------------------------------------------------- |
| 未编辑的输入框连续聚焦、失焦           | 配置保存 IPC 为 0。                                                  |
| 同值选择、等价对象键顺序、恢复原值     | 无多余保存，数组内容变化仍可识别。                                   |
| 游戏输入框修改一个值后失焦             | 保存一次，重新读取保留结果，其他字段不变。                           |
| 滑块、颜色和背景选项连续修改           | 保留实时预览，防抖结束保存最终值；离开页面不丢已确认需要提交的修改。 |
| 保存中重复提交相同内容                 | 共享请求，不重复保存或显示成功提示。                                 |
| 保存中继续修改，含 A → B → A           | 最终状态正确，不被旧请求或配置事件覆盖。                             |
| 后端规范化返回、读取与写入交错         | 已确认状态来自新响应，旧读取不能覆盖。                               |
| 保存失败后重试相同值                   | 允许重试；失败不更新确认快照，不误报已保存。                         |
| 外部配置事件与本地未提交编辑并存       | 同步已确认状态，保留未提交编辑，无保存循环。                         |
| 嵌套背景、调试偏好、下载目录、联机节点 | 每类入口验证无变化 0 写入、真实变化保存且保留不相关字段。            |
| 实例或插件切换、插件内容或 schema 变化 | 状态按目标隔离，旧缓存不能跨目标抑制写入，版本冲突仍显示。           |
| 插件审阅并启用、启停、重载             | 稳定操作后的重复列表刷新合并；后续真实变更仍能补读。                 |
| 页面关闭、重复打开、保存失败再重试     | 资源释放，无重复订阅，待保存内容按领域会话约定保留。                 |
