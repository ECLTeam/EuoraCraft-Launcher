# 背景图片旧路径与未启用分支读取修复方案

- 日期：2026-11-07
- 状态：用户已选择 B，已实施、验收并完成本地交付。
- 基线：主仓库 `901cbc0`，前端 `6525432`；保留当前其他未提交改动。
- 问题：[视频背景初始化仍读取未启用图片并提示文件不存在](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/130)。

## 1. 已确认事实

1. 用户反馈的文件仍存在。已定位到图片收藏目录，Pillow 能打开，格式为 PNG，尺寸 5120×3840，大小约 17.6 MiB。
2. 当前数据目录的 `setting.json` 中，`ui.background.image.path` 保存的是另一条已失效的目录路径；日志在 2026-11-07 16:03:28 按该旧路径读取并返回 `FILE_NOT_FOUND`。
3. 配置的 `background.media_type` 是 `video`。外层另有 `type: default`，但当前实现会优先读取嵌套的图片配置；不能仅凭外层旧字段判断当前实际显示的是默认背景。
4. `frontend/src/composables/useTheme.ts` 的 `initTheme()` 先按图片设置读取单图或扫描目录，之后才判断媒体类型、调用 `activateVideoBackground()`。未启用图片的失效路径会产生报错，并能中断后续初始化。
5. `ECL/api/files.py::image_read_file` 按收到的路径检查文件；这次传入的旧路径确实不存在，没有证据表明后端把现存文件误判为不存在。

旧路径与实际路径的具体值仅用于本机修复与用户确认；公开 Issue 不附带用户目录、完整配置或个人文件内容。不扫描磁盘猜测并自动改写其他路径。

## 2. 方案比较

| 方案 | 改动 | 收益 | 限制 |
| --- | --- | --- | --- |
| A：仅重选图片 | 通过现有背景设置重新关联已确认的原图，保持当前媒体选择 | 直接修正本机旧路径，改动小 | 启用视频时仍会无意义地读取约 17.6 MiB 的未启用图片；以后旧图片移动仍会复发 |
| B：修正路径并按当前分支加载（推荐） | 修正这一个已确认的旧路径；初始化只加载当前媒体分支，保留另一分支的设置以供切换 | 解决本次路径不一致和重复误提示的原因，避免未启用图片阻断视频 | 涉及共享主题初始化，需要前端全量检查与真实界面验收 |

不移动原图、不自动寻找同名文件、不删除历史背景设置，也不通过吞掉所有图片错误来让提示消失。当前启用图片确实缺失时仍应显示明确失败。

## 3. 推荐方案 B 的具体行为

- 保留单图路径、文件夹路径、轮播模式、间隔与视频设置；保存的配置结构不变。
- 初始化视频背景时仅加载视频及其适用封面，不读取、解码或扫描图片分支。
- 初始化图片背景时按现有默认、单图、轮播或随机模式加载需要的图片，不请求视频流。
- 切换回图片分支时，才加载其已保存的单图或轮播目录；避免为懒加载清空已有设置或误把单图路径当目录。
- 当前分支加载失败时保留保存的配置，允许用户重选或重试；未启用分支的失败不阻断当前分支。
- 本机路径修正只更新已确认的图片位置，不更改媒体选择、视频路径、外观设置或其他配置。应用正在运行时优先通过现有设置入口同步内存与磁盘；不能安全同步时不直接覆盖活跃配置。
