# 实例快捷方式图标等比例放大实施方案

状态：用户已确认开始实施；修复、自动检查与 Windows 实际快捷方式验收已完成。

## 目标与验收标准

让新创建的 Windows 实例快捷方式图标具有正常的视觉大小。将原始图像等比例适配到 256×256 画布，小图放大、大图缩小，保留原始透明边缘与宽高比例。

1. 草方块、箱子、命令方块及主要加载器的 64×64 图标，生成后最长边达到 256 像素，不再以原始 64×64 尺寸居中摆放。
2. 自定义小图标也能放大；非正方形图标等比例居中，原图已有透明留白保留。
3. ICO 包含 16、24、32、48、64、96、128、256 像素的方形图层，在不同桌面显示尺寸下具有正常占比。
4. 新创建的快捷方式引用新生成规则下的缓存；同一来源图像可稳定复用新缓存。
5. 已有快捷方式继续引用原图标文件。用户重新创建快捷方式后使用放大的图标；现有文件冲突处理保持原样。
6. Windows 实际创建的 .lnk 的图标路径有效，启动目标、参数和工作目录与现有规则一致。

## 当前实现与已确认原因

- 前端调用 `game_instance_shortcut_create`；`ECL/api/workspace.py` 解析实例有效图标，再委托 `InstanceShortcutService.create` 生成图标和 .lnk。
- `ECL/utils/instance_shortcuts.py` 的 `_cache_icon` 使用 `converted.thumbnail((256, 256), LANCZOS)`。该方法只缩小图片，小图片保持原尺寸。
- 后续代码将图片居中放到 256×256 透明画布，导致草方块等图标实际只占约四分之一宽度。
- 已检查内置资源：草方块、箱子、命令方块、Fabric、Forge、NeoForge、OptiFine、Quilt 都是 64×64；煤、铁、石英是 300×300。后者原本已缩小至 256×256，因此问题在不同图标之间表现不一致。
- 现有 ICO 只包含 16、32、48、256 四种尺寸。
- 缓存文件名仅由原始图片内容的 SHA-256 决定，缓存命中后直接返回。因此仅修改缩放代码会继续复用旧的小图标。
- 现有测试只检查 ICO 文件格式和外部尺寸，没有检查实际图案占比。

## 选定实现

### 1. 按完整原图等比例适配画布

在 `_cache_icon` 中，将只缩小的 thumbnail 改为支持放大和缩小的等比例适配，例如 `ImageOps.contain`，目标为 256×256。

- 以整张原图的宽高计算比例，不裁剪透明边缘，不改变源文件。
- 使用现有的 LANCZOS 重采样，居中合成到透明 RGBA 画布。
- 正方形原图适配为 256×256；长方形原图最长边为 256，另一边按比例缩放。
- 保留现有输入字节数、像素总量上限与原子写入流程。

### 2. 提供完整的 ICO 尺寸

将 ICO 输出尺寸调整为 `(16, 24, 32, 48, 64, 96, 128, 256)` 对应的方形图层。画布尺寸、ICO 尺寸集合与缓存版本放在 `InstanceShortcutService` 的有类型类属性中，遵循主仓库 snake_case 常量规范。

### 3. 新规则使用新缓存目录

新生成的 ICO 使用 `shortcut-icons/v2/<原始图片 SHA-256>.ico`，同一图片重复创建时复用同一路径。

- 新生成规则不会命中原来的 `shortcut-icons/<SHA-256>.ico`。
- 旧图标文件保留，已有 .lnk 的引用仍有效。
- 本次只为新创建的快捷方式使用新版图标；已有快捷方式通过用户重新创建获得新版图标。
- 沿用现有 .lnk 同名冲突提示，批量迁移旧快捷方式不在本方案范围内。

## 影响与注意事项

- 修复的是每个图标文件中图案的占比，Windows 桌面的全局图标大小继续由系统设置决定。
- 小图片放大不会增加原图细节；采用现有重采样方式，首先纠正尺寸与留白比例。
- 有意留出大量透明空间的自定义图标仍会保留该设计，裁去留白需另选方案 2。
- 新 ICO 增加少量缓存体积；旧缓存保留以支持现有快捷方式。
- 旧快捷方式需要重新创建才能引用新版图标。新路径也降低了 Windows 继续读取旧图标缓存的可能性；验收需核对实际 Shell 显示结果。

## 实施结果（2026-10-10）

- 使用 `ImageOps.contain` 将完整原图等比例适配至 256×256，保留透明边缘和 LANCZOS 重采样；ICO 输出包含全部 8 个目标尺寸。
- 新图标写入 `shortcut-icons/v2`，同一图片稳定复用新版缓存，原缓存文件保留。
- 增加小图放大、大图缩小、非正方形居中、透明留白、真实内置资源、多图层和缓存隔离回归。新增用例在原实现上有 9 项失败，修复后全部通过。
- 扩展现有 Windows COM 测试，核对 .lnk 的 IconLocation、TargetPath、Arguments 和 WorkingDirectory，确认新图标路径与原启动规则一致。
