# 默认加载器最新版解析方案

状态：已选择 A，待确认实施。日期：2026-10-25。关联：[Issue #61](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/61)。

## 目标

安装弹窗选择“默认安装最新版本”时，由后端确定当前 Minecraft 版本对应的最新加载器版本。统一覆盖 Fabric、Forge、NeoForge、Quilt；用户手选的具体版本保持不变。

缺省、None、空字符串及纯空白表示自动选择；其他类型的非法输入明确拒绝，不当成默认值。沿用现有请求字段，不新增“latest”字符串或额外开关。

## 当前原因

前端默认项提交空字符串，API 将它映射为对应加载器的版本字段。`install_version` 仅允许 Fabric 省略版本，其他三种在创建安装任务前抛出 `LOADER_VERSION_REQUIRED`。

## 改动点与实施顺序

1. 修改 `ECL/services/game/install.py`：受理请求时统一将未指定版本保留为 None，不在 IPC 路径查询网络。具体版本继续按现有逻辑传递。
2. 在 `InstallCoordinator` 内增加私有版本解析方法，由已有工作线程中的 `install_blocking` 调用。该入口也供整合包基础安装复用，避免只修复弹窗入口。使用现有 `loader_versions` 查询当前游戏版本的候选列表，沿用下载源、超时与重试机制，不新增服务层或兼容层。
3. 最新版按版本号比较，不依赖不同来源的返回顺序。复用已依赖的 `packaging.version.Version`，保留选中的原始版本号供 Core 使用；不增加“只选稳定版”的过滤。空列表、查询失败、无法比较的版本数据分别明确失败，不猜测或伪报成功。
4. 在查询前后检查取消信号；取消后不得继续生成清单或下载。解析完成后向现有 Core 构建接口传入具体版本，Fabric 也由同一后端入口确定默认版本。
5. 保持用户选择的实例名称、安装目录、Java 选择及 Fabric API 处理不变。实际加载器版本由既有 Core 流程写入实例元数据；更新参数说明和必要的操作日志。

本次以主仓库后端为主，不修改 Core 子模块，不靠前端预选第一项规避后端问题。若验收发现现有错误展示需要调整，仅补齐直接相关的提示与六语言文案。

## 测试与验收

- 新增修复前失败的回归：四种加载器默认版本、手选版本不被替换、数值排序（如 `47.4.10` 高于 `47.4.9`）、不同来源及乱序列表。
- 覆盖空列表、无效版本数据、网络失败、查询期间取消、非字符串输入；校验失败时不生成实例版本文件或下载清单。
- 覆盖 API 字段映射、安装任务和整合包调用 `install_blocking` 的集成路径，并覆盖 Windows/POSIX 适用分支；不重跑无关的应用界面巡检。
- 涉及安装和文件写入，按项目规范执行后端全量 Ruff、格式与 pytest 检查，并执行修改文件的定向检查。Core 不变，补充实际消费方集成测试。
- 实际启动启动器，在独立验收目录中使用 Forge 的默认最新版完成一次安装，核对所选版本与实例元数据；检查 NeoForge、Quilt 默认项及 Fabric、手选版本的提交行为。区分实际下载验收与受控回归，不把两者混称为已通过。
