# LittleSkin 双 OAuth 登录实施方案

日期：2026-11-03。

状态：用户已确认恢复两种登录方式，按方案 A 由启动器直接完成设备代码流与授权代码流；本文待审阅，尚未获准实施功能。

## 1. 已确认需求与本方案的界面假设

- 为当前启动器添加 LittleSkin OAuth 设备代码流和 OAuth 授权代码流，面向简体中文用户。
- 两种流程都直接请求 LittleSkin，不增加自建授权服务器。
- 应用 ID、客户端密钥沿用现有 Microsoft `client_id` 的环境变量、根目录 `.env`、构建注入方式；普通用户无需自行创建 OAuth 应用或输入应用密钥。
- 用户已确认授权代码流默认回调为 `http://127.0.0.1:34127/oauth/littleskin/callback`，允许通过配置自定义本机回调地址。
- 用户尚未单独回答入口的语言范围问题。本文暂定仅 `zh-CN` 显示新增 LittleSkin 登录入口，作为本次文档审阅项；界面文案仍同步六语言。已添加账户的展示、刷新和游戏启动不随界面语言失效。
- 方案 A 会将授权代码流所需的 `client_secret` 提供给桌面程序，发行包内的密钥可以被提取。GitHub Secrets 只保护构建前的存储，不使发行包内的密钥保密；不把混淆或编译描述为安全存储。

## 3. 应用配置与上线前提

| 配置 | 用途 | 可用性要求 |
| --- | --- | --- |
| `LITTLESKIN_CLIENT_ID` | 两种流程使用的 LittleSkin 应用 ID | 两种流程均需要 |
| `LITTLESKIN_CLIENT_SECRET` | 授权代码兑换和授权代码流刷新 | 仅授权代码流需要 |
| `LITTLESKIN_REDIRECT_URI` | 授权代码流的已注册本机回调地址 | 可选覆盖；未配置时使用已确认的默认地址 |

读取优先级为非空进程环境变量、非空 `.env`、非空构建注入值；回调地址在上述来源均未配置时使用已确认的默认值。新增配置只使用上述正式名称，不新增无实际使用者的别名。应用 ID 和密钥的示例及源码默认值为空或占位值，回调示例使用默认地址，不读取或输出开发者真实 `.env` 内容。

在 `BuildEnvironment` 添加对应类属性，通过 GitHub Secrets 和构建环境提供配置，注入使用安全的字符串序列化，避免引号、反斜杠或换行破坏 Python 源码。普通用户界面只接收各流程是否可用和缺少哪项配置，不接收密钥本身。

回调默认采用 `http://127.0.0.1:34127/oauth/littleskin/callback`，在 `.env.example` 与接入指南中提供示例；允许通过 `LITTLESKIN_REDIRECT_URI` 自定义本机回调地址，包括端口和路径。监听器绑定和请求校验均以最终生效的配置为准，不写死默认端口或路径；地址必须与 LittleSkin 应用中实际登记的 URL 完全一致。仅接受明确的 IPv4 回环地址、端口和有效路径，不接受任意远程 URL、通配绑定、含凭据、查询参数或片段的 URL。配置的端口被占用时明确失败，不静默换端口导致回调不匹配。

应用维护者需在 LittleSkin 创建应用、登记回调、申请设备代码流和 Yggdrasil 权限白名单。设备代码流要求登记的官方回调地址与本机授权代码回调分别登记；同一应用能否按此配置启用两种流程，以服务端实际审核和联调为准，不把文档推断当作已通过。

初次白名单通常为仅创建者可授权的测试模式；开发验收完成后仍需维护者申请解除测试模式。本次不自动发送邮件、操作账户后台、推送或发布。

## 4. 两种授权流程

### 4.1 共用范围与角色选择

两种流程统一在启动器内选角色，申请 `Yggdrasil.PlayerProfiles.Read` 和 `Yggdrasil.MinecraftToken.Create`；设备代码流另申请 `offline_access` 以取得刷新令牌。不申请与角色读取互斥的 `Yggdrasil.PlayerProfiles.Select`，不引入仅为解析 ID Token 而增加的 JWT 依赖。其他权限仅在官方接口明确要求且有当前调用方时申请。

OAuth 令牌始终视为不透明字符串。取得访问令牌后读取角色列表；零角色提供前往 LittleSkin 创建角色的入口，一角色直接使用，多角色显示选择步骤。提交前在后端核对角色确属本次授权结果，拒绝前端传入的任意 UUID。

使用选定角色 UUID 请求 Minecraft 令牌，校验返回的令牌字段和角色归属后保存账户。使用服务端返回的 `clientToken`，不自行指定或从 OAuth 令牌推导。

### 4.2 设备代码流

1. 后端向 `https://open.littleskin.cn/oauth/device_code` 请求设备代码对，校验字段类型、非空值、有效期和轮询间隔。
2. 界面展示用户授权码，允许复制和打开官方授权页面；设备代码只保留在后端本次会话中。
3. 后端遵守服务端 `interval` 和整体过期时间向 `https://open.littleskin.cn/oauth/token` 轮询。`authorization_pending` 继续等待，`slow_down` 按协议降低频率；拒绝、过期及其他不可恢复错误结束会话。
4. 授权成功后进入共用角色选择和 Minecraft 令牌兑换流程。设备代码流的请求和刷新均不发送 `client_secret`。

### 4.3 授权代码流

1. 校验配置并成功绑定本机回调后，再生成一次性随机 `state` 并打开 `https://littleskin.cn/oauth/authorize`，请求参数使用标准 URL 编码。
2. 监听器仅在本次登录期间存在，校验 HTTP 方法、Host、路径、参数数量与长度、`state` 和会话有效期；错误请求不消费合法会话。授权响应只允许一次性消费，防止重放和跨会话覆盖。
3. 用授权代码、应用 ID、客户端密钥和同一回调地址向 `https://littleskin.cn/oauth/token` 兑换令牌。授权代码、密钥和令牌不经前端 IPC 传递。
4. 回调页只显示最小的完成或失败提示，不展示授权参数；不记录回调完整 URL，响应设置禁止缓存并限制外部资源。
5. 成功、拒绝、超时、取消及应用退出均关闭监听器并清理会话。超时暂定五分钟，网络调用另设明确超时。

官方授权代码文档未明确列出 `state` 的往返行为，本项必须用真实应用验证。若服务端不返回 `state`，不得取消校验来让流程通过；保留失败证据并修订方案。回环 HTTP 回调是否被应用管理和服务端接受同样属于联调前提。

### 4.4 网络和错误边界

- 网络请求使用所属领域 HTTP 客户端、明确超时和 `Accept: application/json`；授权站点和令牌端点固定，不跟随重定向向未知地址发送密钥或令牌。
- 校验 OAuth 错误、HTTP 状态和 API 业务错误。LittleSkin 可能用 HTTP 200 携带业务 `code: 403`，不能只判断 HTTP 成功。
- 稳定错误码区分配置缺失、应用未准入、用户拒绝、授权超时、无角色、角色失效、网络失败和保存失败；外部错误描述经过脱敏后再展示。
- 不自动从一种 OAuth 流程切换到另一种流程或密码登录；失败后由用户明确重试或选择其他方式。

## 5. 职责、IPC 与账户持久化

- 新增 `ECL/services/account/littleskin.py`，提供职责明确的 LittleSkin OAuth 客户端及有类型的请求结果；当前调用方是账户登录服务和已保存 LittleSkin 账户的凭据刷新。负责官方协议、会话回调资源和远程请求，不创建跨提供方认证框架。
- `AccountManager` 作为登录会话的权威维护者，按会话 ID 隔离两种方式，持有任务、阶段和取消状态；状态变化通过既有事件机制通知界面。取消确认后禁止旧任务继续提交账户。
- `AuthlibAccountManager` 继续作为外置账户与凭据文件的唯一维护者，新增接收已校验 LittleSkin 登录结果的公开方法，不让新模块调用其私有 `_store_response`，也不伪造密码待登录数据。
- 账户主类型保持 `authlib`。新增明确的 LittleSkin 来源标记和登录方式，用于区分刷新策略和品牌展示；不借用插件认证 `provider` 的业务语义。对应后端模型、前端快照校验和显示同步更新。
- OAuth 访问令牌、刷新令牌、到期时间、登录方式与应用 ID 保存在同一个账户私有凭据记录中，与游戏令牌一起由外置账户领域维护；账户列表和事件仅返回展示资料。应用密钥从运行配置读取，不复制到每个账户文件。
- 角色身份按认证服务和角色 UUID 判断。重复登录同一角色更新原稳定账户 ID，不新增重复项；同一 LittleSkin 账号的其他角色可以分别添加。若同角色原为密码登录，本次明确成功的 OAuth 登录可替换该角色的认证方式，不扫描或迁移其他账户。
- 先完成有效结果校验和必要文件写入，再发布内存状态、当前账户和事件；文件写入采用原子替换及必要回滚。磁盘失败不得误报账户添加成功，已有账户和其他用户数据须保留。
- 新增 `accounts_littleskin_login_config`、`accounts_start_littleskin_login`、`accounts_poll_littleskin_login`、`accounts_select_littleskin_profile`、`accounts_complete_littleskin_login`、`accounts_cancel_littleskin_login`，配套明确请求/结果模型和状态事件。请求携带所属会话 ID，旧前端不能取消或完成新会话。
- 在 `ECL/api/operation_logging.py` 的 `IpcLogPolicy` 为新增命令声明中文操作、分类和结果归属。轮询与配置查询成功保持安静；由实际执行方记录必要阶段和一次最终结果。用户取消不记为异常，不输出凭据、完整授权 URL、用户授权码和内部会话编号。

## 6. 刷新、取消与资源生命周期

- LittleSkin 账户通过原登录流程对应的端点刷新 OAuth 令牌：设备代码流使用 `open.littleskin.cn`，授权代码流使用 `littleskin.cn` 并提供当前客户端密钥。
- 游戏令牌可沿用官方支持的 Yggdrasil 验证和刷新；仅在明确的令牌失效且需要重新签发时，使用有效 OAuth 凭据兑换该角色的游戏令牌。网络失败不被视为凭据失效，也不触发无条件降级。
- 同一账户的刷新实行互斥，防止并发使用旋转前的刷新令牌。重新登录、删除账户和刷新提交之间核对凭据版本，防止旧请求复活删除的账户或覆盖新登录。
- OAuth 刷新成功后旧令牌立即失效，必须先原子保存新 OAuth 凭据，再执行后续游戏令牌兑换。后续操作失败保留已成功轮换的新凭据，不回写失效的旧值。
- 服务端令牌轮换不能由本地文件回滚。如果服务端成功而本地写入失败，保留现有文件并明确要求重试保存或重新授权，不宣称凭据仍有效；本进程内保留的新结果只用于受控恢复，不输出到日志。
- 取消需要等待实际任务结束及回调资源关闭，再确认停止。关闭弹窗、切换界面语言导致入口隐藏、离开页面或应用退出时，通过所属会话取消并解除订阅；无法立即取消的网络结果不得在会话关闭后写入账户。
- 游戏启动、账户刷新等应用级任务不因普通账户页面卸载而中断。凭据只进入受信游戏启动边界，不因来源标记扩展插件读取权限。

## 7. 前端体验与文件范围

在添加账户的单一弹窗内增加 LittleSkin 入口，进入后提供“授权码登录（推荐）”和“浏览器登录”两个选项，分别解释操作方式，避免要求用户理解协议术语。

- 设备代码流展示复制授权码、打开浏览器、有效期和等待状态；授权代码流展示正在等待浏览器、重新打开浏览器和取消操作。
- 两种方式共用角色选择及保存阶段；失败时保留可理解的原因和重试入口，完成保存后刷新账户列表并关闭添加流程。
