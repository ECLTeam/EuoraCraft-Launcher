# 插件实例只读 API 实施方案

日期：2026-10-20（Asia/Shanghai）。状态：用户已批准方案 A，实例只读能力已实施；本轮验证记录见第 9 节。

本轮接续 [Worker 管理器接入](plugin-worker-manager-integration-plan.md)，细化 [总体设计](../designs/plugin-worker-api-v2-implementation-design.md) 的 P07 第一部分。当前基线：主仓库 `459bd1f`，前端 `f4eb6fb85abee81c88db07423cfc5a27a145fb69`，Core `467b58c602e8e309d3057a63920b09c679802753`。旧阶段验收数字不作为本轮验证结果。

## 1. 目标、路线与边界

目标：示例插件只能发现并查询用户明确允许的游戏目录或实例；获得的数据不包含真实路径、账户、启动命令和裸配置。撤销、资源移除、内容变化或运行结束后，旧引用和迟到查询结果失效。业务查询不修改游戏目录、实例资料、运行统计及游戏进程。

上轮建议的 P07 实例查询路线已被用户选择。本轮内部实现比较如下，推荐方案 A，具体契约修订随本文一起审阅：

| 方案 | 做法 | 收益与代价 |
| --- | --- | --- |
| A，推荐 | 宿主资源目录、精确范围授权、每次运行引用、真正只读的实例查询 | 支持目录及单实例选择，可独立验证越权和撤销；需要补齐资源目录、无写入读取路径和权限 UI |
| B，只开放已有缓存 | 仅筛选启动器之前扫描过的数据，不主动访问实例文件 | 改动较少，但首次查询可能无数据，难以兑现刷新和单实例最新查询；不能冒充完整 `instances.scan` |
| C，先只按目录授权 | 用户批准整个目录，暂不支持单实例选择 | 实现较简单，但不能满足本轮推荐的细粒度选择；若选此方案，应明确缩小验收范围 |

方案 A 的本轮范围：资源发现、`instances.scan`、`instances.get`、严格实例 DTO、目录/实例授权界面及真实 Worker 示例。不开放实例写入、文件内容 API、游戏启动/停止、下载、账户、Java、外部兼容提供方或自定义 UI。P08 的任务归属、取消与提交阶段仍在后续单独推进。Worker 平台范围继续沿用已验收的 Windows x64，不扩大 OS 沙箱承诺。

## 2. 当前实现与具体缺口

| 位置 | 已核实情况 | 本轮处理 |
| --- | --- | --- |
| `runtime/broker.py` | 只开放自身命令、设置和事件，没有实例查询或共享资源引用 | 接入明确的只读实例服务；不转发通用 IPC |
| `grant_models.py`、`grant_store.py` | 决定中的资源必须是清单声明资源的子集；空声明不能选择本机动态资源 | 为 `instances.read` 明确引入用户选择范围，其他能力维持现行精确范围语义 |
| `PluginContentBinding` | 内容摘要包括代码、声明及锁；插件清单不可能预知宿主本机资源 ID | 不把目录列表或用户选择拼进代码摘要；选择归授权 revision/epoch 管理 |
| `services/game/scan.py` | `scan_versions()` 创建 `ecl.json`、注册目录监视，并通过 `_scan_game_path()` 初始化统计 | 新增真正只读查询路径，不在插件查询中调用这一有写入的入口 |
| `instance_profiles.py` | 现有 `enrich_version()` 合并外部提供方、处理图标并同步统计；资料没有权威递增 revision | 分出本地资料的纯读取/校验部分；不伪造 revision，不调用统计同步和外部提供方 |
| Core `Data/instance_metadata.py` | 已有组件识别和有界继承解析，但公开读取入口自行读路径 | 增加从已校验文档纯解析的公开入口，供主仓库受控读取复用；不复制一套加载器识别规则 |
| `services/game/workspace.py` | 现有 `rootKey` 是真实路径，`instanceKey` 包含路径；路径解析本身不是插件授权 | 仅在宿主内部使用既有身份；插件获得新的不透明运行引用 |
| `services/game/launch.py` | `list_instances()` 会协调已退出运行及统计 | 为只读 DTO 提供受锁保护的运行计数快照，查询不触发退出收尾或进程操作 |
| `application.py`、管理器 | 插件运行服务尚未接收 GameService 和配置资源目录 | 注入已有应用服务的窄接口；不为插件新建 GameService/ConfigStore |
| `PluginPermissionsModal.vue` | 只能允许/拒绝能力，提交原样复制已有 resource_refs | 增加宿主提供的资源候选与明确选择，不接受手填路径 |

## 3. 资源身份与授权语义

### 3.1 持久身份与运行引用分开

- 新增 `PluginResourceCatalog`，由当前应用拥有，负责已配置游戏目录和可选实例的身份、存活检查与退休。当前调用方为可信权限管理入口和只读 Broker，不创建通用服务注册框架。
- 资源候选仅来自有效配置 `game.minecraft_paths` 及这些目录的直接实例；插件不能要求宿主枚举任意目录。配置别名仅用于可信管理页展示，路径不会进入 Worker DTO。
- 宿主持久资源 ID 使用随机值，绑定规范目录、资源种类及物理目录身份；不能直接用路径哈希作为可猜测的授权凭证。目录别名指向同一实体时去重；大小写敏感目录不能机械转小写合并。
- 新建宿主自有 `plugin_resources.json` 严格记录目录身份，原子写入并使用有界文件锁；损坏保留原文件并拒绝相关共享资源 API。现有仅使用自身能力的插件不因此获得新许可，也不应被资源目录故障阻断。
- 稳定资源 ID 只用于宿主授权记录及可信管理页。Worker 的 `root_ref`、`instance_ref` 由所属运行生成，绑定安装、内容、run 和资源代次；不能跨安装、跨运行或跨类型使用。
- 资源目录映射只是身份索引，实例内容和配置仍由 GameService/ConfigStore 维护。业务查询不自动生成或重新绑定失效身份；发现和审阅时可更新宿主自己的资源目录文件。

### 3.2 范围如何授予

- 通用插件清单声明 `{"capability":"instances.read","required":true}`，不嵌入本机资源 ID。该能力不接受插件自报的 `resource_refs`。此项是对尚未开放能力的明确契约细化，不转换旧 SDK 权限。
- 可信主界面可批准“此目录的全部实例，包括以后新增的实例”，或“仅选择的这些实例”。界面明确展示两种范围；默认均不选中。选择单实例不会顺带授权兄弟实例的资料或运行状态。
- `PermissionDecision.resource_refs` 对该能力保存用户选择的持久资源 ID。GrantStore 通过宿主资源目录校验类别、来源及当前有效性；不能取消全部能力的子集检查来实现此功能。其他现行能力的声明/决定行为不变。
- `instances.read` 为必要能力时，至少一个有效选择且用户明确允许才满足启用条件；选定部分实例足以满足“读取获准实例”的能力要求，不要求批准目录中的所有实例。可选能力允许未选择或拒绝并继续运行。
- 选择范围、拒绝、期限仍通过现有 expected_revision、拒绝屏障、原子保存和 epoch 处理。更换目录选择不修改插件内容摘要，也不自动继承更新后代码的许可。
- 取消配置中的目录、物理身份变化或所选实例消失会使对应资源失效；显示“已不可用”，保留原授权记录供查看和撤销，不按同名路径自动重新授权。移除后重新添加或同路径重建须重新审阅。
- 已允许整个目录时，该目录内新增实例属于明示范围；仅选择单实例时，新实例及同名重建实例均不自动进入范围。空目录本身仍可被明确授权，扫描成功返回空列表。

### 3.3 失效与并发

配置变化由应用订阅更新资源有效性，实际查询仍验证根和实例身份。目录/实例被删除、替换或变为未批准链接时，拒绝操作，不把它当成一个新的空目录。资源身份更新与 GrantStore 失效通知分开执行，避免目录锁、授权锁和服务锁互相等待。

授权/资源锁只保护内存状态与短时准入，不包围扫描、磁盘长读取、Worker 回调或用户代码。查询在读取前取得授权租约，分页生成及最终交付前复核授权 epoch、内容、run 和资源代次。范围缩小后，旧引用与旧游标失效；仍被批准的资源可在新的 epoch 重新发现，不延用旧租约。

必要资源全部失效时按现行必要权限机制停止 Worker；可选范围失效只拒绝对应新调用。已进入宿主的查询仍按实际执行完成跟踪，等待超时不代表读线程结束；未结束时按现行 cleanup pending 表达，不强杀宿主线程。

## 4. Host API 与 DTO

总体设计缺少共享资源引用的首次发现入口，本轮补充以下明确契约，并在实施时同步总体目录、SDK 示例、严格模型和测试。

| 方法 | 请求 | 返回及约束 |
| --- | --- | --- |
| `resources.list` | `{capability:"instances.read",cursor?:string,limit?:int}` | `Page<ResourceView>`；只列本运行当前获准的目录/实例，不列全部配置；无许可则拒绝 |
| `instances.scan` | `{root_ref,force?:bool,cursor?:string,limit?:int}` | `Page<InstanceView>`；只接受本运行获准的目录引用；单实例许可不能用于扫描其父目录 |
| `instances.get` | `{instance_ref}` | 当前 `InstanceView`；接受直接批准的实例，或在获准目录扫描中派生出的实例引用 |

`ResourceView` 为严格判别联合：目录 `{kind:"instance_root",root_ref,label}`，实例 `{kind:"instance",instance_ref,version_id,label}`。label 仅使用批准范围内的目录短名称/实例展示名称，不返回绝对路径或配置中的任意对象。资源列表同样受 64 KiB 上限限制。

`permissions.list` 中 `instances.read` 的 `resource_refs` 转换为本运行引用，保持授权结果与运行 API 一致；原始持久资源 ID 不交给 Worker。可信管理页使用单独的候选 DTO 与持久资源 ID。引用本身不替代授权，每次调用都检查实际许可。

`InstanceView` 本轮精确字段：

```text
instance_ref: string
version_id: string
alias: string
loader: string | null
game_version: string | null
profile: {description: string, favorite: bool, tags: string[]}
profile_etag: string
running_count: int >= 0
```

- DTO 显式构造；不得透传扫描字典、`rootKey`、`instanceKey`、path/jsonPath、图标路径、完整启动配置或统计源记录。用户资料文本为获准业务内容，按 DTO 长度界限投影。
- 本轮资料读取仅组合本地 ECL 覆盖及实例自身声明，不读取 QomicEX 等外部提供方或同步第三方统计。缺省别名采用 version_id；不能确定的加载器/游戏版本返回 null，不伪装为已成功识别。
- **已批准的总体 DTO 修订**：当前 profile 无递增版本，因此本轮以 `profile_etag` 表达公开资料快照摘要，替代原拟议 `profile_revision:int`。该摘要不承诺单调性，也不作为已实现的写入令牌；不写入新 revision 文件，不伪造 0。未来 P09 的资料写接口及其并发契约届时一起确定，当前仍未开放。
- alias 最多 120 字符、description 最多 1000 字符；tags 复用本地资料现行规则，最多 20 项、单项 40 字符（严于 DTO 的 64 项/64 字符上界）。只对这类展示文本按边界截取，身份字段超限明确失败，不截断身份造成碰撞。
- 分页 limit 为 1—100，默认 50，按可容纳的结果字节数提前分页。游标绑定安装/内容/run/epoch、查询条件与资源代次；不得仅信任客户端 offset。最多同时保留 16 个分页快照，120 秒到期；容量耗尽明确失败，不保留无界列表。
- 一次扫描最多登记 4096 个实例，资源目录展示及授予最多沿用现有 128 个精确选择；超过边界明确提示缩小范围，不静默截掉列表后声称完整。目录枚举和继承读取按截止时间检查。
- 只读分派在执行前将 scan 截止限制为 30 秒、get/resources 限制为 5 秒，取请求更短预算；磁盘系统调用本身不能因 Python 超时而被宣称已停止。
- 错字段、裸路径、错误类型及未知引用明确失败。使用既有稳定公共错误；补充 `PLUGIN_RESOURCE_UNAVAILABLE`、`PLUGIN_CURSOR_INVALID`、`PLUGIN_INSTANCE_METADATA_INVALID` 等明确错误并同步文案。错误响应及日志不包含私有路径或原始 JSON。

## 5. 真正只读的实例数据路径

新增 `ECL/services/game/instance_queries.py`，由既有 GameService 暴露窄的类型化实例摘要查询。Broker 只负责身份、权限、输入输出、分页及交付；元数据识别、资料读取和运行计数仍属于游戏领域。

1. 验证宿主解析的目录/实例身份；实例名称遵循现有目录名校验。不因客户端字段切换 game_path，也不在单实例查询中先扫描整个目录再过滤。
2. 只读取实例声明、必要的本地父元数据和 ECL 资料白名单。继承父声明仅用于解析目标版本和组件，不输出父实例资料；继承链限制为 64，不能越过已批准根边界。不读取日志、存档、账户及任意文件。
3. 用有界文件读取检查大小及 JSON 类型：单个实例声明最多 8 MiB、ECL 资料最多 64 KiB、一次查询累计读取最多 64 MiB；JSON 拒绝非有限数值和过深结构，超限明确失败。根、versions、实例、父声明及资料文件均校验链接、重解析点与实际读取对象；Windows 和 POSIX 分支分别测试。读取通过已验证句柄取得的对象，读取前及交付前复核资源身份，不把单次 `Path.resolve()` 当成完整边界证明。
4. Core 增加 `InstanceMetadata.from_documents(...)` 纯解析公开方法；现有 read 路径复用它，主仓库查询传入受控读取后的文档，复用已有组件和游戏版本识别。该小范围 Core 接口变更是本方案的明确组成部分，不修改 Core 的扫描/启动行为，也不改 Florolding。
5. 在实例资料所属模块提取无写入的本地字段校验/解析入口；现有读接口复用其规则。对损坏文件或读取失败返回可观察错误；首次缺少 ECL 覆盖是正常未设置，保留原文件，不生成默认文件。
6. `running_count` 读取既有 GameService 锁保护的受管理运行快照；不调用会执行退出收尾的 `list_instances()`，不枚举所有系统进程，不假造所有游戏已停止。
7. 不调用 `_ensure_ecl_config`、`VersionStatsStore.ensure/read/reconcile_external`、写配置、初始化图标、外部提供方及新目录监视。force 仅使本查询快照失效，不刷新会写入磁盘的桌面扫描链路。

业务只读指不写用户游戏数据；可信授权管理仍可原子保存宿主资源目录和授权。若现有服务抽取后无法保证上述读取边界，保持对应方法不开放并报告具体阻碍，不用宽松全目录扫描代替。

## 6. 可信权限界面与注入

- 新增仅主 WebView 可用的 `plugin_permission_resources`，请求包含 installation_id、content_digest、能力、父候选标识及有界分页；返回当前候选、选择状态、不可用状态和目录版本。插件、Dev Channel、未知入口与伪造 body 均不能调用。
- 资源候选采用按目录展开及搜索/分页，不预先将全部目录的实例加载进一个响应。目录候选只来自有效配置，单目录展开只做上述无写入读取。
- `plugin_permissions_update` 对资源选择复核内容、授权 revision、目录版本和候选 ID。过期页面或被替换资源拒绝保存并提示刷新，不把客户端提交的标签/路径当成证明。
- 复用现有 Modal、Naive UI、useRequestScope 和执行锁。切换插件、目录或查询时旧响应不能覆盖当前选项；加载、空目录、失败、删除及保存冲突均有明确状态。
- 提示“该目录全部实例，包含以后新增”及“仅所选实例”；显示必要/可选状态、允许期限和有效选择数量。撤销后不能因为折叠/分页而保留隐藏的允许；同一实例被目录范围覆盖时明确展示覆盖关系。
- 所有用户文案同步六语。默认/最小/放大窗口及 Classic/Folia、亮暗主题、背景透明度/模糊设置依根规范验收，主要滚动区域和底部操作可达。
- 在 `application.py` 将共享游戏查询和有效配置提供器注入管理器/Worker 服务。仅构造服务对象不扫描实例或修改目录；命令行普通 headless 与 Worker bootstrap 不初始化完整宿主业务服务。
- 严格同步 IPC 模型、命令注册、日志策略和前端请求/响应校验；查询按查询通道记录，不记录选择路径、完整配置或账户信息。主入口日志继续由统一边界负责。

## 7. 实施文件与顺序

| 步骤 | 主要落点 | 可独立检查的结果 |
| --- | --- | --- |
| 1. 契约及回归 | grant_models/store、runtime/models；新增查询/资源测试 | 清单请求与用户选择分离，原有自身权限行为不回归；记录本方案中的 API 修订 |
| 2. 无写入读取 | Core `Data/instance_metadata.py` 与测试；主仓库 instance_queries、instance_profiles、launch 的纯快照入口 | 临时游戏目录树查询前后字节不变；加载器识别复用；运行查询无收尾副作用 |
| 3. 资源身份与生命周期 | 新增 `ECL/plugins/resource_catalog.py`、`runtime/resources.py` | 持久身份、退休、实例/目录范围、run 引用和游标；严格原子记录与关闭路径 |
| 4. Host API 接线 | runtime/broker、worker_service、manager/base、application | 仅获准资源可查；前后校验；范围缩小、迟到结果与断线不泄漏 |
| 5. 可信管理入口和 UI | api/plugins、plugin_models、registry、models、operation_logging；前端权限 API/类型/模态/六语 | 精确资源审阅、冲突刷新、无默认全选、去重及旧响应失效 |
| 6. 示例与交付 | 新增 `examples/plugins/instance_reader`；测试、总体设计/API 文档 | 审阅一个实例或目录 → Worker 查询 → 撤销 → 拒绝旧引用，真实冻结及桌面证据 |

这里的三个新增职责各有实际调用方：资源目录维护持久物理身份；运行资源表维护 run 引用和分页生命周期；游戏查询协调器读取领域摘要。不创建第二套游戏服务、配置存储或任务系统。

## 8. 测试、验收与交付

按 [AGENTS.md 第 6 节](../../AGENTS.md#6-测试与验收) 执行完整适用门禁；Core 改动同时执行其自身检查与主仓库集成测试。下表为新增行为要求，不替代统一门禁。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 未审阅、未允许、必要未选择、可选拒绝 | 无业务读取、无新增许可；必要阻止启用，可选明确拒绝查询 |
| 批准 A 目录、仅选 A1 实例 | 目录授权可扫 A；单实例只能获取 A1，不能扫父目录、读取 A2 或其他根 |
| 目录未来新增与单实例同名重建 | 目录范围内新增可见；单实例重建不继承旧授权；UI 说明与行为一致 |
| 跨安装/内容/run、错误类型、猜测引用、失效游标 | 明确拒绝，无路径及未授权资源信息返回 |
| 目录别名、大小写、symlink/junction/reparse、父声明越界 | 不混淆资源或读取外部内容；不能安全验证则失败，保留原文件 |
| 配置移除/重加、资源替换、损坏资源记录 | 原选择失效，不自动绑定同名新资源；资源故障不影响现有自身设置能力 |
| 查询中撤销/缩小/到期、断连、超时、外部配置变化 | 读取前和交付前拒绝失效租约；迟到结果不交付；等待取消不报线程已结束 |
| 并发审阅、外部宿主更新、资源候选页面过期 | revision/目录版本冲突，不覆盖他人决定；资源记录原子保存失败保留原文件 |
| 首次缺配置、损坏 JSON、继承循环、超过文件/条目/结果上限 | 缺少可选覆盖按未设置处理；其他错误明确返回；有界且不写用户数据 |
| 白名单 DTO | 注入 path/token/完整配置等额外字段不能被透传；profile_etag 为真实公开快照摘要 |
| 查询副作用 | 游戏目录及全部文件内容查询前后相同；不创建 ecl.json、统计、图标、监听或网络请求；不停止游戏 |
| UI 异步和可访问性 | 双击只提交一次、失败可重试、旧响应失效、所有分页选择和底部按钮可达、键盘焦点正确 |

示例通过命令返回可见实例数与单个实例的名称/版本摘要，避免为了输出任意嵌套对象而扩大现有命令 FieldSpec。测试直接验证 Host DTO 的全部字段及分页。真实 Windows 数据目录仅包含人工夹具，不扫描个人游戏库或账户。

## 9. 实施与验收记录
