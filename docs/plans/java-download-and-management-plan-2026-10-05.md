# Java 下载与管理实施方案

日期：2026-10-05。基线：主仓库 `6319626`、前端 `220069b`、Core `f8c7a64`。

状态：用户已确认开始实施，功能与必要检查已完成。交付范围为统一管理页及全局、实例和缺失 Java 时的快捷入口。

## 1. 已选择的方案与目标

此前提供三种方案：轻量下载弹窗、统一管理页、完整多发行商管理。用户选择统一管理页，既覆盖日常下载和维护，也保留实例设置中的快捷操作。

本方案交付：

1. 设置中新增 Java 管理页，统一显示系统发现、手动登记和启动器安装的运行时。
2. 下载适用的 Java；默认推荐 JRE，有需要时可选 JDK。根据实例要求选择主版本，列表来自实际来源元数据。
3. 手动登记、重新扫描、启用/停用、查看路径与使用情况；缺失或无效的已登记条目保留原因。
4. 为启动器安装的 Java 检查同主版本更新、安装新版本、移除旧版本。
5. 在全局与实例 Java 选择器提供管理入口；缺少 Java 时提供按当前实例需求下载的入口。

完成安装后由用户选择使用范围。安装、选用和重新启动是不同动作；下载完成本身不改其他实例的独立设置。

## 3. 下载来源与版本策略

首批下载源推荐 Eclipse Temurin 官方 API，保持单一明确来源；统一管理页仍可登记其他发行商的现有 Java。新增第二个下载发行商另行评估，不在本次搭建通用发行商插件框架。

- 使用 available_releases 与 assets 元数据获取 GA 正式发布包，默认突出常用 8、17、21、25；其他实际可用版本可展开选择，不将这些数字当作完整固定目录。
- 默认按后台识别的平台和架构查询，默认 JRE；JRE 不存在时明确展示可选 JDK，不在后台静默换包。
- 每个可下载候选必须有明确发行版本、包类型、平台、架构、下载大小和 SHA-256；后端保存不可变安装计划。
- 官方“版本存在”不等于某个平台有包。只展示实际查询出的组合，不把空列表标成可安装。
- 安装目录和可信下载地址由后端计划生成；提交安装时只接受计划标识，不接受任意前端 URL 或任意删除路径。
- 元数据走启动器网络通道，二进制下载走现有下载代理通道；请求有超时和有上限的重试，离线时保留本地清单。

2026-10-05 实际元数据查询：Windows x64 的 Java 21、25 JRE 均有 ZIP 与 SHA-256；Java 25 Windows aarch64 的 JRE/JDK 列表为空。该组合展示来源暂无适用包及手动登记入口，不宣称完整 ARM 覆盖。Windows ARM 原生补全发行商可作为用户调整本方案的选项。

来源：[Adoptium API 文档](https://api.adoptium.net/)、[官方 API 使用说明](https://github.com/adoptium/api.adoptium.net/blob/main/docs/cookbook.adoc)、[当前版本目录](https://api.adoptium.net/v3/info/available_releases)。

## 4. 页面与操作流程

### 4.1 设置 → Java 管理

新增路由 `/settings/java`，位于设置的游戏项之后。页面有“已安装”和“下载”两个视图。

已安装视图：

- 工具栏提供搜索、重新扫描、添加现有 Java、检查更新。
- 每行显示供应商、JDK/JRE、完整版本、架构、系统/手动/启动器安装来源、启用状态与有效性。
- 路径作为次要信息，支持打开目录；长路径不挤压主要操作。
- 展示全局或实例引用、运行中使用状态，帮助用户判断是否可移除。
- 操作包含使用、启用/停用、更新及移除。系统和手动 Java 的移除仅移除登记，不删除外部目录。
- 已登记路径失效时保留条目，显示重新定位或重新安装入口；选择器只提供适用的有效条目。

下载视图：

- 默认当前平台、架构和适用主版本，展示推荐 JRE；JDK 选择放在次要选项。
- 每个候选展示来源、准确发行版本、类型、下载大小和安装位置。
- 空包、查询失败、离线分别显示相应状态，并可刷新。
- 确认安装计划后提交任务；阶段为下载、校验、解压、探测、登记，复用统一任务面板。
- 预览的磁盘需求是保守估算；下载包大小不冒充解压体积，实际解压总量另行核验。

### 4.2 全局设置与实例设置

Java 选择器保留即时选择和刷新，浏览选中的 Java 验证并登记后再回填。新增“管理/下载”入口，打开复用管理内容的弹窗；只有一份 Java 运行时状态。

实例设置的管理弹窗保留当前表单和保存会话。选择运行时后只修改 javaMode/javaPath，交由既有实例保存会话即时保存；不拿一个旧整表单覆盖其他刚编辑的字段。全局使用走现有 settingsStore 的局部合并保存队列。

点击使用前重新验证运行时和实例要求。切换实例、关闭弹窗或旧查询返回，不得把选择回填到另一个目标。失败保留原选择。

### 4.3 缺少 Java 的恢复入口

在现有 JAVA_NOT_FOUND / JAVA_VERSION_NOT_FOUND 恢复区域增加“下载适用 Java”，打开同一管理内容并传入当前实例目标和版本要求。

下载后提供“用于当前实例”。使用成功后用户可重新启动；下载完成、等待超时或关闭页面不隐式恢复已取消的启动流程。要求尚无法识别时明确展示未知，让用户选择版本，不固定下载 Java 21。

六种语言一起补齐；新增操作需有可访问名称、键盘焦点与窄窗口布局。

## 5. 数据模型与状态归属

新增 `ECL/services/java/` 领域服务，负责登记、来源查询、安装与运行时生命周期；应用启动时创建，关闭时释放网络客户端、任务和订阅。GameService 消费该服务，不维护第二份独立登记清单。

建议模块：

| 模块 | 职责 |
| --- | --- |
| `models.py` | 不可变运行时信息、登记记录、下载候选与安装计划 |
| `registry.py` | 原子清单读写、手动登记、状态修改和真实路径身份 |
| `catalog.py` | Temurin 元数据校验、有界缓存与平台可用包查询 |
| `installer.py` | 下载、哈希、临时安装、探测与最终提交 |
| `archives.py` | Java ZIP/TAR 布局、内部链接和可执行权限校验 |
| `lifecycle.py` | 启动/运行使用租约、引用检查、移除与失败清理 |
| `manager.py` | 公共协调接口与服务关闭 |

字段分开表达：runtime_id、executable_path、java_home_path、vendor、runtime_kind、major_version、full_version、architecture、origin、is_enabled、validation_status；发行来源使用 distribution_source，原有 sources 是发现来源的协议兼容字段，不能混用。

身份由后端确认的实际 Java Home 与可执行路径确定；Windows java/javaw 同运行时归属合并，大小写及链接别名按平台和实际文件确认，不对 POSIX 路径一律 casefold。

默认托管目录为 `<启动器数据目录>/runtimes/java`，清单与临时目录同根。该位置若在 macOS `.app` 内或只读安装包，使用平台用户数据目录下 `EuoraCraft-Launcher/runtimes/java`；只确定新增 Java 的存储位置，不迁移已有配置。测试明确注入临时根目录。

前端新增 `features/java` API、store 和管理内容组件，统一拥有清单、查询代次和操作状态；settingsStore 原 Java 清单消费者迁入该唯一状态，避免管理页与选择器各自缓存。

## 6. 安装、更新与移除规则

### 6.1 安装

1. 生成有有效期的服务端计划，核验版本、平台、架构、来源、大小与 SHA-256，并检查可写目录和磁盘空间。
2. 同一安装目标串行且幂等，跨窗口重复提交不得启动第二个同包安装；返回已有任务或明确状态。
3. 下载到独立临时目录，使用有限重试，校验文件大小和 SHA-256，再解压。
4. 限制归档文件数、总解压字节与压缩比；拒绝越界、重复冲突路径和特殊设备文件。内部链接仅在验证目标始终位于临时根目录后处理；拒绝外部链接及链接链逃逸。POSIX 执行位仅按运行所需设置，不保留提权权限。
5. 找到真实 Java Home，包括 macOS Contents/Home 布局；执行有超时的真实探测，核验主版本、架构、JDK/JRE 与可执行性。来源发行版本与探测版本使用不同字段，不能直接按字符串等同。
6. 在取消互斥提交边界内，把临时安装原子移入正式目录并登记。登记失败回滚本次目录，不损害已有 Java；提交成功后不再把取消报告成已经撤销安装。
7. 发布清单变更事件，统一刷新页面与选择器；原有 Java 和配置保持到用户明确选用新运行时。

### 6.2 更新与自动选择

检查更新只适用于有可信安装来源的托管 Java，按相同主版本、包类型、平台、架构查询补丁更新。Java 21 升级到 25 是新的安装与选择，不当作普通补丁更新。

新版本先完整安装、验证并登记，旧版本保留。用户选择应用范围，显式绑定未被批量改写。自动选择保留既有“满足当前要求的最近主版本”规则，同主版本优先有效的较新补丁；未知比较结果保留确定性回退，不据文件夹名字推断版本。

停用影响后续选择和启动，不停止已经运行的游戏；显式使用停用条目时给出清晰恢复入口。启用失效条目不能把它当成可运行状态。

### 6.3 使用保护与移除

移除前重新检查全局和已配置实例根目录的独立 Java 引用、正在启动的任务与游戏进程。仍被引用时引导先切换；使用状态或引用检查无法确认时保留文件。

启动时取得运行时使用租约，进程真正退出后释放。记录实际所用 Java 与进程身份；启动器退出后游戏仍运行的情况必须保留可核对的占用信息，重启时按 PID 与进程启动时间核对，不只依赖当前页面的运行列表。

物理移除仅适用于登记为启动器安装、边界与安装文件清单仍可信的目录；发现外部路径、替换链接或未知新增文件时拒绝递归删除。

移除采用“改名移出可用目录 → 登记移除 → 清理”的顺序：登记失败改名恢复，清理失败保留可重试的清理记录，不报告空间已完全释放。系统发现条目可停用；手动条目可移除登记，外部文件保留。
