# LittleSkin 账户材质管理实施方案

日期：2026-11-03。

状态：用户已审阅并明确批准“开始实施”；第一阶段本地实现及模拟提供方验收完成，官方完整授权和真实账户写操作仍待应用准入及测试目标。验证记录见第 11 节。

## 1. 已确认需求与取舍

- 第一阶段只扩展 LittleSkin OAuth 账户，复用现有账户入口、本地衣柜和三维预览。
- 支持查看当前皮肤和披风、浏览 LittleSkin 云端衣柜、选择穿戴、取消穿戴、下载到本地衣柜和另存 PNG。
- 用户最初希望上传后直接穿戴，后选择分阶段推进，并进一步明确“上传先做 todo”。因此上传整体列为后续 TODO，本阶段不提供上传操作或跳转上传网站的入口。
- 本地衣柜和 LittleSkin 云端衣柜有明确的来源标识；本地导入不表示已上传，预览不表示已经穿戴。
- 不扩展 Microsoft、普通密码外置账户或插件账户的管理能力；已有行为和入口保持现有语义。
- 不包含角色新增、删除、改名，云端收藏增删改、公共皮肤库搜索，以及个人资料、邮箱、密码管理。

已比较的安排：

| 方案 | 收益与限制 | 结论 |
| --- | --- | --- |
| 先做已有 OAuth 接口支持的选择、穿戴和下载 | 可以独立交付；上传仍需后续接口调研 | 用户选定，上传进一步调整为纯 TODO |
| 等待确认 PNG 上传接口后一次性交付 | 上传与穿戴连续完成，但阻塞整个管理功能 | 本轮不采用 |

## 2. 调研基线与已有能力

主仓库基线：`082f832`；前端基线：`6a50fd6376475f30e936d98f9553a40d4be4973f`。

- `ECL/services/account/littleskin.py` 已实现两种 OAuth、角色读取及游戏令牌兑换；当前登录只请求游戏登录权限，设备代码流另带 `offline_access`。
- `authlib.py` 持有账户 OAuth 凭据、刷新与删除互斥锁、轮换后写盘失败的恢复状态；管理请求必须复用同一凭据所有者，不能再维护一份令牌缓存。
- `accounts.py` 聚合账户、提供材质地址并发布账户更新；账户来源标记为 `auth_provider: littleskin`。
- `ECL/api/accounts.py` 已有当前账户皮肤下载、本地衣柜导入、去重、导出与 Microsoft 穿戴命令。当前远程同步只处理皮肤，导出标题和前端按钮也有皮肤限定，需要在本次下载范围内补齐披风。
- `WardrobeModal.vue` 位于游戏页面，支持目标账户、本地皮肤/披风、正版披风、三维预览及请求失效保护。目前本地素材的远程穿戴限定 Microsoft。
- 现有 `accounts:changed` 数据及头像材质失效列表负责同步展示；不新增平行的头像刷新事件。
- 前端无关的 `MAPPING_TABLE.yaml` 删除及主仓库未跟踪 `output/` 保留，不加入本轮提交。

## 3. 外部接口、授权和准入前提

### 3.1 第一阶段使用的接口

| 业务 | 官方接口 | 请求约束 |
| --- | --- | --- |
| 读取名下角色及当前材质编号 | `GET /api/players` | 校验角色数组、正整数 PID、名称与材质编号 |
| 读取云端衣柜 | `GET /api/closet?category=skin\|cape&page=N` | 校验分页、材质 TID、类型、名称和哈希，不信任返回的下一页 URL |
| 穿戴皮肤或披风 | `PUT /api/players/{pid}/textures` | 每次只发送选定的 `skin` 或 `cape`，不覆盖另一项 |
| 清除皮肤或披风 | `DELETE /api/players/{pid}/textures` | 使用文档中的 `type` 数组格式，只清除用户指定的一项 |
| 当前材质与角色 UUID 核对 | 现有 Yggdrasil 档案读取 | 复用现有类型及材质模型，不解码 OAuth 令牌 |

当前 LittleSkin 文档链接到 Blessing Skin API，且说明接口仍可能变化。实施先用脱敏响应核对 LittleSkin 实际接口，不能把旧上游文档或 mock 测试当成官方联调成功。

角色管理的 PID 与游戏 UUID 是两种标识。服务端根据本地账户绑定 UUID，在本次 OAuth 授权的 Yggdrasil 角色中查到当前名称，再与同一令牌的 `/api/players` 名下角色进行唯一匹配；不能把 UUID 转成 PID，不能使用本地别名匹配，也不能接受前端指定 PID。缺失、重名或不一致时拒绝写操作并提示刷新或重新授权。写操作前重新核对目标归属，避免使用过期角色列表。

### 3.2 权限补齐

- 普通游戏登录继续使用现有权限集合。
- 管理授权在原游戏登录权限上增加 `Player.ReadWrite` 和 `Closet.ReadWrite`，设备代码流继续保留 `offline_access`。这与维护者提供的已获批列表一致；第一阶段只读取云端衣柜，不暴露云端收藏的写操作。该选择不宣称是仅供读取的最小权限；后续若独立申请并验证 `Closet.Read`，可再收窄。
- 应用获批权限与具体令牌获得的授权分开处理。进入管理界面时执行实际读取；仅明确的权限拒绝引导“授权账户管理”，网络、服务异常、限流和损坏响应分别提示，不全部归为缺授权。
- 管理授权复用已有设备代码/授权代码流程，但绑定目标账户；新授权中必须仍包含目标 UUID，不展示可将目标改为其他角色的选择步骤。
- 成功后沿用账户 ID、别名、收藏、置顶及当前选中状态；只有全部校验和持久化成功后替换目标凭据。取消、拒绝、账户不匹配或保存失败保留原账户。
- 不新增读取旧格式、自动迁移账户文件或解码令牌判断权限的逻辑。权限不足通过真实 API 响应识别，无需新增持久化权限缓存。
- 先前真实设备授权报错的 `Yggdrasil.MinecraftToken.Create` 准入仍是独立的登录前提。用户提供的获批清单缺少该项；在确认补齐前，不承诺官方完整授权与真实游戏验收已经具备条件。

## 4. 界面与交互

1. LittleSkin 账户的管理操作打开现有衣柜，并预选该账户；复用账户列表操作和弹窗结构，不另建账户管理页面。
2. 保留现有本地皮肤/披风区域；选中 LittleSkin 时增加“LittleSkin 云端”来源，在其中切换皮肤/披风并分页。Microsoft 的正版披风保持原归属。
3. 云端条目显示名称、类型及当前穿戴状态。选中条目只更新预览，点击“穿戴”后才发送修改请求。
4. 提供“下载到本地衣柜”和本地条目的“另存为”；当前穿戴的皮肤、披风也可下载。无披风或默认皮肤未返回可下载文件时说明原因。
5. 分别提供重置皮肤和移除披风；操作成功后刷新当前材质与头像，服务端成功但后续刷新失败时显示“已修改，刷新失败”，不引导重复提交写操作。
6. 云端衣柜提供手动刷新。分页、账户、类别切换后清理选中项并使旧请求失效，不显示上一账户的私有收藏。
7. 权限不足时展示简短原因及补充授权入口；沿用两种登录方式、取消和过期交互，在同一管理流程中完成后回到原账户。
8. 上传只存在于本文 TODO，不放置可点击但无法完成的产品按钮，也不将“打开网页”包装为上传成功。

新增功能面向已存在的 LittleSkin 账户，不按界面语言禁用其管理。新登录入口仍沿用上一方案的简体中文限定；管理界面文案、错误、可访问名称同步六语言。

## 5. 后端职责与协议改动

### 5.1 复用现有领域边界

- `LittleSkinClient` 增加角色管理和云端衣柜的协议方法及 Pydantic 外部响应模型，统一处理 HTTP 状态与 HTTP 200 内的业务错误码。
- `AuthlibAccountManager` 在现有 OAuth 互斥边界内提供管理请求入口，复用刷新和旋转令牌先落盘策略；管理读取不额外兑换游戏令牌。与删除、登录覆盖和游戏刷新保持一致的锁顺序，网络阶段不长期占用账户列表锁。
- `AccountManager` 校验来源与目标账户，编排角色绑定、凭据替换和材质更新通知。管理授权不复用“添加账户后自动选中”的提交副作用。
- `LittleSkinLogin` 为补充授权增加明确的会话用途和目标账户，延续单活动会话、实际取消、临时材料清理及保存期间防重入约束。
- 沿用 `WardrobeStore` 的原始 PNG 校验、哈希去重和原子写入；本地素材来源与云端 TID 分别建模，不将云端列表复制成第二份可写的本地收藏状态。
- 不新增通用皮肤站适配器、全局提供方注册表或与当前调用方无关的管理框架。

### 5.2 IPC 草案

| 命令 | 请求与结果 |
| --- | --- |
| `accounts_littleskin_management` | 本地账户 ID；返回当前角色、穿戴信息及管理权限状态，无凭据 |
| `accounts_littleskin_closet` | 账户 ID、类别、正整数页码；返回已校验的分页和云端条目 |
| `accounts_littleskin_set_texture` | 账户 ID、材质种类、正整数 TID；核对授权衣柜及角色后穿戴 |
| `accounts_littleskin_reset_texture` | 账户 ID、材质种类；只重置一项 |
| `wardrobe_sync_account_texture` | 替代仅限皮肤的同步命令；账户 ID、材质种类，返回本地条目及去重结果 |
| `wardrobe_import_littleskin_texture` | 账户 ID、TID、类别；从已验证云端条目下载到本地衣柜 |

已有 `accounts_start_littleskin_login` 请求增加用途判别：普通登录与目标账户管理授权分别校验字段，管理完成沿用现有会话查询/取消/提交命令。不新增第二组轮询命令。

替换 `wardrobe_sync_account_skin` 时同步修改注册表、模型、API 类型、前端调用、Showcase、日志规则和测试，删除旧入口，不保留无需求的转发别名。现有导出命令补齐披风的文件名、对话框标题和界面入口，不改变原始 PNG。

具体命令命名可在编码时随职责微调，但功能范围、凭据边界和替换策略不得隐式扩大。

## 6. 输入、并发与失败处理

- IPC 只接收本地账户 ID、种类、页码和 TID；前端不传 OAuth 令牌、任意 API 地址、角色 PID或目标文件路径。
- 云端条目需验证属于目标 OAuth 用户可见衣柜，类型与操作一致；不凭 TID 数值直接为任意角色穿戴。
- PNG 下载使用受信材质来源、限长流式读取和既有尺寸/类型校验；响应及重定向目的地都要核对，认证头不随材质下载发送。不为任意 URL 新增通用下载入口。
- 当前角色下载复用既有材质读取；云端下载根据已验证哈希和官方材质地址契约取原图。实施时核实真实哈希格式及允许的官方材质域名，不放行任意第三方主机。
- 修改操作按账户串行并防重复提交；账号切换或页面退出可使等待结果失效，但不能声称已撤回服务端已经执行的穿戴。实际结果仍使相关账户材质缓存失效。
- 401、权限拒绝、限流、连接失败、响应损坏、无角色和材质失效使用各自稳定错误码。远程写操作超时不自动重放，先重新读取当前穿戴以确认结果。
- 只修改用户选择的皮肤或披风；写请求失败不以默认数据覆盖另一个材质。远端成功后本地刷新失败保留真实成功事实和明确恢复入口。
- OAuth 刷新、账户删除和重新授权替换必须使用同一凭据所有者；外部操作均有超时，取消等待与实际停止分别处理。
- 查询及轮询成功保持安静；穿戴、清除、下载只记录实际结果，日志不输出令牌、完整响应、私有收藏或个人路径。

## 8. 测试与验收

本功能涉及账户认证与凭据、IPC、外部写操作、文件写入和共享状态，按主仓库 AGENTS.md 第 6 节执行受影响仓库全量检查，不按普通文案或局部 UI 修复处理。

- 后端：Ruff 检查及格式检查、全量 pytest；对应命令以 AGENTS.md 第 6.2 节为准。测试使用隔离账户目录，不修改维护者真实账户。
- 前端：`pnpm check`、`pnpm build`；在既有相关测试中补充行为回归，不引入新的测试框架或无关依赖。
- 角色归属：UUID 与 PID 区分、角色改名、缺失/歧义匹配、伪造 PID/TID、另一用户的材质、另一角色不被覆盖。
- 授权：两种方式、管理用途字段校验、账号不匹配、权限拒绝与网络错误区分、取消/超时、旧凭据保留、同 ID 与偏好/当前选择不变、并发刷新及轮换写盘失败。
- 远端操作：只修改一项、重置一项、不重复提交、超时后读取确认、成功后刷新失败、删除与刷新竞争、页面关闭后实际完成仍通知正确账户。
- 云端读取：分页、皮肤/披风类型、空衣柜、非法响应、限流、账户切换后旧数据失效。
- 下载导出：当前/云端皮肤和披风、PNG 格式与尺寸、超长响应、错误种类、不可信重定向、去重、磁盘失败、保存对话框取消、原始字节不变。
- 直接消费方回归：Microsoft 穿戴与官方披风、普通外置账户材质读取、本地衣柜导入导出、现有游戏登录和凭据刷新。
- 真实浏览器：Classic/Folia × 亮暗，960×600、默认和放大窗口；检查长名称、分页、末项可达、焦点、错误及透明度/模糊代表配置。
- Windows 原生：管理 IPC、两种补充授权、原生保存对话框和取消；涉及本机回调时覆盖 Windows/POSIX 分支。未执行的其他平台原生检查明确列出。
- 官方联调：先核实应用准入和 `MinecraftToken.Create`，再验证目标用户的只读列表；穿戴/清除须由维护者指定测试角色与素材，记录原穿戴并提供恢复。未获得真实写操作授权时只做模拟，明确其验收缺口。
