# 下载结果布局、后续五页预加载与调试工具停靠实施方案

状态：用户已确认开始实施；布局、五页预加载、左上角停靠、自动检查与 Windows 桌面验收已完成。

## 需求与选定方案

1. 下载页面右侧结果卡片填满工具栏以下的剩余高度，底边与左侧菜单卡片对齐；加载中、空结果和有结果时保持一致。
2. 当前搜索页显示后，额外预加载后续五页。例如当前为第 1 页，则后台准备第 2～6 页；切到第 2 页后继续补齐第 3～7 页。
3. 调试工具收起条默认位于页面区左上角，并保留收起状态下的拖动能力。全屏弹窗打开时，收起条停靠到当前弹窗区左上角，并能正常展开使用；展开面板保留拖动和调整尺寸功能。

用户最初写成右上角，随后明确更正为左上角，本文以左上角为唯一目标。

已比较的调试层级方案：

- 方案 1：在当前全屏弹窗内部提供调试工具的停靠位置，并参与该弹窗的焦点管理；普通确认弹窗出现时暂时隐藏工具。用户已选择。
- 方案 2：全屏弹窗打开时隐藏工具，关闭后恢复。实现较简单，但无法直接调试全屏弹窗内容，不采用。

## 当前实现与原因

- `Download.vue` 的外层为占满页面的网格，左侧菜单自然拉伸；右侧 `download-content` 是 flex 容器，但 `OnlineModSearch.vue` 的 `.oms-root` 只有相对定位，没有建立完整的纵向伸展链。
- `.mods-results-panel` 虽有 `flex: 1`，其父级缺少对应 flex 布局，加载区最终主要依赖 240px 最小高度，空状态另有 360px 最小高度，因此卡片底边不能跟随菜单。
- `OnlineModSearch.vue` 已有最大 60 项的页缓存和旧响应守卫，但缓存只用于单来源，且只存结果、总数和来源状态；聚合搜索仍逐页访问后端，没有后续五页预加载。
- 后端 `ResourceSearchService` 通过同一会话锁串行扩充聚合页，要求目标页不能超过已构建页数加一。前端必须顺序推进该会话，避免跳页和请求争用。
- 调试工具通过 Teleport 放在 body，固定 `z-index: 90`；全屏弹窗为 100。当前工具在所有覆盖层出现时变为 inert，但仍然显示，透明弹窗背景下会露出被内容遮住的一部分。
- 调试收起条与展开面板共用 x/y 坐标。当前默认收起位置虽在右侧，展开时尺寸收敛、移动和再次收起都会改变其实际位置，无法稳定停靠。

## 改动点

### 1. 结果卡片填满剩余高度

- 调整 `Download.vue` 与 `OnlineMods.css`，让右侧内容、搜索根节点、结果面板和内部加载/滚动容器建立完整的 flex 高度链，使用 `min-height: 0` 防止内容撑开外层网格。
- 搜索栏与来源提示占据自身高度；结果面板伸展到右侧区域底部；列表通过现有滚动容器滚动。
- 将加载和空状态的高度规则收敛到结果面板的可用高度。窗口较矮或筛选栏换行时允许必要滚动，确保输入、分页和提示能够访问。
- 验证相同视口下左侧菜单和右侧结果面板底边误差不超过 2px；验证加载状态切换不会使卡片高度跳动。

### 2. 当前页之后预加载五页

- 将页面请求、完整响应缓存和预加载调度从组件中提取为下载领域的可测试模块，组件继续负责当前页展示和交互。
- 缓存键覆盖资源类型、搜索词、来源、排序、版本、加载器和安装目标；聚合页同时属于明确的搜索会话与请求代次。
- 缓存完整分页响应，包括结果、来源状态、总量、页码、会话、是否有下一页、精确总量标记和截断状态。保留现有缓存数量上限，并清理已失效会话的页数据。
- 当前页成功后立即结束其加载状态，再后台顺序请求后续五页。聚合来源沿用同一个 session，单来源按对应页的 offset 查询。
- 点击已缓存页直接应用缓存；若目标页正在预加载，复用该请求。用户请求优先于尚未派发的后台请求，同一会话保持一条执行链。
- 切页后调整预加载窗口，补齐当前页之后五页，跳过已缓存或在途的页面。
- 遇到已知末页、`hasMore: false`、截断或请求未推进页码时停止本轮预加载，避免越界和空转。
- 预加载失败不覆盖当前列表、不触发全屏加载、不将当前页变成错误页；停止本轮后续派发，用户实际取页时保留正常错误和重试行为。
- 刷新、条件变化、目标实例变化或组件卸载时作废旧代次，停止派发其后续请求。已发出的 IPC 可能继续在后端执行，其结果不得写入新条件缓存或覆盖当前页面。
- 后台发现聚合会话过期时停止预加载；用户下一次实际取页按既有规则重建会话，不保留旧会话混合数据。
- 覆盖 Mod、资源包、光影、数据包、整合包及世界资源搜索；复用原搜索接口，不新增启动时的全分类网络扫描。

预加载用于减少后续翻页等待。首次搜索仍需网络返回；不会等待五页全部完成才显示当前页。

### 3. 调试工具停靠与模态层级

- 在普通页面区和 `FullscreenModal` 的可聚焦 wrapper 内提供明确的调试工具停靠位置，将收起条初始位置设为区域左上角；停靠位置不随列表滚动。
- 停靠条与可拖动面板分开计算位置。收起条与展开面板分别保存本会话拖动位置，展开面板另行保存尺寸，并在当前区域和窗口尺寸变化时收敛到可见范围。
- 工具保持悬浮覆盖，不增加占位高度或改变页面内容尺寸；左上角仅作为默认位置。
- 当前全屏弹窗是唯一可交互模态项时，将同一工具组件挂到该弹窗 wrapper 内，覆盖其内容而不受背景页面的 inert/退场样式影响。
- 全屏弹窗内部的工具控件自然参与现有 Tab 焦点循环。工具自身处理 Esc 收起，弹窗内容的 Esc 继续按现有规则关闭对应弹窗。
- 普通确认弹窗、错误弹窗、协议或其他阻断项覆盖全屏弹窗时，工具暂时隐藏并停止拖动手势，保留展开状态；覆盖层关闭后恢复到当前有效区域。
- 全屏弹窗切换和退场时按全局模态栈的实际交互状态转移工具，防止挂到已关闭节点、露出后台工具或抢占新弹窗焦点。
- 沿用现有调试开关、默认收起行为、设置入口和面板内容，不增加第二个调试面板实例。

## 影响与注意点

后台预加载会增加实际使用分类的网络请求和缓存占用，按五页窗口、顺序执行和现有缓存上限约束。预加载中的单次后端请求仍可能等待网络，用户取页优先级只能影响尚未派发的请求。

调试工具不占页面布局空间；全屏区域与焦点调整需要回归其他全屏页面和普通子弹窗。

## 收起条拖动回归修正

用户反馈收起后无法拖动。原实现将左上角默认位置解释为固定停靠，并在收起状态阻止拖动，改变了既有交互。现按反馈恢复：

- 移除收起状态的拖动禁用条件；按钮区域仍不启动拖动。
- 收起条采用相对当前宿主的独立坐标，初始位置为左上角；展开和收起分别保留各自位置。
- 页面与全屏宿主切换、窗口缩小时，将收起条限制在当前可见区域内。
- 普通弹窗阻断、拖动手势清理与焦点恢复保持既有规则。

此前报告的新增文件不在 TypeScript 项目清单内的问题，已在原始本地仓库核验：独立 `pnpm typecheck` 通过，运行中的 vue-tsc 与 ESLint 检查器均报告零诊断；`tsconfig.app.json` 已覆盖新增文件，无需修改 include。刷新了检查配置的时间戳，文件内容未改变。

回归验证：前端 `pnpm check` 通过，825 项测试通过、1 项 todo；`pnpm build` 通过，主仓库集成测试 146 项通过。实际 Windows 启动器验证收起条拖动 80×40px、展开面板独立拖动、再次收起恢复原位置；全屏区域继续拖动后，关闭全屏保留相对位置。普通子弹窗仍隐藏工具并暂停交互。修正分别提交并同步原始本地 main，未推送；验收资料归档于 `debug-minimized-drag-20261011/playwright`。
