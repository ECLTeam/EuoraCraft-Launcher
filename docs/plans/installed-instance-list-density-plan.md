# 实例列表紧凑双行实施方案

状态：用户已确认方案 A，已完成实施、验证和日常使用目录同步。

## 目标与现状

上一轮已完成列表的信息层级与操作收纳。用户反馈列表偏大，本次将密度调整为紧凑双行，保留当前名称、版本信息、分类标签和操作入口。

当前行最小高度为 68px，图标为 38px，上下内边距各 12px，名称与版本间距为 4px。内容区宽度不超过 600px 时，分类与标签被移到第三行；标签区域还允许换行，进一步增加行高。

本轮可选方案：

| 方案 | 设计 | 取舍 |
| --- | --- | --- |
| A（已选择） | 52px 紧凑双行，缩小图标与留白 | 保留信息层级和字号，长辅助信息通过省略和悬停提示展示 |
| B | 44px 单行，名称和版本横向排列 | 更密集，但长名称更容易截断 |

## 具体设计

1. **行高**：常规与窄窗口均以 52px 为目标。六行由约 408px 收紧到约 312px，减少约 96px。通过内容与内边距共同控制高度，不用裁切整行的方式隐藏控件。
2. **图标与间距**：图标由 38px 缩至 32px；上下内边距由 12px 缩至 7px，左右由 16px 缩至 12px；列间距由 14px 缩至 12px。名称与辅助信息间距由 4px 缩至 2px。
3. **文字**：名称继续使用 13px、18px 行高；版本与加载器继续使用 11px、16px 行高。保留长文字省略、完整名称/实例 ID 与版本信息提示，避免通过缩小文字降低可读性。
4. **分类与标签**：与名称区、操作区并列，不再移到第三行。标签区域采用单行布局，长标签省略；保留最多两个标签、剩余数量提示及完整分类/标签悬停内容。窄内容区减少标签列宽，优先保证名称和操作空间。
5. **操作**：继续保留启动、详情、更多。启动按钮局部高度收紧至约 28px；沿用全局按钮颜色、圆角、悬停与焦点样式。收藏、置顶、隐藏、删除等入口及确认流程保持当前行为。
6. **响应式与主题**：在应用原有最小尺寸 820×600、常用 960×600 和更宽窗口验证；窄内容区仅收紧列宽，不增加第三行。继续使用全局主题与动画变量。

- 在 820×600、960×600、1440×900 下，默认字号的列表行约为 52px；分类、多标签不产生第三行，右侧按钮不越出可见范围。
- 验证长名称、长加载器版本、长标签与剩余数量，省略处能够通过提示查看完整内容。
- 验证浅色、深色、自定义背景和英文按钮文案，保持文字可读、按钮可辨识与选中状态清晰。
- 列表选择、启动事件、详情、更多菜单、收藏/置顶状态、搜索筛选及卡片切换继续通过现有测试；实际桌面检查详情、菜单与删除取消路径。
- 隔离测试使用最小实例 JSON 文件，不将界面验证描述为真实 Minecraft 游戏启动成功。

## 风险与处理

- 单行标签区域更紧凑：长标签省略、保留完整悬停提示，数量提示不被挤掉。
- 字体或主题自定义可能改变内容尺寸：以默认字号验证 52px；额外字体高度优先保证控件完整，不通过整行溢出裁切强制固定高度。
- 日常目录可能仍加载旧构建：交付时同步、重建并检查本地开发服务与实际桌面页面。
