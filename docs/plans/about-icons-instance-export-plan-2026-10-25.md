## 4. 全屏导出页

### 4.1 入口、层级与布局

- 使用新的 `InstanceExportModal.vue`，复用 FullscreenModal。入口文字及全屏标题均为“导出”，在内容中明确显示源实例。
- 从现有 `export` 动作统一打开，捕获游戏根目录、实例 ID 和展示名称；打开后不跟随后台选中实例变化。
- 从实例详情进入时展示当前导出页，关闭后恢复原详情及页签；不让两个全屏页面同时显示，不修改公共弹窗栈行为。
- 页面上方为实例信息、名称、版本、简介及资源处理方式，中部为分类操作和文件树，底部为已选统计与导出按钮。
- 使用现有主题和公共间距。主要内容区撑满可用高度，文件树是明确的滚动区域；底部操作保持可达，不使用固定整页像素高度。
- 文件树支持展开、目录半选、逐文件勾选、路径搜索、全选可选项、取消选择和恢复推荐选择。搜索仅过滤展示，不重置已选项；“全选”作用于全部可选内容，使用明确名称，避免只选择搜索结果的歧义。
- 使用虚拟列表或现有树的虚拟化能力处理较多文件，文件与目录以稳定业务 ID 为 key。长路径可查看全文。

### 4.2 整合包信息

- 名称默认使用实例展示名称，版本默认 `1.0.0`，简介可选；名称和版本去除首尾空白后不得为空，并设置合理长度上限。
- Minecraft 与加载器依赖从实例启动元数据解析，仅展示，不允许在导出页任意改成另一版本。
- 输出清单的 `name`、字符串 `versionId`、`summary` 使用用户确认的信息，依赖使用后端解析结果；移除当前硬编码名称、整数版本值及固定简介。
- 生成安全的建议保存文件名，复用现有 `select_save_file` 的默认名称能力与 `.mrpack` 用途；取消保存对话框不创建任务。

### 4.3 文件类别及默认选择

| 类别 | 默认与说明 |
| --- | --- |
| 已启用模组 | 默认选中，支持逐文件取消；取消模组可能使整合包不完整，说明常驻可见。 |
| 模组配置、默认配置及整合包脚本 | 推荐选中常用 `config`、`defaultconfigs`、`kubejs`、`scripts` 等内容；已知账户/凭据子目录始终排除，不因勾选上层目录绕过。 |
| 游戏设置 | `options.txt` 等基础设置默认选中。 |
| 资源包、光影及适用的游戏资源 | 默认选中，允许查看和选择具体文件；只显示实际存在的内容。 |
| 禁用模组 | 默认不选，可显式选择；不参与已启用模组的在线来源反查。 |
| 存档、截图、服务器列表 | 默认不选，可显式选择；选中后始终显示包含个人游戏数据的提示，不放入折叠帮助。 |
| 其他可导出的游戏文件 | 默认不选，由用户查看后选择；不把任意未知文件自动视为整合包必需内容。 |
| 日志、崩溃报告、缓存、账户凭据、启动器配置、其他实例及运行依赖 | 不作为可选导出内容，不由全选或自定义相对路径绕过。 |

类别规则归入后端现有导出领域的策略类型，明确目录和文件匹配，前端不复制一套打包规则。可见条目只代表允许导出的文件；被排除项目以分类说明或有界摘要告知，不向界面泄露敏感文件内容。

### 4.4 资源处理方式

1. **优先引用在线来源（默认）**：只对已选中的启用模组复用现有 Modrinth、CurseForge 反查；命中且满足现有下载地址契约的文件写入清单，避免同时进入 overrides。未识别的模组与其他已选内容直接打包。
2. **直接打包**：所有已选内容进入 overrides，不请求在线来源反查；清单依然保留整合包元信息和游戏依赖。

常驻短说明在线方式仍需在导入时下载、未识别文件会直接打包，以及直接打包通常更大。反查失败沿用明确的警告与直接打包结果，不把失败说成反查成功；结果页显示实际引用数、打包数及警告。

## 5. 后端扫描与导出选择契约

### 5.1 扫描来源

- 调用 `resolve_version_isolation` 取得实例最终隔离状态，再调用既有实例目标解析，明确区分版本元数据目录与实际游戏数据目录。解决 Issue #64 的同一来源问题。
- 从版本目录读取游戏/加载器元数据；可选游戏文件来自实际数据目录。共享模式下必须在递归前识别并排除兄弟实例目录，不能把整个共享 `versions` 当成一棵无条件可导出的目录树。
- 不搬迁、删除、改写公共目录或实例文件，不假定用户应把共享内容转为隔离内容后才能导出。
- 递归前跳过运行依赖、缓存和禁止目录；不跟随符号链接、Windows 重解析目录或越界路径。文件计数、深度与请求数组有界，超限明确失败，禁止静默截断后显示为完整清单。首版清单及选择上限统一为 50,000 个文件，错误提示建议缩小内容范围。
- 读取失败保留原因并允许重试；文件扫描在现有后台操作机制中执行，可请求取消，不阻塞 IPC 事件循环。

### 5.2 预览与选择一致性

新增 `game_instance_export_preview`，输入为现有实例目标，返回扫描操作句柄。扫描完成结果经运行时校验后包含：

- 实例身份及有效隔离模式、Minecraft/加载器信息。
- `sourceRevision`：用于判断来源目录、实例元数据与隔离状态是否仍与预览一致。
- 文件条目：服务器生成的 `fileId`、归档相对路径、分类、原始大小及推荐勾选状态。
- 排除说明与扫描结果摘要。

`fileId` 根据规范化来源身份、相对路径及文件大小/修改时间形成，不把绝对路径作为前端可修改的导出参数。后端最终导出重新解析来源并枚举允许文件，将提交 ID 与当前候选清单匹配；选中文件变化、消失、越界或来源变更时明确要求刷新预览。

本方案不创建另一套长期私有快照注册表。预览结果由现有操作结果保存，前端只维护选择 ID 和表单；导出时重新扫描并校验，避免新增预览会话的释放、过期及持久化负担。未选文件的内容变化不需要伪装为所选文件变化；不能在重新枚举时自动把新文件加入已确认选择。

### 5.3 导出请求与结果

扩展现有 `game_instance_export`，保留当前唯一格式 `pack_format = modrinth`，同步更新所有生产和消费方：

- 现有实例目标与 `output_path`。
- `source_revision` 与有界 `selected_file_ids`。
- `pack_name`、`pack_version`、`summary`。
- `resource_mode = references | bundled`。

新字段按当前契约使用，不保留旧请求的隐式全量导出路径或双格式兼容入口。前后端类型、运行时校验、演示 Transport、日志策略、测试及文档同时更新。

导出只处理后端重新验证的已选文件。空文件选择允许导出仅含依赖的基础整合包，按钮旁明确显示“未选择附加文件”；未扫描成功、字段无效或正在提交时禁止提交。

执行中使用唯一临时文件，成功后原子替换输出；失败或取消保留已有目标，清理仅限本任务临时文件。拒绝输出覆盖已选源文件，禁止把输出及本次临时文件递归打进自身；同一输出目标正在导出时拒绝重复任务，避免任务间覆盖。

结果至少包含输出位置、实际格式、引用与直接打包数量、警告；任务提交、完成、失败和实际取消分别展示。提交成功只提示“导出任务已创建”，不能立即提示“导出完成”。

## 6. 状态与资源归属

- 新建实例导出 store，由 `ManageTab` 的现有动作入口打开；窗口不直接拼装 Transport 调用，使用领域 API。
- 状态覆盖扫描中、可设置、扫描失败、提交中、导出中及结果。扫描失败提供重试，重新打开或换实例使旧响应失效。
- 扫描属于导出页的准备工作，关闭时请求取消并解除页面订阅；取消请求不等于扫描已停止。
- 导出任务提交后属于应用级长任务，由现有 applicationOperationStore 和任务队列继续跟踪。关闭页面不隐式终止导出；用户需要时通过明确取消入口申请取消。
- 保存对话框及提交期间使用共享执行锁阻止重复操作。迟到的保存路径不得提交到已关闭或切换目标的新流程。
- 导出页面可重新打开查看已提交操作状态，不复制一套任务状态或以轮询失败推断任务失败。
- 全屏层级、焦点、Esc、关闭和原详情恢复沿用既有机制；不通过 DOM 遮盖或强行清空全局弹窗栈实现页面切换。
