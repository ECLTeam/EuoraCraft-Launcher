# 实例设置、模组列表与 Java 选择整理实施方案

日期：2026-10-24（Asia/Shanghai）。

状态：用户已明确修改范围，并补充继承规则为「保持空的或者与全局设置一样的按钮配置」。本文供审阅，尚未批准功能实施。

## 1. 用户目标与当前实现

本次处理三组需求：

1. 实例详情的设置页取消每项「全局/自定义」选择，直接使用输入框、开关和正常业务选项；输入留空或操作值与全局相同时跟随全局，修改为不同值时成为实例自定义。
2. 「模组管理」改为「模组」，列表采用与其他资源页面一致的紧凑样式；「添加模组」使用加号图标；实例快捷方式移到总览。
3. 全局设置的游戏设置页仅从 Java 管理清单中选择可用 Java，移除本页的 Java 文件浏览入口；锁定内存移到内存卡片。

调查基线：主仓库本地 `main` 为 `0834546`，前端本地 `main` 为 `bce6dfb`。用户截图展示 Windows 下的 Fabric 实例模组页。

当前代码：

- `InstanceDetailSettingsTab.vue` 的 Java、内存、布尔选项及命令字段使用继承模式下拉框；窗口宽高已允许留空，启动参数是实例追加内容。设置按 300ms 防抖保存，并通过保存会话保持目标身份和请求顺序。
- 实例持久化使用现有 `VersionLaunchSettings` 和后端 `InstanceLaunchOverrides`。Java、内存采用模式与具体值组合，其他字段使用空值或覆盖标记区分继承；不能把界面展示的全局值直接全部写成实例覆盖。
- `InstanceDetailModsTab.vue` 将名称、原名、文件名、版本作者和诊断逐行堆叠；两个「添加模组」入口均使用搜索图标。相邻资源页使用两行主要信息、分隔线及较紧凑操作区。
- 「实例快捷方式」当前位于实例设置页，有 Windows 桌面创建和选择保存位置两个入口。
- `GameTab.vue` 和实例设置共用 `JavaRuntimeSelector.vue`。选择器含下拉框、浏览文件、刷新和管理入口；已配置但未出现在清单中的路径会被插回选项。
- Java 管理的权威清单已经维护启用状态和验证状态；`toJavaInstallations()` 已筛选已启用且验证有效的运行时。Java 管理页自身保留登记本地文件功能。
- 全局「锁定内存」目前位于启动高级设置中，而非内存卡片。

## 2. 方案取舍与边界

推荐沿用当前启动配置契约，在界面层明确区分「展示的有效值」与「要保存的实例覆盖」。现有格式足以表达本次控件整理，不新增字段别名、双格式读写或迁移逻辑。

另一种方式是重新设计全局与实例的完整持久化格式，使所有 Java、内存及命令字段使用完全相同的逐字段结构。这会扩大到启动解析、IPC、CLI、插件及数据处理，本次没有必要，暂不纳入。

模组列表推荐使用「两行主要信息 + 紧凑操作 + 诊断详情」；单纯压缩字体和内边距仍会留下多行堆叠，不能解决截图中的行高问题。详情入口必须可通过键盘访问，不能把兼容性风险完全藏到悬停内容里。

本次不改变游戏启动参数追加顺序、隔离策略、下载来源、模组文件启停规则、Java 安装登记能力或快捷方式后端接口；不整理已有历史兼容代码，不引入新的配置存储方案。

## 3. 实例设置的直接编辑与继承

### 3.1 统一交互

- 移除每项用于切换「继承/自定义」的选择器和依赖其启用状态的输入禁用逻辑。
- 输入框默认不填入全局文本或数值，使用占位或简短说明展示全局有效值；清空后恢复继承。不得将全局路径、参数或命令填进实例输入框再自动保存。
- 布尔项使用开关，展示「实例覆盖值，否则全局值」。用户操作后，与当时全局值相同则保存继承，不同则保存显式布尔覆盖。`false` 不能被当成未设置。
- 优先级、渲染后端、启动器退出行为等保留业务下拉框，删除其中「继承」选项；展示有效值，用户选择与全局相同时取消本项覆盖。
- 对命令类文本，空字符串或只有空白字符按用户确认的规则恢复继承；有实际内容时保留其内容和现有校验，不擅自修剪有效命令中的空格。
- 继承控件在全局设置变化时刷新展示或提示，不因读取全局值、打开页面或切换实例自动产生保存。
- 保留现有「恢复全局设置」作为一次性清除全部实例覆盖的操作；它不再承担逐项选择模式的职责，继续取消待提交的防抖保存。

直接后果：全局已经配置启动命令时，清空实例输入表示继续使用该全局命令，不表示禁用该命令。本次不新增另一个「显式空值覆盖」操作。

### 3.2 Java 与内存的组合语义

现有格式中 Java 的自动开关与手动路径、内存的自动开关与容量分别构成一组，按组合结果映射到现有 `inherit/auto/manual` 存储模式：

- 界面只显示「自动选择 Java」开关及手动选择器、「自动分配内存」开关及容量控件，不显示是否继承的第三种模式。
- 没有修改时继续保存继承标记；组合结果与全局相同则回到继承。不能仅因为自动开关相同，就清掉同组中仍不同于全局的 Java 路径或内存容量。
- 切到手动模式时，展示当前可使用的路径或容量作为选择依据；不得在用户没有确定有效 Java 时写入缺少路径的手动设置。
- 输入容量与全局一致且自动模式也一致时恢复继承；确实选择不同容量或路径时保存当前组合。读取全局状态不能把未修改的组变成固定快照。
- 数值留空保持继承语义，不通过滑块的默认展示值触发持久化；拖动滑块属于用户主动修改。
- 实例内的锁定内存开关归到内存子组，仍按布尔项规则继承。

这组映射放在现有实例设置领域代码中，用明确的读值、写值和比较函数表达，调用者为实例设置组件及其测试；不建立通用配置框架，不重复维护另一份可独立修改的有效设置。

### 3.3 参数与保存边界

JVM 参数和游戏参数目前是「全局参数 + 实例追加参数」，保持此顺序。输入框明确标注实例追加内容，留空表示不额外追加；全局参数通过说明查看，不复制到实例输入框，也不将本次改动解释为覆盖全局参数。

保存继续经过现有 `instanceSettingsApi` 和 `settingsSaveSession`：

- 仅用户修改的字段触发保存，序列化仍输出当前契约允许的模式、空值和覆盖标记。
- 命令清空时移除相应 `commandOverrides` 项；保留内部已有格式，但本页不生成新的显式空命令覆盖。
- 新旧实例切换、关闭弹窗、重置与保存失败沿用并验证现有排队及草稿保护，迟到响应不得覆盖当前实例。
- 校验失败保留输入和可恢复状态，不回写全局配置，不误报保存成功。

## 4. 模组页与实例快捷方式

### 4.1 模组列表

- 实例导航和相关实例菜单统一使用「模组」，六语言同步；不改在线资源的模组分类名称或删除管理能力。
- 工具栏和空状态的「添加模组」图标均改为现有 `plus` 图标，点击仍进入原有在线搜索安装流程。
- 模组行采用与资源页相同的主题变量、分隔线和悬停反馈，不给每一行增加卡片式边框或大留白。
- 常规信息压为两行：第一行显示名称及必要的加载器标识；第二行合并文件名、版本与作者。避免中文译名、原名、文件名分别占据独立行。
- 参考 56—64px 的常规行密度，最终以真实字体和内容为准；不使用固定高度裁切文字或操作。图标保持约 32px，启停、在线详情和删除操作保持紧凑且可达。
- 诊断以可见的短提示表达风险，详细约束和修复入口通过可访问的详情展开；长诊断不默认撑高所有行。保留启用依赖、搜索依赖等已有操作和原始约束信息。
- 名称、文件名及合并元信息需要截断时提供完整内容；最小窗口下不能通过隐藏溢出来丢失末项或操作区。
- 不修改共享 `ModDiagnostics` 对其他资源页面的行为；本页需要的紧凑展示限定在模组页及其局部样式内。

### 4.2 快捷方式

从实例设置移除快捷方式区域，在总览的快捷操作附近提供独立的「实例快捷方式」区域，保留「创建到桌面」和「选择位置」两个入口及 Windows 平台条件。

创建逻辑、目标身份和执行状态由总览所属的实例详情层管理。调用前固定实例路径和版本 ID，防止文件选择期间实例切换导致目标改变；重复操作只提交一次，取消选择不误报成功，失败后可重试。保留现有 `select_save_file` 和 `game_instance_shortcut_create` 契约，不增加新的文件写入接口。

## 5. 全局游戏设置与 Java 选择

- `GameTab.vue` 的锁定内存开关移入内存卡片，保留原来的配置键、说明和保存方式，不再出现在启动高级卡片。
- 共享 `JavaRuntimeSelector.vue` 的两个已确认调用者为全局游戏设置与实例设置；统一改为从 Java 管理清单选择，删除选择器内的文件浏览及直接登记流程。
- Java 管理页仍可登记本地 Java 文件；新增或安装 Java 的入口集中在那里。`settingsApi.selectJava()` 仍被 Java 管理页使用，因此本次不删除该接口。
- 可选项必须来自权威清单且已启用、验证有效；实例有 Java 版本要求时，结合现有选择校验及实例上下文确认可使用，不把 TypeScript 类型或仅版本号匹配当成可执行性验证。
- 用户选择通过现有 `javaApi.select` 验证后，再提交实际可执行路径；加载、验证失败、目标切换及重复选择使用已有请求作用域或修订号保护，旧响应不能写入新的实例。
- 保留刷新清单与进入 Java 管理的入口。无可用 Java 时说明下一步，不弹出任意文件选择器。
- 当前已配置路径不在可用清单时保留原配置并说明不可用，不自动清空、自动改选，也不将其作为普通可用项插回下拉列表；重新选择有效运行时后再替换。
