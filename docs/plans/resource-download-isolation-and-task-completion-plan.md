# 资源下载隔离与任务阶段结束实施方案

状态：用户已选择方案 B，待审阅本文并明确确认实施。

日期：2026-10-24。

## 1. 目标与验收结果

1. 下载页在线资源和安装 Fabric 时附带的 Fabric API，均按目标实例的有效隔离设置选择目录。
2. 隔离开启时，模组写入 `<游戏根目录>/versions/<实例名>/mods/`；关闭时沿用当前游戏启动与工作台使用的共享目录 `<游戏根目录>/versions/mods/`。
3. 主任务成功、失败或取消后，其活动子阶段同步结束；成功时不再残留“正在下载”，迟到的进度事件不能恢复转圈状态。
4. `download_files` 显示六语言对应的“下载文件”名称，不直接展示内部标识。

## 2. 已核实的问题

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| `ECL/api/mods.py` 的 `download_mod` | 调用 `install_online_resource` 时固定传入 `False` | 绕过实例独立设置及全局策略；同入口的模组、资源包、光影、数据包和在线世界均受影响。 |
| `ECL/game/Core/GetGames.py` 的 `build_fabric_download_list` | Fabric API 固定写入 `<游戏根目录>/mods/` | 与隔离实例目录不一致，也与当前关闭隔离时的游戏数据目录不一致。 |
| `frontend/src/app/runtime/useAppRuntime.ts` | 完成事件只更新主任务；仅在事件带 `subtask` 时更新子项 | 后端最终 `done` 事件不带 `subtask`，已有下载子项持续为 `running`，并保留旧消息。 |
| 同上，`getSubtaskLabel` | 缺少 `download_files` 映射 | 界面直接显示内部阶段标识。 |
| `frontend/src/composables/useTaskQueue.ts` | 主任务更新有终态保护，`addSubtask` 没有同等保护 | 晚到事件仍可能修改已结束任务的子阶段。 |

调研已通过提取现有函数执行的最小复现确认上述路径与完成状态问题；这不等于完整功能测试或真实启动器验收。

## 3. 已选方案与职责

用户选择方案 B：一起修复普通在线资源下载、Fabric API 下载目录、任务子阶段结束及阶段名称。

复用现有 `resolve_version_isolation` 和 `resolve_instance`，不增加独立的隔离策略、路径注册表或兼容适配层。有效隔离规则继续以现有实例设置和全局策略解析结果为准；全局“全部隔离”不会覆盖用户对单个实例显式设置的关闭状态。

Fabric API 的来源查询已归主仓库安装服务负责，其目标目录也由该服务决定。Core 只构建 Minecraft 与 Fabric Loader 所需的文件清单。

## 4. 具体改动

### 4.1 在线资源下载

- 在 `ECL/api/mods.py` 中校验目标实例字段，复用现有实例目标模型及路径校验，移除写死的关闭隔离参数。
- 在 `ECL/services/game/resources.py` 的在线安装入口支持省略隔离覆盖；省略时通过 `resolve_version_isolation` 读取目标实例的有效设置，保留受控调用明确传入布尔值的现有语义。
- 每次安装开始时解析一次有效隔离状态，后续资源目录、世界目录和文件提交使用同一结果；不让下载途中的设置变化切换写入目录。
- `download_mod` 的 `modsPath` 返回目标实例有效隔离状态下的模组目录，不再调用仅处理游戏根目录的 `mods_path`。请求及响应字段保持现有契约，不增加历史别名。
- Modrinth 和 CurseForge 共用相同目标解析；“另存为”继续使用用户明确选择的路径。
- 保留现有临时下载、校验与原子替换流程，目录解析失败时明确报错，不退回共享目录。

### 4.2 Fabric API

- 在 `ECL/game/Core/GetGames.py` 删除 `build_fabric_download_list` 的 Fabric API 附加参数和固定根目录 `mods` 写入逻辑，更新文档说明。
- 在 `ECL/services/game/install.py` 先调用 Core 生成 Minecraft/Fabric 清单及版本元数据，再按保存名称解析有效隔离状态，将 Fabric API 条目追加到该实例实际使用的模组目录。
- 元数据生成后再判断隔离，覆盖全局“仅模组实例隔离”策略对新建 Fabric 实例的判断。
- 文件名使用已有安全文件路径校验，防止远端文件名越过目标模组目录。
- 同步更新当前调用方和测试替身；已检索到生产调用位于 `install.py`，整合包测试 `tests/test_modpack.py` 也声明了旧签名。
- 整合包导入仍传入 `include_fabric_api=False`，不额外下载 Fabric API，不与包内文件重复。
- Fabric API 与其他文件共用原下载任务、统计及失败处理，不改变下载器并发、重试机制。

### 4.3 主任务与子阶段

- 在 `frontend/src/composables/useTaskQueue.ts` 集中处理任务终态：成功时将活动子阶段标记为完成，替换旧的进行中文案；失败时将活动子阶段标记为失败并显示失败原因；取消时标记为取消。
- 已完成的历史子阶段保持原有结果；终态处理不将失败或取消伪装成成功。
- 为子阶段补充与主任务一致的取消状态，并在 `TaskQueuePanel.vue` 中提供对应的静止图标与显示处理，沿用现有主题样式。
- 主任务结束时将下载速度清零；主任务和子阶段均拒绝迟到的进行中更新，包括重复结束事件之后到达的旧回调。
- `useAppRuntime.ts` 继续使用后端 `done` / `error` 确认结果，最终事件无需重复携带所有子阶段；已知取消错误按现有错误码区分取消结果。
- 补齐 `download_files` 的国际化映射和六份语言文件的 `task.subtask.downloadFiles`。终态新增的用户文案同样使用六语言键。
- 不在文件数或字节数达到 100% 时提前报告成功；下载结束后的校验、提交或失败仍以实际执行结果为准。

## 5. 范围与数据保护

- 不扫描、迁移、删除或覆盖已经落入公共目录的模组、资源包、存档和用户文件；本次修复影响后续下载目标。
- 不修改全局隔离偏好、现有实例独立设置或历史数据格式。
- 不重写 Minecraft 共享库和 assets 的存储规则；它们不属于实例模组目录。
- 不引入新的重试、旧接口转发、双格式读取或自动迁移代码。
- 不扩展到无关页面、插件下载、Java 下载或下载器线程重构。

## 6. 回归测试

### 后端与 Core

1. 在线下载：全局全部隔离、关闭隔离、仅模组实例隔离；实例开启、关闭及继承分别落到正确目录。
2. 校验下载页请求经过实际 IPC 和服务组合，而非只断言 mock 参数；分别检查目标文件存在及错误目录未创建文件。
3. 模组、资源包和光影覆盖共同资源目录分支；数据包与在线世界覆盖各自的世界目录分支。Modrinth 与 CurseForge 的来源不改变目标隔离。
4. 非法实例名称与路径越界在写入前失败；校验失败或下载失败不产生成功结果，保留原文件及原子提交语义。
5. Fabric API：隔离开启、关闭、仅模组实例隔离，以及实例独立覆盖；使用实际 Core 清单与安装服务组合，外部网络使用固定响应。
6. 整合包导入：`include_fabric_api=False` 不解析、不追加额外 Fabric API，包内模组安装行为保持正常。
7. 备用源流程不把 Fabric API 的目标重新写回根目录，不重复下载已成功文件。
8. 路径规则使用平台无关方式实现；覆盖 Windows 与 POSIX 路径处理分支，报告本机真实执行平台与模拟覆盖的区别。

测试主要落在 `tests/test_frontend_api_config.py` 或新增专门 IPC 集成测试、`tests/test_game_service.py`、`tests/test_mcmod.py`、`tests/test_modpack.py`、`tests/test_download_sources.py`，以及 Core 的新增 Fabric 清单测试中。每个缺陷先补充可在原实现失败的回归用例。

### 前端

1. 重放“download + download_files → done（不带 subtask）”，验证主任务和子阶段均完成，旧下载文案消失。
2. 失败、取消、无下载文件、重复终态及多个子阶段；已完成阶段不被失败或取消结果改写。
3. 主任务结束后收到迟到的下载事件或子阶段事件，保持终态和最终文案，速度为零。
4. 通过实际运行时事件订阅入口验证事件到队列的集成，避免只测提取函数；补充 `useAppRuntime` 相关测试。
5. 在 `useTaskQueue.test.ts` 和 `TaskQueuePanel.test.ts` 验证终态处理及面板显示；在线安装相关测试确认 IPC 参数保持正确。
6. 六语言键一致，下载阶段不显示 `download_files`；终态不保留进行中动画。
