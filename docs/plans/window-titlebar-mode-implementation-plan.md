# 主窗口标题栏模式设置实施方案

> 已确认并实施：仅主窗口，保存后重启生效。

## 目标与范围

- 在“设置 → 外观 → 布局”增加“窗口标题栏”选项，允许选择“自绘”或“系统原生”。
- 默认保持现有自绘模式；已有配置缺少此字段或字段无效时也回退到自绘模式。
- 选择后保存到 `setting.json`，**下次启动**生效；当前运行的窗口不临时改变边框或布局。
- 本方案先控制主窗口。插件窗口及其他受控子窗口继续使用现有自绘窗口，除非用户明确要求统一切换。

## 现状与影响

- `ECL/adapters/tauri.py` 创建主窗口时固定 `decorations=False`、`transparent=True`、`shadow=False`。
- `ECL/api/windows.py` 创建子窗口时也固定 `decorations=False`，且子窗口有独立的前端壳。
- `frontend/src/App.vue` 总是渲染 `TitleBar`。它既负责拖动、最小化、关闭，也承载顶部导航、任务入口、主题切换和插件插槽。
- `frontend/src/views/settings/AppearanceTab.vue` 的“横向标题栏”开关实际切换侧边导航与顶部导航，不控制原生窗口装饰。
- UI 配置经 `ConfigStore` 持久化；启动时 `ApplicationState.config` 在创建 Tauri 窗口前读入。前端现有 `settingsStore.patchUiTheme()` 可串行合并保存外观字段。

## 方案比较

| 方案 | 行为 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 保存后重启生效（推荐，用户已选择） | 新配置在下一次创建主窗口时应用 | 与窗口创建参数一致，跨平台布局更稳定；无需新增运行时窗口控制权限 | 用户需要重启启动器 |
| B. 立即生效 | 调用 Tauri `setDecorations()` 等接口并立即重排前端 | 无需重启 | 需要新增 capability 权限、处理切换失败回滚、窗口透明度和阴影差异；平台验证范围更大 |
| C. 所有窗口统一切换 | 主窗口与子窗口都读取同一选项 | 视觉风格一致 | 需同步改造插件窗口壳及创建时机，影响插件窗口和主题编辑窗口，验收范围明显增加 |

## 拟实施步骤（方案 A）

1. **定义配置**：在 `ui.theme` 增加 `window_chrome: "custom" | "native"`，默认 `custom`；后端在读取窗口参数前校验允许值，无效值回退 `custom`。前端增加对应类型与中英文文案。
2. **主窗口创建**：在 `Adapter._build_config()` 按配置设置 `decorations`。自绘模式保留当前透明、无原生阴影参数；原生模式使用非透明窗口和系统装饰，并检查原生阴影及最小尺寸在 Windows、macOS、Linux 的实际表现。
3. **设置页**：在布局分区添加双选项控件，使用现有串行配置写入流程保存。说明“重启启动器后生效”，保存失败时保持旧值并显示错误。
4. **前端布局**：启动时读取**当前窗口实际**是否带系统装饰，和用户刚保存的“下次启动模式”分开。原生模式下系统标题栏承担拖动、最小化、关闭；应用内顶部区域继续承载顶部导航、任务、主题和插件入口，但去掉重复的窗口按钮、拖动行为及冗余品牌展示。自绘模式保持现状。
5. **边缘样式**：原生模式下取消仅适用于无边框窗口的 `#app` 裁剪与圆角；检查弹窗、任务提示、全屏弹窗和两种导航布局的位置，避免内容被原生标题栏遮挡。
6. **测试**：新增后端测试，覆盖默认/自绘/原生/非法值的主窗口配置；新增前端设置持久化和标题栏条件渲染测试。执行 `ruff check ECL tests`、`ruff format --check ECL tests`、相关 `pytest`、`frontend` 的 `pnpm check` 和 `pnpm build`。随后实际启动启动器，验证两种模式、切换后重启、窗口按钮、拖动与缩放、顶部/侧边导航、弹窗及子窗口。
7. **提交**：通过测试后，按仓库要求分别提交前端子模块和主仓库相关改动；只纳入本功能文件，保留现有未提交或未同步的子模块状态，不推送远端。

## 验收标准

- 旧配置继续显示自绘标题栏，窗口行为与现在一致。
- 选择系统原生并重启后，只出现一套系统窗口控制按钮；导航、任务、主题和插件入口仍可用。
- 切回自绘并重启后，自绘拖动和窗口控制恢复。
- 保存后未重启期间，界面与当前窗口装饰保持一致，并清楚提示待重启生效。
- 浏览器展示模式和插件子窗口不因主窗口选项出现不可用的窗口控制。

## 验证记录

- Windows 下使用隔离配置分别启动自绘与系统原生模式；两次均完成前端就绪并正常退出，Tauri `isDecorated()` 分别返回未装饰和已装饰。
- 后端配置测试覆盖默认值、两种有效模式及非法值回退；前端测试覆盖设置持久化失败回滚和当前窗口状态检测。
- 当前环境为 Windows。macOS 与 Linux 的实际窗口外观仍需在对应平台检查；实现没有新增平台分支。
