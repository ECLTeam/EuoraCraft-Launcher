# 公共基础组件视觉与交互修复

用户已在基础组件审查后明确要求“修了吧”，本次按已列出的六项问题实施。基线为主仓库 `961bb13`、前端 `cbaf2d1`。

## 1. 范围与具体处理

| 问题 | 实施方式 |
| --- | --- |
| 控件尺寸不一致 | 普通控件使用 36px / 14px，小号使用 32px / 13px，大号使用 40px / 14px。按钮、输入框、选择框使用同一组主题高度变量；工具栏可以显式选小号，保留现有页面有明确依据的局部尺寸。 |
| 下拉框外观和键盘操作不完整 | `UiSelect` 的两个调用方是游戏下载分类和联机运行实例选择，没有使用插槽。复用项目已有 `NSelect`，使用向下箭头、统一高度及焦点样式。保留当前调用的 modelValue、options、placeholder、disabled 与选择事件；选项描述继续显示。删除没有调用方的插槽及手写菜单定位、外部点击、滚动监听和搜索实现。 |
| 卡片圆角不响应设置 | `UiCard` 使用 `--ecl-radius-card`，控件继续使用 `--ecl-radius-control`，验证两项分别变化。 |
| 只读与禁用混淆 | 只读输入保持完整文字对比度和文本光标，可聚焦复制；禁用继续弱化。只读或禁用时不显示可执行的清空按钮。清空的可访问名称同步六种语言。 |
| 标签和空状态文字过小 | 标签 tiny / small / medium 分别为 10 / 11 / 12px；空状态标题 13px 并增加字重，说明 12px 使用次要文字色。保留主题色和状态语义。 |
| 滑块缺少选区和焦点反馈 | 原生 range 保留键盘行为，通过当前值、min、max 计算百分比，绘制已选轨道；提供可见焦点并覆盖 WebKit / Firefox。调用方提供实际可访问名称。 |

下拉框可以选择继续维护自定义菜单或复用 `NSelect`。本次选择后者：项目已经依赖该组件，可统一交互并减少当前两处调用方背后的手写逻辑。`UiSelect` 仍负责当前页面使用的简单选项模型和事件，不引入新组件库或历史接口兼容。

不扩展为整站重设计，沿用 Classic / Folia 主题和现有颜色、间距体系。

## 2. 实施文件与步骤

1. 调整 `components/ui` 下 Button、Input、Select、Card、Tag、EmptyState、Slider 及对应样式。
2. 在 `styles/tokens.css` 定义共同尺寸，调整 `useTheme.ts` 中对应 Naive UI 尺寸；清理被替换选择框的专属样式。
3. 更新实际调用方中依赖旧内部类的局部样式、需要紧凑尺寸的分类选择框，以及滑块可访问名称。只处理此次组件变动直接影响的页面。
4. 为选择、禁用、只读清空和滑块值范围补充行为回归；在真实浏览器测量尺寸、圆角、文字状态和轨道样式。
5. 按顺序通过 `pnpm check`、`pnpm build`，实际启动 Windows 启动器验收。完成后提交前端及主仓库指针，先集成前端本地 main，再集成主仓库本地 main，保留无关工作。
