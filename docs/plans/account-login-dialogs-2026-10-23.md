# 添加账户的登录方式选择与独立弹窗

## 已确认目标

用户于 2026-10-23 确认开始实施：添加账户首先展示竖向排列的长按钮，点击后打开对应的独立登录弹窗。选择页移除原有登录按钮及表单。

## 改动范围

- `frontend/src/views/Game.vue`：账户管理页接入账户添加弹窗。
- `frontend/src/features/accounts/components/AddAccountModal.vue`：集中管理选择、表单与授权弹窗的显示和返回。该组件的当前调用方为游戏首页的账户管理弹窗，继续使用原有账户服务与公共弹窗组件。
- 微软账户直接调用现有登录流程，使用已有授权弹窗；保留配置缺失提示、准备状态和失败后的重试入口。
- 离线账户、Authlib 及已注册的插件登录提供方使用独立表单弹窗；关闭后恢复选择列表及触发按钮焦点。
- Authlib 多角色选择仍在对应表单弹窗中进行，角色确认前不关闭。提交期间阻止重复操作并限制关闭。
- 选择按钮复用 Naive UI、主题变量及既有六语言文案，删除旧横向切换控件专属样式。
- 后端认证、账户持久化与 IPC 契约沿用现状，无数据迁移。

## 实施步骤

1. 将现有账户添加表单及其弹窗交互归入账户添加组件。
2. 用竖向、全宽的长按钮替换横向切换控件，连接对应弹窗入口。
3. 处理成功关闭、取消返回、失败重试与重复提交限制。
4. 补充真实公共弹窗组件下的交互测试。
5. 完成前端检查、构建、浏览器布局及 Windows 启动器验收；执行相关主仓库账户集成测试。
6. 分别提交前端与主仓库指针，完成本地 main 集成，保留既有无关改动。

## 验收计划

- 选择页仅含各登录入口及必要提示，不出现登录表单或额外登录按钮。
- 微软点击直接启动；准备期间重复点击只提交一次，取消和失败后保留入口，保存成功后收起选择页。
- 离线与 Authlib 使用不同于选择页的弹窗；Esc、关闭按钮及焦点恢复正确。
- 表单失败保留草稿并允许重试；Authlib 待选角色不影响其他登录方式。
- 执行 `pnpm check`，通过后执行 `pnpm build`；在 Classic / Folia、亮暗主题及背景、透明度、模糊设置下检查。
- 真实布局覆盖 960×600、默认及放大窗口，检查按钮宽度、长译文、内容滚动及表单末项可达性。
- 使用临时启动器数据目录和独立 WebView 配置验证 Windows Tauri/WebView2 实际界面；原生验收只打开和关闭表单，不提交账户或进行微软认证。成功添加流程在隔离演示数据中验证。
