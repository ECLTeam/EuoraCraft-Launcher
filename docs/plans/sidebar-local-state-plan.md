# 侧栏折叠状态前端本地保存实施方案（A）

状态：实施、完整工程检查和 Windows 桌面验收已完成；提交与本地集成记录见第 9 节。用户要求不编写本项旧配置兼容代码，以下以最终实现为准。

日期：2026-10-04（Asia/Shanghai）。

## 1. 目标与范围

侧栏折叠状态保存到前端 `localStorage`，折叠与展开立即生效、重启后恢复，不再因为侧栏切换读取和保存整个 UI 配置。继续通知前后端插件，普通通知使用 DEBUG 日志，失败继续可见。

本次选择对应此前的“A：前端本地保存”，集中处理侧栏。其他已发现的问题保留在第 8 节，分别确认后实施。

验收标准：

- 单次侧栏切换不调用 `settings_get/set`，不修改 `setting.json`，不触发 `config:updated` 及其后续设置重读。
- 同一运行环境重启后恢复最后一次折叠状态；无已有状态时默认折叠。
- 不迁移旧 `ui.theme.sidebar_collapsed`；只读取本地值，无有效本地值则默认折叠。
- 后续主题配置刷新和用户修改其他设置不会把侧栏恢复为旧配置值。
- 插件收到真实的初始化状态和后续变更；普通通知不产生 INFO 日志，失败仍有 WARNING 或现有异常日志。

## 2. 已核实的基线与触发链

主仓库基线：`0ef6e2b45d4d40fbd45b0d5cc690b9e5285d1c2a`。

主仓库记录的前端指针：`acce1363ddfcd5116bf42cc49e184f24eb6c3926`。本工作树子模块尚未展开，调研通过日常前端仓库的 Git 对象读取上述指定提交，没有用未提交源码替代基线。日常前端工作区存在 `src/views/connect/ConnectToolsTab.vue` 的无关修改，实施和集成时必须保留。

当前链路：

1. `useTheme.setSidebarCollapsed` 更新内存与样式，并调用 `saveThemeConfig`。
2. `SideBar.vue` 的立即执行 watcher 同步前端 SDK 状态，并调用 `plugin_notify_sidebar_state`；后端当前按 action 输出开始、完成两条 INFO。
3. 主题保存经过 100 毫秒防抖，先 `settingsApi.getUi()`，再把主题与背景一起通过 `settingsApi.saveUi()` 保存。
4. `ConfigStore.save_config` 原子写入 `setting.json`，输出 DEBUG 并广播 `config:updated`。
5. `useAppRuntime` 接到事件后调用 SettingsStore 的 `refreshAfterWrites`，重新读取设置并应用主题。

因此用户日志中一次侧栏操作出现通知、读取、保存、配置写入和再次读取，通常合计约 9 行。方案 A 切断侧栏与全局配置保存的关联。

## 3. 本地保存与初始化规则

### 3.1 存储格式

- 使用独立键 `euoracraft-sidebar-collapsed`，值只接受字符串 `true` 或 `false`。
- 在创建主题 Store 时读取有效本地值，尽早确定初始状态。不要把字符串 `false` 当作布尔真值。
- 不把侧栏状态塞入现有主题颜色快照，也不创建后端状态文件或新 IPC。
- 保留现有 `useTheme` 的 ref/setter 接口，所有侧栏入口继续访问同一份 Pinia 状态。

### 3.2 初始化

- 创建 Store 时读取本地键，合法值直接使用；无键、非法值或存储访问异常时默认折叠。
- 不读取旧配置字段、不做旧值迁移、不增加首次初始化或迁移会话标记。
- 所有后端主题初始化和刷新都不处理侧栏折叠状态，因此不会覆盖本地状态。
- `saveThemeConfig` 不再序列化侧栏状态；从主题类型、后端新配置默认值及 showcase fixture 中移除该字段。
- 不为清理用户已有配置文件发起额外保存，也不加入专门的旧字段清理程序。

### 3.3 用户切换和存储失败

- setter 先比较当前值，同值操作直接返回。
- 真正变化时更新内存、现有样式和本地值，去除侧栏 setter 对 `saveThemeConfig` 的调用。
- 本地写入是同步小值写入，不需要保存队列、防抖、确认按钮或成功状态提示。
- 捕获 `localStorage` 访问被拒绝或容量异常；保留本次内存状态，侧栏和插件照常使用，不回退为后端配置保存。
- 存储失败使用现有前端日志设施记录简短中文诊断，同一会话控制重复输出，不包含个人路径或完整配置；不增加常驻状态面板。
- 存储不可用时，本次内存状态仍然生效；后端主题刷新不涉及它。

### 3.4 生命周期边界

- 前端本地状态依赖 WebView 的存储环境；清理该环境后需要重新初始化。开发服务与正式包的来源不同，可能有各自的状态。
- 单独复制 `setting.json` 不会带上新的折叠状态；这是方案 A 的取舍。
- 延续项目现有本地界面缓存约定，不为本项增加独立设置入口或跨进程同步协议。

## 4. 插件通知与日志

- 保留 `SideBar.vue` 对前端插件 SDK 的 `setSidebarState` 及后端 `plugin_notify_sidebar_state` 通知。
- 保留初始化通知，并在真实折叠状态改变时发送通知。
- 后端插件管理器已有同值去重，继续沿用，不能删除初始化同步或插件就绪后的补发。
- IPC 策略仍把插件状态通知归为 action；为 `IpcLogSpec` 增加可选的普通生命周期日志级别（默认保持现状），只给该命令指定 DEBUG。统一 guard 读取该声明输出开始与成功日志。
- 请求失败仍按既有规则输出 WARNING；未预期异常继续使用原异常边界，不把通知伪装成日志通道以绕过失败记录。
- 其他业务操作和设置保存的日志级别保持现状。

完整 DEBUG 日志中仍会保留插件通知的两条诊断记录；本次减少的是设置读写产生的整串记录，并把侧栏通知从 INFO 移到 DEBUG。

## 7. 测试与桌面验收

### 行为回归

- 有效本地 true/false 都能恢复，后端配置不影响它。
- 本地值缺失或非法时默认折叠，即使已有旧配置值也不迁移。
- 初始化前用户手动切换、后续主题刷新、本地读写抛异常，都不能导致用户状态被配置覆盖。
- 多次切换及同值 setter 调用不触发设置读取/保存；同时修改其他主题选项仍能正常保存，且不持久化新的侧栏值。
- 插件得到初始状态和真实变更，侧栏通知的成功日志全部为 DEBUG，失败保留 WARNING，普通设置保存仍为 INFO。
- 不输出请求体、状态缓存内容、凭据或操作编号；现有正式 IPC 策略覆盖测试继续通过。

### 必须执行的工程检查

1. 在前端先执行与 CI 一致的 `pnpm check`。
2. 检查通过后执行 `pnpm build`。
3. 后端执行 `ruff check ECL tests`、`ruff format --check ECL tests`，以及操作日志、前端配置、插件侧栏事件与主仓库 IPC 集成相关 pytest 用例；实施时核对 CI 的附加要求。
4. 实际启动 Windows Tauri 启动器，使用独立测试数据目录和有效 IPC 验证，不以 showcase 或模拟响应替代桌面结果。
5. 连续切换侧栏，确认实际 `setting.json` 内容及修改时间不因切换而变化，日志不出现对应保存/重读链；退出后重启确认最后状态恢复。
6. 无本地键时确认默认折叠；改动其他外观设置后确认侧栏不回退；验证插件状态事件与 DEBUG/INFO 输出。

任何必要检查失败都不能把功能宣称为完成或提交功能 commit。平台无关逻辑通过测试校验；没有实际验证的平台明确说明。
