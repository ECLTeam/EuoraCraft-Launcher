## 1. 目标和已选方案

目标是让新增界面和后续修改持续服从 ECL 现有设计体系，把可可靠判断的规则接入自动检查，并明确仍需人工或真实界面验收的部分。

| 方案                   | 内容                                                                            | 取舍                                                  | 选择       |
| ---------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------- | ---------- |
| 规范＋新增改动自动检查 | 补齐权威文档、目录职责和组件契约；静态检查新增的样式违规，接入现有质量命令及 CI | 有执行约束；需要处理 CSS/SFC 解析、Git 对比和例外边界 | 用户已选择 |
| 仅完善规范             | 只整理设计规则、入口和验收要求                                                  | 变化较小，但持续依赖人工检查                          | 未选择     |

本次沿用 Vue、TypeScript、Naive UI 和 Prettier/ESLint，不迁移 Biome，不重新组织为 atoms/molecules，不批量重绘页面。Classic/Folia 是布局皮肤；Absolutely、Catppuccin 等实际内置配色及用户主题仍按现有注册和映射生效。

- 主仓库 `AGENTS.md` 第 4 节已有主题、布局、滚动、状态、国际化、类型及键盘要求；第 6 节已有按风险选择测试和真实启动器验收要求。

- 现有 ESLint/Prettier/类型检查主要约束代码；已有表面、透明度、皮肤、控件行为与模态测试，但没有统一检查新增 CSS 是否绕过视觉规则。

### 3.2 需要写清的规范

1. **令牌归属**：组件和页面优先消费当前语义变量；默认值属于令牌/主题源，页面不得通过重新声明变量绕过主题。保留现有变量消费者，别名清理或主题协议变更另行审阅。
2. **主题覆盖**：说明实际的导入顺序、CSS 级联和 `useTheme` 内联写入；区分布局皮肤、配色、亮暗、用户外观参数及 Naive UI overrides，避免用一张简化优先级表掩盖当前差异。
3. **组件选择**：先复用当前业务入口已使用的 Ui 或 Naive UI 组件。标准输入和操作遵循集中 overrides；自有控件的共性修正在其公共实现。只有现有入口确实不满足当前需求才新增组件。
4. **职责分层**：`components/ui` 负责通用外观与交互；公共布局/模态负责空间、层级和焦点；`features`、业务组件和页面负责业务编排；领域 API、store、composable 维护状态和 IPC。禁止公共 Ui 层反向依赖具体业务。
5. **页面布局**：统一标题、工具栏、内容区、主要滚动容器和单卡片撑满规则；保留页面间距，支持 960×600、默认和放大窗口及长译文。
6. **交互状态**：集中定义 hover、pressed、focus、disabled、loading、empty、error，复用现有变量和组件。保留 ECL 的功能性动效原则，不引入博客状态层或装饰效果。
7. **动效与偏好**：引用现有 duration/easing 和公共过渡；新增 CSS 关键帧遵循当前 `animations.css` 归属。Canvas/Three.js 等运行时动画明确自身所有者，并尊重减少动效设置。
8. **合理固定值**：布局尺寸、细边框、图标几何、比例、圆形、零值和必要的运行时测量不一概禁止。品牌资源、游戏内容色、选色预览、主色填充文字等按当前契约明确归属和理由。
9. **CSS 所有权**：页面样式限定作用域，公共组件修复位于公共层；第三方选择器覆盖集中管理。`!important` 只用于明确的第三方/生成样式边界、用户偏好、窗口裁剪或已有公共覆盖契约，不用来解决无关级联冲突。
10. **验收区分**：分别记录规范审查、静态检查、组件行为、浏览器布局和真实启动器结果。基础矩阵沿用 Classic/Folia × 亮暗；改到主题共用入口时补充受影响内置配色及用户主题代表状态，不因改文档运行全量 UI 矩阵。

## 4. 自动检查设计

### 4.1 实现位置和依赖

新增 `frontend/scripts/check-design-styles.mjs` 及对应测试，由现有 `vue/compiler-sfc` 读取 Vue style 块、现有 PostCSS 读取 CSS 语法树。两者已在当前安装环境解析可用；不增加依赖、锁文件或新的通用规则框架。

新增 `pnpm check:design`，接入现有 `pnpm check`。共享 Ui 层的业务依赖边界通过现有 ESLint 的定向规则实现，避免另写一套 TypeScript 导入解析器。修改 ESLint 规则时补充能区分合法和非法调用方的用例。

### 4.2 首批可执行规则

| 规则                      | 检查行为                                                                                         | 合法边界                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 新增硬编码视觉颜色        | 检查页面和组件 CSS 声明中的字面颜色，包含渐变、阴影、变量赋值及 var fallback，避免换一种写法绕过 | 主题/令牌源中其拥有的变量定义；内容固有颜色等登记例外；transparent/currentColor/inherit 等关键字 |
| 新增非令牌动效参数        | 检查 transition/animation 的 duration、delay 与 easing，包括简写及长属性                         | 零时长关闭效果、令牌源、已说明的减少动效规则或精确例外；保留函数几何参数                         |
| 新增越权关键帧            | 组件或页面新增 `@keyframes` 时失败，提示归入公共动画来源                                         | `animations.css`；确有独立生命周期并登记的例外                                                   |
| 新增未说明的 `!important` | 对新增声明核查所有权边界                                                                         | 精确到文件/规则/声明的有效例外，不支持整目录关闭或无限期接受                                     |
| Ui 层反向业务依赖         | `components/ui` 引入 views、features、业务 API 或业务 store 时失败                               | 已确认必要的通用工具、类型、公共组件及交互 composable；具体允许入口在实施时按真实依赖收敛        |

字体阶梯、信息层级、是否应当复用某组件、页面是否好看和对比度是否足够，不由正则或 CSS 静态扫描假装判定；仍由规范、组件测试和实际页面验收覆盖。

### 4.3 增量范围与 Git 边界

- 对比当前文件与受检版本的原始 Git 内容，以“文件、祖先 at-rule、选择器、属性、值和重复次数”识别新增或修改声明。旧违规移入新文件/新选择器、增加重复声明，也属于新增。
- 新文件全部检查，删除项不要求修复，未改的存量声明不阻塞本次提交；不得以复制旧代码为由新增违规。检查仍输出明确文件、行号、规则和修复提示，不记录用户路径或配置值。
- 本地默认以 `HEAD` 对比工作区，包含暂存、未暂存及新文件；CI 明确传入基线和目标，并按事件计算提交差异，不能在干净 checkout 上仅比较 HEAD 与工作区而得到空覆盖。
- 前端独立仓库 PR 使用 PR 基线；push 使用 before SHA，手动运行使用明确基线；主仓库 CI 使用主仓库前后 gitlink 所指前端提交。历史不足时补取所需 Git 对象。
- 新分支、首次接入或旧 Git 对象不可获得时，执行已定义的受管入口检查或明确失败并给出取回方式，不能静默通过。纯删除或无受管样式变化允许成功，但必须报告实际范围和数量。
- 不扫描 `node_modules`、dist、生成文件、用户安装目录或第三方插件任意源码。`frontend/src` 内受维护的页面、公共组件和样式属于扫描范围。
- 精确例外记录原因、所有者、适用声明与到期日期；过期、未匹配或超出范围时失败。不自动生成例外来使现有代码通过，不维护无解释的整文件哈希豁免。

## 5. 实施顺序与文件范围

1. 核对并整理设计规范及组件选择表，更新主仓库和前端目录入口；先明确全部规则的真实所有者。
2. 建立 CSS/SFC 检查器和有限范围例外模型，使用合成输入验证规则与合法边界，不先跑全仓改写。
3. 加入 Ui 依赖约束，调查当前依赖后只修正本次接线阻碍，不引入新组件层或大范围搬迁。
4. 将检查接入 `package.json`、前端独立 CI 和主仓库前端 CI，处理 Git 基线及浅克隆，测试干净 checkout 中的实际变更范围。
5. 只处理本次新增规范、检查器和接线涉及的代码；未触及页面保留当前外观和行为，存量视觉整理单独记录和审阅。
6. 完成第 6 节验证，先提交/集成前端本地 main，再更新主仓库 gitlink、规范和本地 main。远端推送及发布不在本方案授权内。

主要运行文件为新检查脚本及其测试、ESLint 配置、package scripts、两处 CI 的差异基线接线；文档文件见 3.1。若规则实施需要改动全局主题、公共组件运行行为或增加依赖，先补充具体原因和影响再确认，不借检查器引入视觉改版。

## 6. 测试与验收

本次包含共享检查工具、ESLint 和 CI 接线，前端执行全量检查；主仓库仅修改规范文档、前端 gitlink 和对应工作流，不修改后端运行代码，不运行无关全量 pytest。

- 检查器回归：CSS 与 Vue style 块、注释和字符串、渐变/阴影/var fallback、简写/长属性、多个样式块、合法零值/关键字、精确例外与过期、语法错误必须失败。
- 增量回归：已有违规未修改、修改值、移动到新选择器、复制到新文件、重复声明增加、暂存/未暂存/未跟踪、删除和重命名、无相关变化、缺少 Git 对象、独立前端与主仓库 gitlink 提交范围。
- ESLint 回归：公共 Ui 允许的组件/工具输入通过，导入业务 store/API/views/features 失败，文件豁免和路径别名不能绕过。
- 执行 `pnpm check`，包含新规则回归及全量既有检查；构建 `pnpm build`，确认开发工具未进入产品 bundle。
- 对 CI 中用到的实际事件字段和 Git 命令做本地仓库场景验证；未运行远端 CI 时如实注明。
- 本方案不调整页面模板、CSS 视觉值或产品运行逻辑，默认不重新运行真实启动器主题矩阵；若实施中出现这类修改，按主仓库 `AGENTS.md` 第 6 节补足对应浏览器/真实启动器验收。
- 文档检查结构、当前入口、本地链接及格式，执行 `git diff --check`；不重复执行同代码同环境已通过的无关检查。
