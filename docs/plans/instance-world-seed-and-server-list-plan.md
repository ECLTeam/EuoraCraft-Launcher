## 1. 需求与调研结论

调研日期：2026-10-02。主仓库基线 `0d434e4`，前端子仓库基线 `38e06ca`，两者工作区在调研开始时均干净。

本次目标：实例管理弹窗的存档列表正确显示真实地图种子，编辑保存不会丢失精度或写错字段；服务器页采用既有列表的图标、信息、操作对齐方式。

### 1.1 种子问题

- `ECL/services/game/worlds.py` 的 `_read_world` 只读取 `Data.RandomSeed`，没有读取 `Data.WorldGenSettings.seed`。
- `_nbt_scalar(None, "")` 返回 `None`，后续 `str()` 生成字面字符串 `"None"`。前端 `world.seed || '-'` 无法识别这个真值字符串。
- `_apply_world_patch` 只写 `RandomSeed`。新增现代格式读取后，若不同时修复写入位置，用户修改后仍会读到旧种子。
- `InstanceWorldsTab.vue` 使用 `Number.parseInt` 和 `NInputNumber` 编辑种子，且保存其他设置时也总是提交种子，可能损坏超出 JavaScript 安全整数范围的值。
- `WorldPatchData.seed` 目前仅接受整数；前端需要使用十进制字符串，后端须明确校验后再转换为 Python 整数。
- 前端 Chunkbase 按钮直接拼接链接，未检查种子是否有效；后端还有独立的 `chunkbase_url`，同样需要避免使用缺失种子。

已使用临时目录中的真实 gzip NBT 文件调用当前 `_read_world`，结果如下。没有读取或修改用户的实际存档。

| 构造的种子位置 | 当前返回值 | 期望 |
| --- | --- | --- |
| `Data.RandomSeed` | `-4172144997902289642` | 保持准确 |
| `Data.WorldGenSettings.seed` | `None` 字符串 | 返回准确种子字符串 |
| 缺少种子字段 | `None` 字符串 | 返回明确的不可用状态 |
| 独立种子数据文件 | `None` 字符串 | 读取对应格式的真实种子 |

同一个长种子经双精度数值往返后变成 `-4172144997902289408`，因此修复不能只调整空值文字。

格式依据：[uNmINeD NBT 库作者提供的读取示例](https://github.com/unminednet/Unmined.Minecraft.Nbt)使用 `Data/WorldGenSettings/seed`；[Minecraft Java 26.1 官方更新说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1)明确将 `WorldGenSettings` 移到 `data/minecraft/world_gen_settings.dat`。独立数据文件的根节点包装和压缩形式需在实施首步通过对应版本的实际文件或发布代码确认，不能把本次构造的测试包装形式当成官方格式证据。

### 1.2 服务器列表问题

- `InstanceServersTab.vue` 每个服务器采用独立边框圆角卡片，与模组、资源列表的连续行和分隔线不同。
- 左侧只有状态圆点，没有列表图标；名称和地址挤在同一行，地址缺少溢出处理。
- 右侧启动按钮与其他操作占用较多宽度，窄窗口和长文本可能相互挤压。
- `ServerEntry.icon` 和 `ServerStatus.icon` 已存在，后端已经返回本地图标和状态查询图标，前端尚未展示。
- 加载和空内容已经使用 `InstanceContentState`，本次继续沿用统一加载动画和空箱占位。

## 3. 种子读取、显示与保存规则

### 3.1 读取规则

1. 将种子来源解析与一般 NBT 标量读取分开，使用明确类型的种子来源对象，记录文件、字段位置、有效整数和可编辑状态。
2. 优先识别实际使用的存储结构：独立 `world_gen_settings.dat`、`WorldGenSettings.seed`、旧式 `RandomSeed`。现代有效来源优先于迁移后残留的旧字段。
3. 独立文件存在但损坏、字段类型异常时，不静默回退到可能过期的旧字段。列表保留存档，种子显示“未知”，并提供可理解的原因。
4. 接受格式中真实的整数种子，校验有符号 64 位范围 `-9223372036854775808` 至 `9223372036854775807`。`0` 是有效种子，不能被空值判断吞掉。
5. API 输出有效种子为十进制字符串；不可用时统一为空字符串，并以可选的状态字段说明原因。前端不得显示 `None`、`null`、`undefined`。
6. 不搜索任意模组私有标签、不猜测随机种子、不自动改写存档。对未识别结构提示未知。
7. 独立文件读取采用解压体积限制，并拒绝越出存档目录的符号链接；读取失败不影响其他存档条目。

### 3.2 编辑与 IPC

- 种子输入改为 `NInput` 文本字段，值从展示到 IPC 全程保持字符串。
- 前端使用整数文本检查和 `BigInt` 范围检查，不经过 `Number`、`parseInt` 或 `NInputNumber`；禁止小数、科学计数法及任意非整数文本。
- 前端只在用户明确修改种子时提交 `seed`。打开编辑器后直接保存或修改难度等其他字段，不应隐式修改种子；缺失种子不能自动填 `0`。
- 未知或无法安全识别的来源不能直接写入猜测字段，编辑器明确说明种子不可编辑原因。
- IPC 模型接受十进制种子字符串并严格转换。兼容旧调用方的安全整数请求；拒绝布尔值、浮点值、越界值及经 JavaScript 数字传输已经可能失真的超大数值请求。
- 服务层再次校验，防止绕过 IPC 的内部调用写入非法 NBT。使用稳定的 `INVALID_WORLD_SEED` 等领域错误码。
- 保持原有编辑功能；本次只修正种子链路，不开展 26.1 难度、天气等其他迁移字段的全面改造。

### 3.3 写入与备份

- 旧式存档写回 `RandomSeed`；现代内嵌存档写回 `WorldGenSettings.seed`；独立格式写回原独立文件中的实际种子位置。
- 不向现代存档新建无效的 `RandomSeed`。若存在遗留生成器的显式种子字段，实施时根据对应版本源代码确认其是否参与生成，再限定处理；不得对模组自定义结构递归替换所有名为 `seed` 的字段。
- 修改前继续执行游戏运行、目录边界、存档占用检查，保留自动备份以及所有未知 NBT 字段。
- 先完成请求与结构校验，再创建备份和准备写入；非法输入不产生内容修改。
- 单文件使用临时文件与 `replace`。如果同时修改 `level.dat` 和独立种子文件，先准备全部内容，再按受控写入顺序执行；任一替换失败回滚已替换文件，清理临时文件。
- 写操作使用同一存档的锁，避免并发保存交叉覆盖。测试注入第二次替换失败，确认两个文件都恢复原值。
- 保存成功后刷新世界缓存并重新读取，显示磁盘上的新值；保存失败保留编辑内容和错误提示。

### 3.4 Chunkbase

有效种子保持完整文本用于链接编码，支持 `0` 和负数；缺失种子时按钮禁用或提示“无法读取世界种子”，不打开错误链接。前端实际入口与后端已有 URL 方法使用一致的种子有效性规则。本次不新增外部服务接口。

## 4. 服务器列表布局

### 4.1 行结构

采用连续列表行和底部分隔线，悬停色、文字色、圆角与既有实例管理列表使用相同主题变量。移除每个条目的独立卡片边框和外间距。

| 区域 | 展示内容 | 约束 |
| --- | --- | --- |
| 左侧图标 | 优先查询返回图标，其次本地记录图标，最后现有服务器图标 | 32px 图标槽，固定占位；图片失败立即回退 |
| 信息区 | 名称及收藏标记、地址、MOTD／查询状态 | `min-width: 0`；长文本省略，完整内容可通过提示查看 |
| 状态区 | 在线／离线／未查询、玩家数、延迟、版本 | 保留文字，颜色作辅助；未查询、查询中及离线不能显示错误的在线值 |
| 操作区 | 启动并连接、复制地址、编辑、删除 | 按钮统一尺寸、垂直居中，提供完整可访问名称 |

### 4.2 响应式与行为

- 宽窗口保持信息、状态和操作列对齐。窄窗口将状态信息放到正文下方，启动操作可显示图标并保留“启动并连接”的提示和可访问名称。
- 行不能因条目多而压缩高度；正文随状态信息自然增高，不采用可能覆盖文字的固定高度。
- 明确滚动区域的 `flex: 1`、`min-height: 0` 和 `overflow-y: auto`，大量服务器仍保持正常行高。
- 图标只使用已返回的合规 PNG 图像数据，不把任意地址直接用作图片 URL；损坏、过大或非图像数据回退，不造成布局跳动。
- 搜索、刷新列表、刷新状态、添加、收藏、连接、复制、编辑和确认删除沿用当前业务逻辑。图标不额外触发状态查询。
- 沿用现有顶部工具栏和 `InstanceContentState`，不重新引入加载遮罩或模糊层。
- 不增加多选管理、服务器自动探测或联机功能。

## 7. 测试与验收

### 7.1 后端

- 三种格式读取：正数、负数、`0`、有符号 64 位上下界和超过 JS 安全整数范围的值。
- 新旧字段同时存在时读取实际有效来源；缺失、错误类型、损坏文件、符号链接越界、过大 NBT 有明确结果。
- 三种格式种子修改后磁盘重读一致，保留未知标签，自动备份包含修改前文件。
- 文本输入不经过浮点转换；布尔值、小数、科学计数法、超范围及不安全数字请求拒绝，磁盘内容不变。
- 不提交种子时不改变任何种子字段；现代格式不新建旧字段。
- 多文件替换失败回滚，并覆盖并发保存、游戏运行中拒绝写入及临时文件清理。
- Chunkbase 不接受未知种子，完整编码有效长种子。
- 最低检查：`ruff check ECL tests`、`ruff format --check ECL tests`、相关 pytest，以及后端 CI 的 `python -m pytest --tb=short -q`。已有浏览器测试如遇本机未安装 Chrome，使用已安装 Edge 运行相同测试并如实记录环境适配。

### 7.2 前端与实际启动器

- 存档长种子原样显示、打开编辑器、保存与重载；零种子可正常显示和提交。
- 未知种子不显示 `None`，不默认写入 `0`；仅修改难度等字段不提交种子。
- 非法输入提示、保存失败保持编辑器、成功后刷新真实数据。
- 服务器未查询、在线、离线及查询中的图标和状态；缺失、损坏图标回退。
- 名称、IPv6／长域名地址、长 MOTD 和版本文字不会挤压操作或超出容器。
- 验证 1、20、272 条服务器记录；窗口宽度 960px、较窄窗口及宽窗口，检查行高、文本边界和按钮可点击性。

- 浅色与深色背景下检查分隔线、图标、状态、悬停、空箱占位和纯加载动画。
- 前端必须先完整 `pnpm check`，再 `pnpm build`，最后真实启动器验收；不能用组件测试代替桌面运行检查。
