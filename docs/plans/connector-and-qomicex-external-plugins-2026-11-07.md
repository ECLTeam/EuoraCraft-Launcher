# 联机系统与 QomicEX 兼容插件外置实施方案

- 日期：2026-11-07。
- 状态：用户已批准实施；代码、普通插件、本地 main 集成和必要验收已完成，公开网络双端验收尚未完成。实际记录见第 10 节。2026-11-08 后续：两个插件已按用户要求迁出为独立仓库（ECL-Plugin-OnlineGame、ECL-Plugin-QomicexCompatible），主仓库删除 `external_plugins/` 与配套工具、测试，本方案保留历史记录。
- 决策记录：[ADR-003](../ADR-003-connector-and-qomicex-external-plugins.md)。
- 目标：主程序不携带联机业务及其专用原生库；两个插件分别安装、授权、启用和卸载。

## 1. 已确认的产品范围

| 项目             | 联机插件                            | QomicEX 兼容插件                    |
| ---------------- | ----------------------------------- | ----------------------------------- |
| 插件标识 `name`  | `ECL-OnlineGame`                    | `Qomicex-Compatible`                |
| 显示名称 `title` | ECL-OnlineGame                      | Qomicex-Compatible                  |
| 作者             | ECLTeam                             | ECLTeam                             |
| 显示版本         | v1.0.0-beta                         | v1.0.0-beta                         |
| 清单版本         | `1.0.0-beta`                        | `1.0.0-beta`                        |
| API              | `api_version: 1`，普通 Worker 插件  | `api_version: 1`，普通 Worker 插件  |
| 分发             | 独立 `.eclplugin`，不随主安装包分发 | 独立 `.eclplugin`，不随主安装包分发 |
| 界面             | 主窗口内的插件页面                  | 宿主插件设置页，按需登记联机扩展    |
| 特权             | 无内置、隐藏、免授权或不可禁用待遇  | 无内置、隐藏、免授权或不可禁用待遇  |

用户已指定联机插件的标识和显示名称统一为 `ECL-OnlineGame`，分发文件名使用 `ECL-OnlineGame.eclplugin`。

`Qomicex-Compatible` 是完整插件身份替换，不保留旧 `qomicex-compat` 身份别名。外部协议中的 `qml:*` 与第三方来源标识 `qomicex` 沿用其业务契约，不随显示名称重命名。

本次修正上一轮建议：QomicEX 实例元数据读取也随兼容插件移出主程序，不再作为内置能力保留。

## 2. 现状与必须解决的缺口

已检查以下拥有实际行为的代码和配置：

- `ECL/application.py`：无条件创建联机服务，并向插件管理器注入服务与协议注册表。
- `ECL/services/connector.py`、`connector_nodes.py`、`ECL/services/florolding/`：EasyTier、房间协调、局域网广播、端口与 NAT 探测、节点配置及会话资源。
- `ECL/api/connector.py`、`api/bridge.py`、`api/system.py`：直接联机 IPC、状态读取和节点预热。
- `ECL/plugins/runtime/connector_api.py`：现有 Worker `connector.*` 仍由宿主联机服务执行，不能直接满足外置减包。
- `ECL/plugins/runtime/broker.py`、`runtime/models.py`、`manager/registry.py`、`ECL/plugins/api/plugin.py`：普通 Worker 有插槽、命令和跨插件调用；尚无完整 Worker 页面注册，命令字段仅支持基础标量。
- `resources/system_plugins/qomicex_compat/`：一个系统插件同时实现实例读取、索引设置和四个 `qml:*` 协议，内部直接使用宿主对象和路径。
- `ECL/plugins/instance_compat.py`、`tests/test_plugin_compat_remote.py`：Worker 兼容来源目前仅能提交有限字符串字段，不能完整表达现有图标、隐藏/固定状态、运行统计和索引刷新。
- `frontend/src/views/More.vue`、`views/connect/`、`features/connect/`、`components/connect/`、`composables/usePluginBridge.ts`：现有联机入口和页面仍是宿主代码；宿主已有可复用的动态插件路由。
- `pyproject.toml`、`EuoraCraft-Launcher.spec`、`packaging/build-nuitka.ps1`、`.github/workflows/build.yml`：主程序声明 EasyTier 依赖，构建显式收集原生资源，PyInstaller 还递归收集 `ECL`。
- `docs/guides/plugin-development/`、`docs/designs/plugin-cross-plugin-invocation-design.md` 及现有联机、兼容、Worker、打包测试。

本机开发环境的 `easytier_pyo3` 目录未压缩约 18.18 MiB，其中原生扩展约 17.47 MiB。该数值仅是依赖目录基线，不能当作最终安装包缩减值。

`mcstatus` 仍由游戏服务器查询使用，`websockets` 仍由开发通道使用；`httpx`、`psutil` 等也有主程序调用，保留宿主实际需要的依赖。

工作区已有主仓库规范与前端修改，前端提交也在其他工作中推进。实施开始时重新取基线，使用隔离工作树；本方案文档提交不带入既有修改和子模块指针。

## 3. 目标结构与职责

### 3.1 主程序

只保留通用插件发现、安装、权限、Worker 监管、设置、页面容器、命令调用、实例查询与兼容来源接口。主程序不导入 Florolding 或 EasyTier，不创建房间，不探测联机节点，不维护联机玩家列表。

已有 `connector.*` 宿主实现、专用 IPC 与预热入口随生产方、前端和示例一起移除。现有联机插件示例改为发现并调用外置联机插件公开命令；未安装提供方时明确报告不可用，不保留旧宿主实现作为回退。

不为 ECLTeam 的外部插件建立自动信任或系统插件特殊分支。

### 3.2 联机插件

完整拥有以下行为与资源：

- 指定端口和选定运行实例建房、房间码解析、加入、离开、踢出玩家。
- Florolding 协调、EasyTier 节点、局域网广播与转发、端口探测、Minecraft 端口识别、NAT 检测。
- 公共及自定义节点、节点缓存、玩家状态、基础版本信息及相关错误反馈。
- 主窗口联机页面、节点设置与 NAT 弹窗、房间码和玩家列表组件及插件内翻译。
- Worker 内的网络客户端、线程、定时器、取消和幂等关闭；宿主异常监管负责最终回收。

只通过宿主公开 API 获取用户批准的实例和账户摘要，不导入 `ECL.services`、`ECL.plugins` 私有实现，不获取凭据。账户与实例授权被拒绝时，保留可独立使用的手动端口和玩家名操作。

### 3.3 Qomicex-Compatible

完整拥有现有 QomicEX 业务：

- 只读解析 `instances.json`，路径匹配与歧义处理、简介、隐藏/固定标记、图标、累计运行时间和最近启动时间。
- 索引来源设置、候选目录发现、索引缓存失效和清晰的失败提示。
- `qml:game_info`、`qml:player_icons`、`qml:player_leave`、`qml:game_mods` 的生成、解析与会话缓存。

实例读取不依赖联机插件；联机未安装或未启用时，实例兼容继续工作。取消系统插件身份后，普通 Worker 所缺的能力由通用接口补齐，不把原系统插件改为第三方进程内运行。

## 4. 普通插件接口调整

以下是本次真实调用方需要的增量，不建立无调用需求的插件框架。

### 4.1 主窗口插件页面

在 Worker SDK、Broker、管理器和前端桥中补齐 `ui.register_page`，复用现有插件路由注册和页面渲染。

- 页面声明包含插件内相对路由、标题、图标、模板、脚本和样式，按现有注入预算限制资源大小。
- 路由固定归属 `/plugin/{插件标识}/...`，不允许覆盖宿主、其他插件或任意绝对路由。
- 使用现有 `ui.inject` 审阅与主窗口注入开关，不另造免审阅通道。
- 禁用、卸载、撤权、运行结束和注入总开关关闭时撤销页面与入口；若正在查看该页，回到插件管理页并给出原因。
- 页面直接调用本插件已登记命令，沿用可信前端桥；不把任意宿主 IPC 暴露为新的 Worker API。
- 该形式继续遵守现有同文档注入的信任边界，不宣称实现 DOM 或 OS 沙箱。

原 `/more/room` 的内置路由及 `More.vue` 中联机专属上下文删除。联机入口由插件注册，未安装时不显示内置联机页，也不自动下载。联机语言可用范围先保持当前简体中文行为；宿主新增公共文案同步六语言。

### 4.2 有界结构化命令

为现有命令字段增加有界 JSON 类型，用于玩家列表、NAT 结果和协议请求等嵌套 DTO；原有标量字段继续按其契约工作，不将复杂数据塞入无校验的 JSON 字符串。

- 校验 JSON 类型、深度、成员数、字符串和编码后总长度；禁止非有限数值和非 JSON 对象。
- 普通控制请求/响应初始上限 16 KiB；玩家、模组等集合分页读取，每页不超过相同预算。
- 头像按独立有界块传输，单块不超过 16 KiB，单头像解码后不超过 512 KiB；先检查图片类型、尺寸与声明长度，实际限制覆盖现有受支持纹理。
- 宿主执行通用边界校验，插件入口再转换为明确的业务 DTO；不接收任意 Python 对象或可执行 schema。
- 保留命令导出、双方启用状态、运行身份、调用深度和超时限制，旧运行的引用不能用于新运行。

联机插件公开 `status`、`host_port`、`host_instance`、`join`、`leave`、`kick`、`detect_ports`、`search_mc_port`、`nat_type`、节点查询与更新等命令。建房、加入和探测返回操作引用，由后续查询确认执行终态；普通轮询成功不产生日志。

### 4.3 实例兼容来源

扩充现有 `compat.register` 回调 DTO，继续由原实例服务合并结果：

- 类型化支持原 `ExternalInstanceMetadata` 中实际使用的字符串、布尔、受控图标、运行统计、警告和来源修订。
- 实例上下文使用宿主生成的授权引用。为路径匹配提供仅属于已授权实例的最小身份信息，不发送未授权根目录。
- 外部索引由用户选择或确认候选来源；补齐必要的只读外部文件引用与修订查询。宿主只做通用文件选择、授权和读取，不包含 QomicEX 专用目录解析。
- 候选发现、`QOMICEX_HOME`/默认目录策略留在兼容插件；若 Worker 缺少必要平台目录信息，提供有限的目录用途查询，不透传整个宿主环境。
- 索引修订变化或插件启停触发实例扫描缓存失效；刷新回调、文件引用和数据源均绑定安装与运行，撤权即失效。
- 仅允许插件维护已获准实例的外部只读元数据，不向实例文件写入兼容结果，不修改 QomicEX 文件。

文件引用、结构化元数据和缓存刷新是完整迁移的验收项，不能以仅保留描述字段代替。

## 5. 两个插件的可选协作

### 5.1 依赖关系

两个清单均不声明对另一个插件的必需依赖。通过现有 `plugins.list` / `plugins.call` 显式发现和调用导出命令，不新增跨插件事件总线。

- 联机插件发布带协议版本的通用联机扩展命令契约；具体 `qml:*` 处理器只存在于 Qomicex-Compatible。
- 兼容插件启用后尝试发现联机能力；未发现或协议版本不支持时，仅标记联机扩展未接入，不阻止实例来源注册。
- 联机插件在建房/加入时重新发现已启用扩展，按会话建立快照；插件后安装或重新启用后，下一次会话自动生效，不依赖启动顺序。
- 发现基于实际导出的能力及契约版本，联机插件不以 QomicEX 插件名称作为启动条件。

### 5.2 协议及会话边界

联机插件负责网络传输和会话；兼容插件负责协议语义。扩展通过有界 JSON 交付协议名、回调命令、版本和所需状态字段。

会话上下文只含本次必要的房间引用、角色、基础游戏信息、受控玩家标识与已批准头像/模组摘要，不交付 socket、账户凭据、实例全路径或可执行对象。`qml:player_leave` 中对端声明的玩家身份必须与实际连接身份核对，不能允许任意踢人。

使用串行会话队列和单向命令回调：联机插件调用兼容处理器时，处理器直接返回结果或受控后续动作，不在同一调用栈内反向同步请求联机插件，避免 A→B→A 死锁。房客元数据请求由联机插件执行传输，再把响应交给兼容插件解析。

扩展注册、请求和缓存绑定双方安装/内容/运行与房间代次。禁用、撤权或更新后，下一次调用立即拒绝旧身份；联机侧移除相应扩展并释放缓存，迟到响应不得修改新房间。

每次协议协商对本会话固定。会话中兼容插件失效后，仅相应可选协议明确不可用，基础建房、加入和已有隧道保持运行；不重新协商或伪造兼容结果。禁用联机插件则真正停止网络与房间。

### 5.3 必须达到的组合行为

| 安装/启用状态                   | 预期                                                                     |
| ------------------------------- | ------------------------------------------------------------------------ |
| 两者都未安装                    | 启动器正常启动，不加载联机库、不预热节点                                 |
| 只有联机插件                    | 基础建房、加入、NAT、节点和玩家管理完整可用，不出现缺 QomicEX 的启动错误 |
| 只有 Qomicex-Compatible         | 已授权实例兼容正常，联机扩展显示未接入                                   |
| 两者均启用                      | 基础联机加 QomicEX 的四个扩展协议                                        |
| 房间中禁用 Qomicex-Compatible   | 基础房间保持，兼容扩展停止，旧数据清理                                   |
| 禁用/卸载联机插件或 Worker 崩溃 | 停止实际网络资源、撤销页面，兼容插件的实例读取不受影响                   |

## 6. 数据、依赖与包结构

- 源码建议在主仓库新增 `external_plugins/ecl_onlinegame/` 和 `external_plugins/qomicex_compatible/`，作为真实插件工程维护，产物单独输出；不得放入 `resources/system_plugins` 或主安装包资源。
- Florolding 固定当前已验证提交并作为联机插件私有依赖维护，保留许可证及来源；主仓库不再通过运行时 `ECL.services.florolding` 提供能力。完成全调用方清查后移除原 gitlink，并更新 `.gitmodules`；不修改无关子模块内容。
- EasyTier 使用匹配宿主平台/架构/Python ABI 的锁和 wheels 随插件分发，包含实际需要的 DLL/驱动资源。冻结发行物内加载原生扩展必须实测，不能以源码导入成功代替。
- 两个插件各自使用插件设置和私有数据目录。节点设置归联机插件，索引选择归兼容插件；主程序移除旧 `connector`、`game.qomicex_instances_path` 的生产和消费入口。
- 本方案不自动迁移旧配置或授权，不继承旧系统插件权限。用户重新审阅插件并设置节点、选择索引；旧文件保留，不扫描或清理用户历史数据。
- 原有 `instances.json`、实例目录、存档、账户文件和第三方启动器设置一律不被修改或删除。
- 移除主程序 EasyTier 依赖、Nuitka 数据收集和 PyInstaller 隐式收集路径，更新生产依赖清单及治理输入；保留其他业务实际使用的共享库。
- 输出两个独立归档及平台/ABI 说明。不同平台缺 wheel 或原生验收失败时明确列为未交付，不能用其他平台结果代替。

1. **基线与隔离**：重新检查主/前端工作树、子模块及规范，建立 `codex/` 工作分支和隔离工作树；记录同配置未改动构建的体积与功能基线。
2. **通用接口**：修改 `ECL/plugins/api/plugin.py`、`ECL/plugins/runtime/models.py`、`broker.py`、`worker_service.py`、`manager/registry.py` 及必要权限/文件模型；补齐页面注册、有界 JSON 和完整实例元数据回调。先完成对应 Worker、拒绝授权和失效测试。
3. **主窗口承载**：修改前端 `usePluginBridge.ts`、插件类型、Host API、路由及相关测试，复用现有动态路由和页面组件契约；运行中页面撤销必须安全导航。
4. **联机插件工程**：将 `services/connector.py`、`connector_nodes.py` 和 Florolding 的业务迁入插件，消除私有宿主导入，拆出 DTO、设置和网络资源的明确归属；完成跨插件扩展命令契约。
5. **兼容插件工程**：将 `resources/system_plugins/qomicex_compat/main.py` 的实例读取与 `qml:*` 语义迁入普通 Worker，改用自身设置、受控实例与索引接口；原设置 Vue 改为宿主标准插件设置/必要声明式面板。
6. **联机页面迁移**：将 `views/connect/`、`components/connect/`、`features/connect/`、相关样式和翻译迁入联机插件；使用当前页面作功能基准，同浏览器对照插件管理页和工具页的密度、页面边距与反馈。
7. **宿主清理**：删除原联机装配、API、旧权限/类型/事件和专用配置入口；移除 QomicEX 系统插件资源及其专用配置消费，更新插件示例和文档。没有提供方时明确失败，不回退旧实现。
8. **构建与治理**：修改 `pyproject.toml`、`.gitmodules`、`EuoraCraft-Launcher.spec`、`packaging/build-nuitka.ps1`、`.github/workflows/build.yml` 及确实受影响的依赖清单；增加两个插件的归档构建和平台原生库检查。
9. **验收与交付**：先通过受影响仓库全量检查，再完成冻结产物与真实联机验收，按同一功能的可验收阶段提交；子仓库先完成本地 main 集成，再更新主仓库指针。远端推送和发布另行取得当前变更授权。

若实施中发现需要扩大权限、改变协议或无法保持上述完整能力，先修订本文说明具体差异，不用功能裁剪或未验证回退掩盖缺口。

## 8. 测试和验收计划

### 8.1 自动化
