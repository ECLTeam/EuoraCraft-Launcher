本次直接使用原生图片元素加载固定远端地址，不新增后端代理、磁盘缓存、GitHub API 查询、贡献者数据模型或手动维护的头像列表。不读取、解析或注入远端 SVG 文本，不增加普通状态下的刷新按钮、贡献者计数或额外跳转入口。

## 4. 页面布局与交互

### 4.1 卡片内容

新增卡片使用现有 `about-card`、`card-title` 与 `card-body`。感谢文案在上，头像合成图在下，不为这张小图添加内嵌卡片、独立背景、装饰边框或阴影。

图片采用 `display: block`、`max-width: 100%` 和自动宽高，保持自然比例，不设置固定卡片高度或头像数量。贡献者增多导致图片变高时，卡片随内容增高，由设置页既有主要滚动容器承载，不新增同向嵌套滚动。

图片替代文本使用国际化的「EuoraCraft Launcher 社区贡献者头像」。图片本身不作为交互控件，不添加无功能的 Tab 焦点。重试按钮使用现有按钮外观及原生按钮语义，支持键盘和可见焦点。

### 4.2 加载、成功与失败

- 仅在关于页挂载时请求图片，不在应用启动或其他设置页预加载。普通图片加载不设置懒加载，避免未滚动到卡片时计时器先于实际请求超时。
- 初始状态在图片区域显示「正在加载贡献者…」，复用 `UiLoading` 的小尺寸 inline 形态，不叠加遮罩，也不显示破图图标。
- 图片加载成功后展示图片并移除加载提示；已由浏览器缓存完成加载的情况也须正确进入成功状态，不能停留在加载状态。
- 图片加载失败或单次等待超过 20 秒时，移除本次图片展示，显示「贡献者图片暂时无法加载」及「重试」。感谢文案不受影响，不用全局消息反复提示第三方图片故障。
- 重试开始新的加载轮次并重新挂载图片，使用相同固定 URL，不添加随机数或时间戳绕过正常缓存。加载期间不展示可重复点击的重试按钮，事件处理同时校验当前状态。
- 单次等待超时只表示本页停止等待，不宣称底层请求已被可靠取消。旧轮次的 load、error 或计时回调不得覆盖新轮次的状态。
- 页面卸载时清理计时器并使旧轮次失效；离页后的回调不得写回页面状态。重新进入页面按新的加载轮次处理，不维护应用级第二份状态。

状态放在关于页本地实现，可通过加载轮次或当前图片元素身份拒绝过期事件；只有本页一个调用者，不新增通用图片管理框架或共享 store。

1. 在 `frontend` 对实际改动文件执行 `pnpm exec prettier --check <改动文件...>`，对 Vue、TypeScript 与测试执行 `pnpm exec eslint <相关代码文件...>`。

3. 执行 `pnpm exec vitest run src/views/settings/AboutTab.test.ts`，如调查确认有其他直接调用方，再加入对应测试；不为了凑流程运行无关用例。
4. 执行 `pnpm build`，随后完成受影响区域的真实浏览器及 Windows 启动器验收。
5. 对方案文档检查结构、链接、章节引用及 `git diff --check`；提交前检查暂存差异。

组件用例覆盖：

- 社区贡献者卡片位于特别鸣谢之后、技术栈之前，感谢文案和指定图片地址正确。
- 初始加载不隐藏感谢文字；成功后显示图片；失败后不显示破图，并提供重试。
- 重试后能够成功，重复触发不会产生并行轮次；旧轮次事件不改变当前结果。
- 20 秒超时后可重试；成功或失败会释放对应等待计时器，卸载后计时器与迟到事件不写回。
- 缓存命中也能进入成功状态，原文档按钮的链接和外部打开方式继续通过。

真实浏览器与启动器验收覆盖本卡片及直接相邻区域：

- Classic / Folia、亮暗主题，以及有代表性的背景、透明度和模糊设置，检查文本、按钮、边界和焦点。
- 默认窗口、最小允许窗口 960×600、放大窗口；确认图片无拉伸、无裁切、无横向溢出，仍能滚动到技术栈和法律信息。
- 正常联网加载、受控慢响应、失败与重试，确认其他卡片可正常操作。网络异常通过测试拦截模拟，不修改真实第三方服务。

- 至少检查中文和一份较长译文，其他语言核对键、语义及可访问文案完整性。

Vitest/jsdom 的事件验证不作为真实尺寸和滚动验收证据；报告分别说明静态检查、组件测试、浏览器布局和真实启动器结果。
