# 添加账户使用单一弹窗切换步骤实施方案

日期：2026-10-25。

状态：用户已确认实施，单弹窗代码调整完成；按用户“不再测试”的指令未执行测试、类型检查、构建或真实界面验收。

关联问题：[ECLTeam/EuoraCraft-Launcher#63](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/63)。

## 1. 目标与当前原因

选择离线账户、Authlib 外置登录或插件登录后，登录方式选择框不应继续显示在表单下方。添加账户流程只使用一个 Modal，由当前步骤决定标题、图标、内容和操作。

当前 `AddAccountModal.vue` 在选择框内嵌套表单 Modal，并让微软授权 Modal 关联选择框为父级。打开新步骤时，选择框仍为可见父窗口；全局弹窗栈按父子契约保留它为背景，因此底层仍可看见。

问题应在账户流程内解决，不修改公共 Modal 或全局弹窗栈的父子展示规则，避免影响其他正常的嵌套弹窗。

## 2. 单一弹窗与步骤归属

- `AddAccountModal.vue` 只保留一个 Modal，并继续使用调用方传入的 `parentId`，正确归属账户管理页面。
- 以明确的当前步骤表达“选择方式 / 账户表单 / 微软授权”，替换控制嵌套弹窗的 `showAccountFormModal`。选中的账户类型继续由账户流程维护，不在多个组件间复制。
- 选择离线、Authlib 或插件登录后，直接替换当前 Modal 的标题、图标和正文，不新增遮罩或弹窗栈条目。
- 表单步骤提供“返回”按钮，回到登录方式列表；保留同一次添加过程中的输入。返回列表不会触发整个流程重新初始化。
- 右上关闭与 Esc 结束整个添加流程；再次从账户管理打开时回到选择方式列表，按既有规则初始化表单。
- 提交过程中禁止返回、关闭和重复提交；失败后保留当前表单，允许重试。新增账户成功后关闭整个添加流程。
- Authlib 的角色选择也是当前弹窗中的内容步骤，不再新增窗口。插件登录沿用现有字段和提交逻辑。

## 3. 微软授权内容复用

- 当前 `MicrosoftLoginModal.vue` 只有添加账户流程一个生产调用方。将其改为只展示授权内容的 `MicrosoftLoginPanel.vue`，由 `AddAccountModal.vue` 的唯一 Modal 承载。
- 移除原组件的 Modal 包裹、`visible` 和 `parentId` 属性，保留授权码、状态、阶段、错误、复制和浏览器操作的既有输入与事件。
- 授权取消和打开浏览器等操作放入唯一 Modal 的相应操作区；复用现有文案和处理函数。对应样式、组件名及测试文件同步更名，不保留废弃 Modal 转发入口。
- 授权准备期间阻止再次选择其他方式；只有实际准备成功后进入授权内容。准备失败保留选择页，允许重新发起。
- 授权过程继续由现有账户 composable 和后端维护，不修改认证协议、凭据、轮询或账户保存契约。
- 取消微软授权时先调用既有取消流程，结束等待后回到选择方式；取消失败明确提示，不误报已结束。关闭整个添加流程或退出所属页面时，沿用既有资源释放路径。
- 异步准备和取消的响应不得在整个添加流程已关闭或再次打开后切换新流程的步骤；在账户流程层使用请求代次或已有状态约束防止旧响应回填。

## 4. 焦点、布局和文案

- 保持现有主题、弹窗宽度与表单间距；移除底层选择框后不依赖 CSS 隐藏或覆盖旧弹窗。
- 进入表单后在 DOM 更新完成时聚焦首个适用输入；返回列表时聚焦对应登录方式按钮；整个流程关闭后继续由公共 Modal 恢复外层触发按钮焦点。
- 返回和关闭的可访问名称优先复用现有六语言文案；如确需新文案，六语言同步补齐。
- 保留前次已实现的 UUID 框内预览、自定义 UUID 校验、默认皮肤选择、账户图标和错误提示。
