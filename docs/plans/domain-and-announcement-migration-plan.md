# 官网域名迁移与公告数据修正实施方案

状态：用户已确认开始实施；域名与邮箱迁移、自动检查及 Windows 桌面验收已完成。

## 目标与选定方案

将项目中使用旧域名的官网、文档站、公告 API 链接迁移到 `euora.cn`，项目作者邮箱改为用户指定的 `contact@euora.cn`。修正公告源中的无效结束时间，让当前公告能够正常显示，保留启动器已有的日期校验、时间范围过滤和缓存行为。

已比较的方案：

1. 修正公告数据并迁移域名和邮箱：保留现有校验，永久公告使用 JSON `null`。用户已选择此方案。
2. 迁移域名和邮箱，同时让客户端忽略无效结束时间：能够容忍错误数据，但会掩盖公告配置错误，不采用。

## 调研结论

2026-10-10 已检查主仓库与各子模块。旧域名实际出现于主仓库 `README.md`、`pyproject.toml`、`ECL/host/info_card.py`，以及前端子模块 `src/config/urls.ts`。Core 与 Florolding 没有对应域名引用。

新官网 `https://www.euora.cn`、文档站 `https://docs.euora.cn`、公告接口 `https://api.euora.cn/raw/ECLTeam/EuoraCraft-Launcher.API/main/notice.json` 均已返回 HTTP 200。

“暂无公告”的直接原因是公告源唯一启用条目 `maintenance-20260805` 的结束时间无法解析。最初读取到 `9999-99-99T99:99:99+99:99`；随后源仓库与新 API 均返回字符串 `"null"`。两种值都会使 `InfoCardManager._normalize_announcements` 跳过该条目，实际规范化结果均为零条公告。

永久公告的正确格式为 `"end_at": null`，其中 `null` 是 JSON 空值，不能加引号。当前解析器已经支持此格式，无需更改生产代码的校验逻辑。

## 实施步骤

1. 复核主仓库、前端子模块与原始本地 main 的工作区状态，保护已有文件及无关改动。
2. 为本次任务创建独立 `codex/` 分支，修改主仓库与前端中的域名、徽章及邮箱。

4. 使用固定时钟验证目标公告已经到达开始时间，并可在 `end_at: null` 时返回给前端；验证字符串 `"null"`、畸形日期、未来公告、已过期公告仍按原规则处理。

## 影响与完成边界

客户端改动影响文档入口、公告获取地址、README 和项目作者元数据，不影响实例启动、账户、联机或其他资源接口。公告修正影响所有使用该公告源的客户端。

公告仓库的本地提交在发布之前不会改变线上内容。发布后若 API 有代理缓存，必须以新 API 实际返回 JSON 空值为准；启动器还会在既有 300 秒刷新窗口内复用公告结果，桌面复验可重新启动隔离测试实例。
