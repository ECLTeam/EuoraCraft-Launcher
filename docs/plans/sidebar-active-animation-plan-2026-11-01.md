# 侧边栏激活样式与切换动画实施方案

日期：2026-11-01  
状态：待用户审阅确认

## 目标与现状

移除菜单激活项的描边，保留左侧激活竖条，并在切换菜单时让激活背景和竖条一起平滑移动。文字和图标颜色随激活状态渐变，继续使用现有主题颜色和动画变量。

当前 Classic 使用菜单项自身的背景、内描边和伪元素竖条；Folia 使用可移动背景，隐藏竖条。现有定位只匹配内置菜单，插件路由未纳入；插件菜单在侧栏折叠时本来就不可见。侧栏还支持插件插槽和可滚动导航，定位需随实际布局变化更新。

## 选定方案

1. Classic 和 Folia 共用一组导航区内的激活背景与竖条。去除激活项描边和各行重复绘制的激活背景、伪元素竖条；两种皮肤保留各自符合主题的背景颜色，竖条使用主题强调色。两者均不拦截点击或键盘操作。
2. 路由切换时，根据当前可见菜单项的实际位置与高度同步更新背景和竖条，两者使用一致的时长及缓动。首次定位或从无可见目标恢复时直接定位后显示，避免从错误位置滑入；快速切换以最后一次有效路由为准。文本与图标的颜色、透明度使用已有过渡。
3. 保持现有内置子页面对应父菜单的规则；展开状态下支持可见插件菜单的精确匹配。折叠时插件项本身不可见，插件路由不显示悬空的激活指示；展开后恢复到对应项。没有匹配项时隐藏两者。
4. 路由、插件列表、侧栏展开状态或导航区布局变化时重新定位；处理插槽内容变化、窗口尺寸变化和滚动容器坐标，并在组件卸载时清理观察器、事件与待执行任务。定位直接关联实际菜单元素，避免将未经处理的路径拼入 CSS 选择器。
5. 响应 `prefers-reduced-motion: reduce`，关闭滑动和相关颜色过渡，状态仍立即更新。保留清晰的键盘焦点，激活样式和焦点样式各自可辨。

## 修改范围和步骤

1. 在 `frontend/src/components/layout/SideBar.vue` 整理激活目标选择及定位逻辑，合并重复定位调用，处理插件路由、目标缺失、动态布局、折叠切换与资源清理；不改变导航行为或插件协议。
2. 在 `frontend/src/styles/components/layout/SideBar.css` 实现共用的背景、竖条和动画，删除原有描边及重复激活绘制；在 `frontend/src/styles/folia.css` 调整与其冲突的皮肤覆盖，保留 Folia 的主题表现。
3. 更新 `frontend/src/components/layout/SideBar.test.ts` 和现有 Folia 样式相关测试，覆盖内置与插件目标、无目标及折叠展开后的状态、快速切换和卸载清理等适用行为。DOM 测试可模拟布局测量；实际动画位置和视觉效果通过真实界面验收。

## 验证计划

本次涉及共享导航及 Folia 全局样式，按项目规范进行前端全量验证：

- 在前端执行 `pnpm check`，覆盖格式、ESLint、类型检查和全量 Vitest；执行 `pnpm build`。
- 启动实际启动器，在 Classic / Folia、亮 / 暗模式及相关背景、透明度、模糊设置下检查激活背景、竖条、可读性和键盘焦点。
- 在默认、最小允许及放大窗口检查侧栏展开与折叠、导航滚动、窗口缩放，确认竖条与背景贴合目标且不遮挡操作；检查插件项出现、消失与折叠时的表现。
- 检查首次显示、跨多个菜单项切换、快速连续切换和系统减少动态效果；确认导航结果、加载和焦点不受影响。
- 按项目规范执行主仓库集成验收并检查相关 diff；记录实际环境限制和未完成项，不将模拟测试替代真实界面验收。

## 风险与边界

动态插件插槽可能改变导航项的位置；实现需要在布局变化后重新测量并避免观察器触发循环。插件项在折叠态不可见，故该状态不显示插件路由的激活标记。此方案只调整侧边栏激活视觉与定位，不新增设置项，也不改变顶部导航。
