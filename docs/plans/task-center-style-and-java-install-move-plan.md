基线：主仓库 `180b1d1`、前端 `a247a59`；本次调研时两个工作区干净。上一项 Java 管理页卡片底板已完成，本次范围是任务中心、标题栏任务入口及 Java 安装提交失败。

## 1. 已核实的问题

| 问题 | 当前实现及证据 |
| --- | --- |
| 任务名称显示 `operations.java_install` | `applicationOperationStore` 查询 `operations.<kind>`；六语言的 Java 名称却放在 `operations.kinds.<kind>`，日志也记录了缺失翻译。 |
| 进度显示过长小数 | 任务卡片和实时详情直接拼接 `task.progress`。共享进度条已取整，但旁边文字没有取整，导致文字与进度条不一致并挤压布局。 |
| 顶部下载数量突出、任务卡片松散 | 标题栏计数绝对定位覆盖图标；任务卡片固定进度列，取消按钮和下载统计各占一行，运行中还预留了移除按钮列。 |
| Java 安装失败 | 两次日志均失败于 `JavaInstaller._commit` 中的 `unpacked.rename(plan.install_path)`，阶段已到安装提交，下载、解压及 Java 探测已经完成。 |

同一 Java 管理目录下，用独立命名的诊断目录实际完成了「创建 → 从临时目录移动到 installed → 移回 → 清理」；没有移动或删除现有 Java。管理根目录、`.staging` 和 `installed` 的权限规则一致。失败时的临时目录已经清理，目标安装目录没有生成，因此现在无法直接核对当时的占用句柄。

现有证据不支持断言下载源故障，也不能仅凭 WinError 5 断言某个杀毒软件在占用。Windows 的重命名会受到打开句柄共享方式与权限限制；当前代码只尝试一次，没有短时重试和对应领域错误。参考：[Microsoft CreateFile 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea)、[MoveFileEx 文档](https://learn.microsoft.com/windows/win32/api/winbase/nf-winbase-movefileexa)。

## 2. 已选择的界面方案

此前比较紧凑卡片与任务列表、选中详情布局；用户选择前者，保留现有网速详情卡及展开失败详情的交互。

- 顶部任务入口改为图标加内置计数，保持与主题、最小化、关闭按钮在同一高度；没有活动任务时只显示图标，多位计数最多显示 `99+`，不与图标重叠或超出按钮。
- 任务卡片第一行左侧显示名称、状态和当前阶段，右侧集中取消或移除操作；正文名称允许收缩、长名称省略，完整名称可查看。
- 第二行放置整行进度条，百分比占固定宽度；数字显示为 0–100 的整数，例如 `5.506119...%` 显示为 `6%`。未知进度继续使用不确定进度状态，成功为 `100%`。
- 下载统计放在紧凑的同一信息行，操作和统计不再分别制造空行；失败详情允许长文字换行。
- 运行中使用适度的主题强调，卡片底色、边框、圆角沿用现有主题变量；检查任务中心顶部工具栏、滚动和首屏间距。
- 实时网速详情沿用当前结构，进度文字使用与任务项一致的格式，不改变任务查询、取消与终态语义。

## 3. Java 安装失败修复边界

保留现有「下载 → 哈希校验 → 解压 → 探测 → 原子移动 → 登记」流程，在 Java 安装领域内处理目录移动。

1. 为目录移动增加私有辅助方法，只对 Windows 已知的访问拒绝、共享冲突或锁冲突进行有限重试，例如初次尝试加 5 次重试、累计等待不超过约 3 秒；其他平台和其他错误立即结束。
2. 重试只重复当前目录移动，不重复网络下载、解压或登记。继续核对来源、目标及父目录边界，不覆盖未知目录，不采用复制后删除的替代流程。
3. 重试耗尽后转换为稳定的 Java 领域错误及中文说明，例如安装目录被占用或没有移动权限；错误堆栈在现有执行边界记录，页面主状态不直接显示包含完整个人路径的 Python 异常字符串。
4. 整理 `_commit` 的回滚边界，明确记录本次是否真正移动了新目录、是否移动了旧备份。仅回滚本次拥有的变更；新目录尚未移动成功时，不操作偶然出现的目标目录。
5. 登记失败仍恢复本次安装目录和旧版本；备份及恢复移动同样使用有限处理。恢复仍失败时保留备份并明确报告回滚未完成，不将旧版本备份当作普通垃圾删除。
6. 最终提交继续使用现有取消互斥边界。等待与失败不冒充安装成功；不修改全局或实例 Java 选择，不提升权限或变更系统权限配置。

如果真实 Java 25 复验发现持续权限拒绝或本程序持有未释放句柄，继续定位并修复已确认的原因，不把有限重试本身当作已解决的证据。
