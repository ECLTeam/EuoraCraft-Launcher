# LittleSkin 云端衣柜缓存与工具栏调整方案

2026-11-07。已选方案 A，待审阅实施。关联 [重复请求 #125](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/125) 和 [衣柜布局 #123](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/123)。

## 目标与现状

- [云端衣柜](../../frontend/src/features/accounts/components/LittleSkinClosetPanel.vue) 每次进入、切换皮肤与披风或翻页时，都会重新读取角色管理状态和目标列表。材质图片已经有缓存，本轮处理列表元数据和角色管理状态。
- [衣柜顶部](../../frontend/src/features/accounts/components/WardrobeModal.vue) 让分类切换与操作按钮共享一行。约 960×600 的 Classic 窗口中，四个分类出现时，选项、导入和下载会整体折到左侧下一行。对照同一衣柜的本地皮肤、披风、官方披风和 LittleSkin 云端入口，统一操作位置与对齐方式。

## 缓存和刷新规则

| 操作 | 预期行为 |
| --- | --- |
| 首次进入或缓存过期后再次查看 | 读取需要更新的角色状态或当前列表。列表按账户 ID、皮肤或披风、页码区分，角色管理状态按账户 ID 单独缓存。 |
| 60 秒内返回已看过的列表 | 从内存恢复页面数据，包括成功返回的空列表。来回切换类别、翻回已读页或关闭后重开都可命中缓存。命中时不发出对应 IPC，不闪现加载遮罩。 |
| 查看另一页或另一类别 | 复用仍有效的同账户管理状态，只读取未缓存或过期的目标页。切换账号时只显示目标账号的数据。 |
| 手动刷新 | 重读当前账户的管理状态与当前页，并使该账户其他已缓存页失效，重新访问那些页时再读取。失败时明确显示可重试状态。 |
| 穿戴或清除成功 | 用服务端返回的角色更新缓存和已穿戴标识，保留该账户已缓存的衣柜列表。下载材质只更新本地衣柜。 |
| 写入结果未确认 | 使该账户管理状态失效，提示刷新核对。不会自动重发写请求。 |
| 账户删除、重新登录或补充授权成功，或服务端明确拒绝授权 | 清除相关账户的管理状态和各页缓存。补充授权完成后重新读取当前页。网络、限流等读取失败不写入成功缓存。 |

复用 [现有 QueryClient](../../frontend/src/app/queryClient.ts) 的 60 秒新鲜期和同键请求合并，以及 [共享读取协调器](../../frontend/src/app/data/refreshCoordinator.ts) 的失效与迟到响应保护。数据仅存在当前进程的前端内存中，沿用现有缓存回收配置，保留后端现有授权检查和写入校验。

## 工具栏布局

1. 第一行左侧放账号标签与选择框，右侧放当前来源的常用操作和「更多」。本地皮肤与披风保留「导入 PNG」，官方披风保留刷新。「更多」提供衣柜选项，本地来源可在其中下载当前材质。
2. 第二行专用于切换 LittleSkin 云端、本地皮肤、本地披风、官方披风。Classic 保留按钮组，Folia 保留分段样式。账号选择框可随可用宽度缩小，过长名称可查看全名。极窄或长译文时优先将动作整组靠右换行，分类行独立布局。
3. 云端皮肤、披风切换同行保留刷新，下载当前材质与重置皮肤或移除披风收进该行的「更多」。继续使用现有图标、Naive UI 菜单、六语言文案、可访问名称和操作禁用状态。保持键盘打开菜单、选择动作和关闭后恢复焦点。

## 实施步骤与验收

1. 在账户领域的 API 读取边界接入 LittleSkin 专用查询键和缓存生命周期。只缓存已校验的响应，在穿戴、清除、授权完成和删除的现有操作入口同步失效或更新缓存，即使发起操作的面板已经卸载。避免改变共享 QueryClient 默认值、账户凭据流程和 IPC 契约。
2. 在 `LittleSkinClosetPanel.vue` 中区分普通加载与显式刷新，复用同账户查询，保留页面切换、缩略图和预览的请求归属保护。在两个衣柜组件中重新安排工具栏和菜单，沿用现有动作入口和防重复提交约束。
3. 在现有账户 API 和衣柜测试中验证请求次数、60 秒过期、并发同键读取、账户隔离、返回旧页、成功空列表、手动刷新，以及写入、授权和删除后的更新。覆盖失效前已发出的旧请求、查询失败重试及穿戴结果未确认时无自动写重试。
4. 按 [项目规范第 6 节](../../AGENTS.md#6-测试与验收) 执行改动文件的 Prettier、ESLint、设计检查、类型检查、构建和相关 Vitest。用真实浏览器对照各来源，覆盖 Classic / Folia、亮暗、960×600、默认和放大窗口、代表性背景及长译文。检查账号切换、导入、下载、刷新、菜单焦点和禁用状态，并在模拟请求日志中核对缓存命中。若实施范围涉及共享缓存默认行为、应用启动、账户凭据或 IPC 契约，按项目规范扩大测试范围。
5. 验收通过后先提交前端，再更新主仓库指针，提交关联 #123 和 #125。
