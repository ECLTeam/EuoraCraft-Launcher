# 启动器字体分区设置实施方案（已实施）

## 目标与验收

- 修复字体选择下拉框越过主窗口边缘的问题；长字体名称在选择框与菜单中截断显示，完整名称仍可查看。
- 预设及自定义字体选项的名称用该字体绘制，选择时可直接预览字形；字体缺失时按原有后备字体显示。
- 支持输入本机已安装字体的名称，作为自定义字体选项保存并立即应用；不导入字体文件。
- 提供四处独立设置：启动器界面、侧边栏、实例终端输出、启动器日志输出。界面字体直接显示，后三处收在“高级字体设置”折叠区；每处可以单独选预设或自定义字体，也可以恢复默认/继承关系。
- 旧配置中的 `ui.theme.appearance.font_family` 继续作为界面字体，不丢失原有设置。

## 当前项目情况

| 区域 | 当前字体来源 | 现状 |
| --- | --- | --- |
| 普通界面、侧边栏 | `--font-body`，内置 HarmonyOS Sans SC，后备 `sans-serif` | 侧边栏继承普通界面；当前“界面字体”写入 `--ecl-font-body`，主要被 Naive UI 使用，未完整覆盖普通页面文字。 |
| 实例终端输出 | `ProcessInstanceView.css` 固定 MapleMono、JetBrains Mono、HarmonyOS Sans SC 字体栈 | 与通用界面字体无关；终端输入框另用 `--font-mono`。 |
| 启动器日志输出 | `LauncherLogView.vue` 的 `--font-mono` | 默认是内置 MapleMono，后备 JetBrains Mono、Consolas、Cascadia Code、`monospace`。 |
| 字体选择器 | `AppearanceTab.vue` 中宽度不稳定的 `NSelect` | 菜单默认挂到页面外层，长名称与底部弹出位置可能越过主窗口可见边界。 |

## 方案比较与选定

| 方案 | 操作方式 | 取舍 |
| --- | --- | --- |
| A. 四处独立选择器 | 四行分别设置界面、侧边栏、终端、日志字体；各行有预设、继承/默认和“输入字体名称”。 | 区域归属明确，但设置页持续占用四行。 |
| B. 一个总字体选择器和折叠的高级覆盖项（已选择） | 默认只显示界面字体；展开后再配置侧边栏、终端、日志。 | 页面更短，折叠标题需标明已有多少处单独设置，避免隐藏当前状态。 |

按用户选择实施方案 B。

## 配置与默认行为

- 沿用 `appearance.font_family` 作为普通界面字体；新增 `sidebar_font_family`、`terminal_font_family`、`log_font_family`，空值表示该区域使用默认/继承字体。
- 普通界面默认 HarmonyOS Sans SC；侧边栏默认跟随普通界面；实例终端与启动器日志默认继续使用各自现有的等宽字体栈。设置一个区域不改变其他区域。
- 自定义输入仅接受字体族名称，限制长度并过滤会破坏 CSS 字体声明的控制字符。保存名称而非本机字体文件路径；在 CSS 中安全引用名称并保留后备字体。旧的非预设 `font_family` 值继续可读取与显示。
- 修改设置后立即预览并保存；清除设置时同步移除旧的内联 CSS 变量，避免看似恢复默认但旧字体仍生效。

## 实施步骤

1. 在前端外观配置类型和后端默认配置中补充三个区域字段，保留既有 `font_family` 值及旧配置兼容。
2. 抽出共享的字体选择控件：固定合适的控制区宽度、把菜单挂在主窗口容器内、限制菜单宽度与高度，对超长名称加省略与完整名称提示。通过 Naive UI 的 `render-label` 同时渲染菜单项和已选名称的字体预览。
3. 保留一行可见的“界面字体”，在其下加入可通过键盘操作的“高级字体设置”折叠区，内部放侧边栏、实例终端和启动器日志三行。折叠标题显示独立覆盖项的数量；折叠状态不影响已有配置。每处选择器提供默认/继承、现有预设和“自定义字体名称”入口；输入本机字体名称时提供即时样例，确认后保存，取消时不修改当前设置。缺失字体使用后备字体。
4. 将普通界面正文与 Naive UI 控件统一接到界面字体变量；侧边栏单独使用侧边栏变量，未设置时跟随界面。实例终端的输出及输入、启动器日志正文分别使用独立变量；审查直接写死 HarmonyOS Sans SC 的普通界面样式，将应跟随界面字体的部分改为变量，代码片段和数字等宽排版继续使用原有等宽规则。
5. 为六种语言补齐四处设置名称、高级折叠标题、覆盖项数量、默认/继承、自定义输入、无效名称提示。设置页说明保持简短，具体字体来源写在文档中。
6. 补充配置兼容、字体变量应用与重置、分区互不影响、字体预览和长名称溢出的相关测试。执行后端 `ruff check ECL tests`、`ruff format --check ECL tests` 与相关 pytest；前端执行 `pnpm check`、`pnpm build`，再用隔离数据启动 Windows 11 版本，目视验证四处设置、菜单边缘和终端/日志内容。
7. 测试通过后先提交前端子模块，再提交主仓库配置、文档与子模块指针；不推送远端。

## 风险与边界

- 系统没有安装输入的字体时，浏览器会使用后备字体；此功能不枚举系统字体，也不复制或上传字体文件。
- 某些字体缺少中文、符号或等宽字形，浏览器会逐字回退；终端默认仍保留等宽字体，以维持日志和命令输出的可读性。
- 插件自行指定的字体及系统原生标题栏文字由各自环境控制，不纳入这四处设置。

## 实施与验证记录

- 已新增共享字体选择器、自定义本机字体名称输入、字体名称预览，以及界面、侧边栏、实例终端和启动器日志四处独立字体配置。高级覆盖项保持折叠，标题显示覆盖数量。恢复默认时会移除对应 CSS 变量。
- 已补齐六种语言的设置文案；保留旧版 `font_family` CSS 字体栈，并调整普通界面、侧边栏、终端输出与输入、日志正文以及原先固定 HarmonyOS Sans SC 的普通界面文字。
- `ruff check ECL tests`、`ruff format --check ECL tests`、`pytest tests/test_config_defaults.py`、`pnpm check` 与 `pnpm build` 均通过。使用独立 `ECL_DATA_PATH` 启动 Windows 版，日志确认主窗口前端就绪且错误日志为空；窗口菜单边缘和各字体的目视效果仍需在交互式桌面上确认。

## 2026-09-26 排版与运行警告修复

用户截图显示，自定义字体输入区直接位于选择器下方，使设置行高度增加，左侧标签被垂直居中在整块输入区旁；日志中的 Vue 警告指出 `NInput` 的 `onKeydown` 同时收到了 Enter 与 Escape 两个监听器组成的数组。

| 方案 | 效果 | 取舍 |
| --- | --- | --- |
| A. 从选择框弹出编辑层（采用） | 设置行始终保持原高度；输入、操作按钮和预览集中在选择框旁。 | 需确保弹层挂到主窗口并在点击外部、取消和按 Escape 时关闭。 |
| B. 继续内嵌编辑区 | 无额外浮层，操作始终可见。 | 设置行仍会变高，难以保持与其他选项一致的排版。 |

实施：将自定义编辑区移到 `NPopover`，以选择器为定位点；合并为一个 `keydown` 处理函数。新增组件回归测试，覆盖编辑层不进入设置行布局、传给 `NInput` 的 `onKeydown` 是单个函数，以及 Enter 应用和 Escape 取消。

验证：`pnpm check` 通过（93 个测试文件通过，384 项通过、1 项原有待办），`pnpm build` 通过；使用独立 `ECL_DATA_PATH` 启动后，日志确认主窗口前端就绪、前端加载完成、无 Vue 警告，错误日志为空。由于隔离启动未进行界面点击，弹层在真实窗口中的最终视觉位置仍需人工确认。
