# 下载源优先级与失败回退实施方案（已确认实施）

## 需求与当前实现

- 设置页现有选项为“官方源 / BMCLAPI”，配置键 `download.mirror_source` 保存 `official` 或 `bmclapi`，默认 `official`。后端将该值传入版本目录、加载器目录、安装与启动流程，当前含义是固定使用该源；实例修复入口目前没有传入此配置，实际固定为官方源。
- 下载器会对同一 URL 重试，最终通过 `failed_entries` 报告失败；游戏服务不会自动换到另一源。Core 内还有版本元数据、Forge / NeoForge 安装器等直接下载，不能只改设置页标签。
- `ECL/game` 是独立子模块。它的 `FilesChecker.check_assets` 会吞掉资源索引请求异常，实施时需要处理这一错误边界，否则部分失败无法触发回退。

## 可选方案

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| A. 按请求和失败文件回退（推荐） | 元数据请求在首选源失败后尝试备用源；批量下载只对失败文件尝试备用 URL。 | 保留已成功下载的文件和安装进度；涉及游戏服务、Core API / 文件检查器及测试，改动较多。 |
| B. 整个安装或补全任务回退 | 首选源失败后，从另一源重新运行整个任务。 | 实现较简单，但会重复查询和执行部分安装步骤；Forge / NeoForge 安装器及已写入文件的重复执行风险较高。 |

推荐 A。两个设置值继续沿用现有配置，以免迁移旧配置；界面改为“优先官方源”“优先 BMCLAPI”，并说明另一源仅在可用时回退。

## 方案 A 的范围与规则

1. 首选源成功即结束，不做预先测速，也不永久修改用户偏好；同一请求最多尝试另一源一次。
2. 版本目录、加载器目录、安装中的元数据与安装器下载，在首选源的网络、HTTP 或内容解析失败时尝试另一源。来源特定的 URL 和响应格式必须交给对应源的客户端处理。
3. 安装、启动补全、实例修复中的批量文件下载，先执行现有同源重试；仍失败时按目标路径查找备用源生成的 URL，只重试失败且有不同备用 URL 的文件。已经成功的文件不得重新下载。
4. 取消、路径或参数校验错误、Java 安装器执行错误、磁盘写入错误，以及没有备用地址的第三方资源，不触发换源。两源均失败时保持明确的失败结果，并记录尝试过的来源；日志不记录账户数据。
5. 官方源与 BMCLAPI 对部分资源会使用同一第三方地址（例如没有镜像覆盖的服务）。这类资源仍由原地址负责，不宣称具备双源保障。

## 具体改动

1. 在设置页及六份语言文件中将选项说明改为“首选 + 失败回退”；保留 `mirror_source` 字段、`official` / `bmclapi` 值以及默认值。
2. 在游戏服务增加统一的首选 / 备用源顺序和回退判定，供版本目录、加载器目录、安装、启动补全、实例修复共用；`ECL/api/workspace.py` 的修复入口需读取下载配置。显式指定的 `source` 也表示首选源。
3. 为 Core 的元数据与直接下载建立按来源执行的请求边界；对 `FilesChecker.check_assets` 中被吞掉的网络失败补充可观察结果。若改动 `ECL/game`，先在该子模块提交，再由主仓库提交指针。
4. 批量下载结束后，仅针对 `failed_entries` 按目标路径获取备用 URL 并再次下载；核对完成文件，保持现有进度、取消和任务清理语义。
5. 新增回退路径测试：两种首选顺序、首选成功、首选失败后备用成功、两源失败、部分文件失败、无备用 URL、取消、非网络错误，以及 Windows / POSIX 路径匹配。

## 验收与提交

- 六种语言的设置页均显示“优先官方源 / 优先 BMCLAPI”的语义；旧配置无需迁移。
- 模拟首选源不可用时，目录查询与可替代文件自动使用备用源；只重试失败文件，成功文件不重复下载。
- 运行子模块相关测试、主仓库 `ruff check ECL tests`、`ruff format --check ECL tests` 和相关 `pytest`；前端运行 `pnpm check`、`pnpm build`，再实际启动启动器验证设置与下载流程。
- 分别检查并提交涉及的子模块、前端及主仓库变更；不推送远端。

## 实施与验证记录

- 保留 `download.mirror_source` 的原有值和默认值；设置页六种语言均改为“优先官方源 / 优先 BMCLAPI”及失败回退说明。
- 游戏服务通过双客户端对版本清单、加载器元数据、资源索引和 Forge / NeoForged 安装器请求回退；Core 资源索引失败会向上报告。批量文件下载只重试失败且有不同备用 URL 的文件，本地写入失败不换源；实例修复读取全局首选源。
- 离线测试覆盖两种优先顺序、首选成功、双源失败、无备用 URL、部分文件失败、启动补全和实例修复。完整后端测试 575 项通过、1 项跳过；前端 `pnpm check` 91 个测试文件通过，`pnpm build` 通过。
- 使用隔离数据目录实际启动桌面版：两个优先选项和说明正常显示，选择“优先 BMCLAPI”后配置保存为 `bmclapi`，随后正常退出。
- 完整后端回归最初发现 `ECL/services/dev_channel.py` 已有两处单行 docstring 不满足架构检查；仅调整了这两处文档格式，复测后全套通过。该整理单独提交。
