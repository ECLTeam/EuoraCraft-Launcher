# 配置分区对象校验修复

关联问题：[#109](https://github.com/ECLTeam/EuoraCraft-Launcher/issues/109)。

用户已要求修复，并明确此类小问题只做必要的定向测试。

## 范围与实施

所有当前可写分区均使用 JSON 对象。现有 `SettingsUpdate.data` 接受任意 JSON 值，
导致 `ui` 等分区可以被数字、字符串、列表、布尔值或空值替换。

1. 将 `SettingsUpdate.data` 收窄为 JSON 对象，使用现有请求校验返回 `INVALID_REQUEST`。
2. 在 `ConfigStore.save_config` 的分区白名单检查后拒绝非对象值，避免内部调用绕过校验。
3. 保留对象内部字段、原子写入、同值跳过和专属分区校验的现有行为。
4. 不扫描或改写已有配置，不涉及前端、迁移或自动恢复逻辑。

## 验证与交付

- 回归覆盖全部八个可写分区拒绝数字，及 IPC 拒绝五类非对象值。
- 每项检查拒绝后内存、文件字节和变更事件均不改变；复用现有正常保存与同值跳过用例。
- 只检查修改文件的 Ruff、格式及 Git 差异，不运行全量测试或界面构建。
- 独立提交到本地 `main`，通过 `Refs #109` 关联；远端交付前保持 Issue 打开。

## 执行结果

- 修复前新增回归出现 13 项失败，现有正常保存用例通过；修复后选定 16 项全部通过。
- 定向执行配置类型、同值保存及设置 IPC 用例，其余 179 项未运行。
- 四个修改或新增 Python 文件的 Ruff 和格式检查通过，`git diff --check` 通过。
- 按用户要求采用局部校验修复的定向验证，没有运行全量测试、构建或额外界面验收。
