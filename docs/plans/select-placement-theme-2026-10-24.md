# 下拉菜单边界与激活颜色修复

用户已授权无人值守实施、推送与检查远端构建；本方案无需再次审批。

## 现状与选择

- Naive UI 已提供按窗口空间自动翻转及左右对齐。全局菜单 `min-width: max-content` 与下载页泄漏的 200px 最小宽度使菜单大于定位容器，破坏边界判断。
- 版本设置的短选择框需要允许菜单按内容展开；长路径仍需限宽并保留滚动和截断。
- 版本侧栏使用公共 `--ecl-primary-alpha`，该变量目前固定为蓝色。
- 采用修正样式边界并复用现有定位的方案；不引入另一套弹层定位框架，也不逐个指定固定展开方向。

## 实施

1. 删除全局菜单强制最小宽度，统一限制菜单最大宽度与列表高度，使定位容器和可见菜单尺寸一致，长列表在菜单内滚动。
2. 版本设置中的选择框使用 Naive UI 的内容宽度模式，由原定位逻辑根据可用空间翻转、对齐。
3. 公共主题高亮与焦点颜色由当前主色 RGB 派生，亮暗主题保留原透明度。
4. 新增真实浏览器回归，覆盖版本设置所有下拉框、四个边角、长选项、列表末项、滚动与窗口变化；切换两套皮肤、亮暗主题和不同主色检查激活底色。

## 验收与交付

- 公共样式/主题变量变更按 AGENTS.md 第 6 节执行前端 `pnpm check` 与 `pnpm build`。
- 在真实浏览器及 Windows 启动器中验收最小、默认及放大窗口，检查背景、透明度和模糊组合。
- 文档独立提交；前端提交后更新主仓库指针。保留现有 Core 指针、桌面文件及简体中文文案的未提交改动。
