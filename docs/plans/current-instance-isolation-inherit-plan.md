## 目标

仅将日常源码目录中的 `fabric-loader-0.19.3-26.2` 实例改为“继承全局隔离策略”，使右键打开崩溃报告等数据目录与继承后的启动目录一致。

## 已核实的现状

- 日常项目目录：`E:/Projects/EuoraCraft-Launcher/EuoraCraft-Launcher`。
- 全局 `ECL_data/setting.json` 中的 `game.instance_isolation_policy` 当前为 `all`。
- 当前实例的 `.minecraft/versions/fabric-loader-0.19.3-26.2/.ecl/settings.json` 含旧字段 `isolated: false`，未设置 `isolationMode`。
- 后端隔离解析中，实例独立设置优先于全局策略；该旧字段因此让当前实例使用共享数据目录 `.minecraft/versions/`。
- 实例列表右键的“崩溃报告文件夹”经过后端隔离解析，并打开最终数据目录中的 `crash-reports`。已验证真实 API 与服务组合的 6 个场景，未复现绕过隔离配置。
- 此实例配置被 Git 忽略，属于本地用户数据，不应纳入源码提交。
- 当前共享存档和模组目录均为空；实例自己的存档目录有 1 个条目，日志目录有 16 个条目。实例自己的 `crash-reports` 尚不存在。

| 方案 | 操作 | 后续行为 |
