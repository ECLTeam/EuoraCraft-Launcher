# 前端清洗与版权文件头实施方案

日期：2026-11-01

## 目标和边界

清理经核实无用的前端文件、配置和依赖，修正失实或无效的注释与文档，并为前端自行维护的源码加入统一版权和职责说明。保留应用行为、用户数据、第三方版权与现有未提交改动。前端是独立子仓库，实施前重新检查两个仓库状态，逐文件合并现有工作，不使用重置或清理命令。

## 已发现的候选项

- 仓库跟踪了 `tsconfig.app.tsbuildinfo`、`tsconfig.node.tsbuildinfo`、`vite.config.d.ts`，但 `.gitignore` 已排除它们，当前 TypeScript 缓存配置位于 `node_modules/.cache`。核实 CI、构建与生成方式后移出版本管理；本地生成物可以保留。
- `MAPPING_TABLE.yaml` 是主题重构记录，尚未确认是否仍需归档；核对文档引用及当前用途后决定保留或删除。
- `jsrepo.config.ts` 和 `jsrepo` 依赖提供组件获取配置，不能仅因无运行时引用而判为无用；核对现有开发工作流、仓库历史和组件来源后再决定。删除依赖或更改锁文件须执行依赖治理检查。
- `components.d.ts` 与 `src/auto-imports.d.ts` 是 Vite 插件生成的声明，保留生成机制和现有用途，不添加手写头部。
- `README.md` 指向前端目录中不存在的 `CONTRIBUTING.md` 与 `BACKEND_API.md`；查明现行文档后修正链接或说明。
- `src/styles/folia.css` 的主题编辑器注释疑似过时；对照实际主题实现更新，保留解释约束和原因的有效注释。

上面只是初步候选，不代表其他文件已确定无用。对外部引用、动态路径、自动发现、打包入口、脚本、CI、文档和测试均做交叉检查；无法证明无用的文件与配置保留，并在结果中列出。图片、字体、第三方资源与用户数据不因静态搜索无引用而删除。

## 版权和注释规则

对项目自行维护、支持注释的生产 `.vue`、`.ts`、`.tsx`、`.js`、`.mjs`、`.css`、HTML 文件，以及相关维护脚本和配置，按各格式合法语法在文件开头加入简短文件头。Vue 使用 HTML 注释，TS/JS/CSS 使用块注释；带 shebang 的脚本保留 shebang 为首行。测试按相同版权信息处理，但不强制公开接口清单。示例：

```text
EuoraCraft Launcher
ECLTeam © 2026 GPL-3.0 License
https://github.com/ECLTeam/EuoraCraft-Launcher
文件作用：描述该文件的实际职责。
```

职责说明按文件实际内容编写，不批量填充空泛文字；确有稳定对外接口时可列出，不强制所有组件列接口。以仓库现有 GPL-3.0 LICENSE 为准；保留原有第三方作者、许可证和来源，不将第三方文件标为 ECLTeam 所有。自动生成文件、锁文件、JSON、二进制资源不插入非法或易被生成器覆盖的注释。若来源不明，先核实，不能确认归属则保留原样并报告。

逐项检查现有注释：修正与当前代码矛盾的描述，删除无信息的重复说明和已失效的注释代码，保留必要的技术原因、许可、工具指令及边界说明。不为格式统一改写业务逻辑。

## 实施步骤

1. 记录主仓库与前端工作区状态，检查相关规范和子仓库历史，梳理生产入口、动态加载、工具链、CI、资源及文档引用。
2. 逐项列出清理对象及证据，处理已证实无用的文件、配置和依赖；保留不确定项。同步修正直接受影响的文档和引用。
3. 按上述范围和归属逐文件加入版权头、修正注释；保持现有未提交修改并审查差异，避免修改用户可见行为。
4. 按最终实际差异执行下述验证；若发现需改变功能、接口或删除无法确认用途的内容，先停下说明，再确定后续范围。

## 验证与交付

- 检查前端和主仓库 `git diff --check`，审查每项删除依据、文件头语法、第三方声明、文档链接和生成文件差异。
- 本次覆盖范围跨前端全仓，执行 `pnpm check`；涉及配置、依赖、模板或运行代码时执行 `pnpm build`，并按照主仓库第 6.3 节启动真实启动器验收受影响流程。若实际仅为不改变运行行为的文档和注释，则按规范采用定向检查并说明。
- 若更改依赖或锁文件，按第 6.2 节执行生产及全部前端依赖治理审计和例外检查；若更改公共界面行为或可访问性边界，补充相应自动及真实界面验收。
- 失败不得宣称完成；报告执行结果、未能完成的检查及原因、保留的不确定项和子模块状态。提交、推送和发布按现有项目规范及用户授权执行。
