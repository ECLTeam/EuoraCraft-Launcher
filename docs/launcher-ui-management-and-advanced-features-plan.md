### 2.1 必须一并处理的关联问题

1. **统一启动设置解析**：仅补实例设置控件，会使列表启动、联机启动、命令行和快捷方式使用不同配置。
2. **修复单实例启动请求转发**：仅生成包含 `--launch` 的快捷方式，在启动器已经运行时不能完成实例启动。
3. **明确原理图下载能力**：当前 Download 分类和在线资源提供者均没有原理图能力，不能将原理图搜索跳转到模组分类冒充支持。
4. **目标传递不能依赖页面首次挂载**：下载页面已经打开时，切换 query 也应切换分类并处理新目标；实例、存档列表未加载完成前不能提前清掉目标。
5. **管理操作不能伪造资源状态**：资源包、光影包及数据包的实际启用方式不同；已有列表的 `.disabled` 推断不足以支撑新增“批量启用”承诺。
6. **下载取消必须结束真实下载**：从前端任务队列移除条目不等于停止下载器；需要取消、资源清理及最终状态的完整链路。

## 4. 实例管理界面与资源管理

### 4.1 R01：模组列表

**目标结构**：左侧图标，中间名称与辅助信息，右侧状态及操作。参考 `InstalledInstanceList.vue` 的行间距、悬停、圆角、文字层级和响应式处理，保留模组自己的字段和操作。

- 去掉独立的多列表头，使用约 32px 图标与紧凑行布局；最终行高以实际实例列表对比验收。
- 首行显示本地化／展示名称；次行优先显示原名、版本、作者，缺失信息省略，文件名可在次行或提示中查看。
- 加载器及兼容提示使用已有徽标，不占固定大列；状态开关、在线详情、删除操作放在末尾。
- 禁用模组使用一致的次要文字样式，同时保留可读性和明确状态。
- 保留搜索、状态筛选、计数、添加模组、打开目录、启用切换、删除及原有拖入能力（如所在入口支持）。
- 窄宽度允许辅助信息折行，操作按钮不压缩成无法点击的尺寸；长文件名、长作者、无图标有明确回退。
- 复用视觉规则而非将模组强行转换为实例业务模型。若提取通用行组件，组件只处理布局与插槽，不承担启动／模组逻辑。

### 4.2 R02：四类资源的管理模式

初始状态为普通模式：无复选框、无批量删除区；仍有安装、刷新、目录、单项操作及适用类型的预览／启用控件。已实现的资源包包内图标保持使用。

点击工具栏“管理”后：

1. 四类资源统一显示行复选框、已选数量、“全选当前结果”和批量删除按钮。
2. “管理”变为“完成”。点击完成，清空选择并回到普通模式。
3. 全选只选择当前筛选结果。更改搜索条件后保留仍存在的选择，数量显示总选择数；若有隐藏选择，确认删除时明确数量。
4. 切换实例、资源类型、数据包目标存档或关闭弹窗时，退出管理模式并清空选择；刷新后剔除已不存在的资源 ID。
5. 点击行本身不执行删除；复选框与启用开关、原理图预览等操作互不触发。
6. 批量删除使用现有确认交互，提交前再次校验类型、实例／存档目标及资源 ID。
7. 后端返回逐项成功／失败结果；部分失败时刷新成功项，保留失败项选择并说明原因，不把部分成功当成全成功。

**首版批量能力**：选择、全选、批量删除。普通模式单项删除继续可用；已有导出能力保持对应资源类型的原本语义。批量启用／停用不是默认推荐项：光影通常只能选择一个，数据包依赖存档配置，原理图没有启用状态，必须先对齐真实状态才能扩展。

**改动点**：资源组件的模式状态与选择状态、工具栏及行布局、资源 API 的批量删除结果类型和错误处理。新增类型通过前后端模型定义，不继续扩散 `any`。

### 4.3 R07：在线搜索跳转与安装目标

删除 `InstanceResourcesTab.vue` 的在线搜索弹窗及其专用搜索状态、请求和无引用样式。改为向父弹窗发出类型与目标信息，由统一处理器关闭实例弹窗并导航。

| 管理入口 | 下载页分类     | 需要携带的目标                                     |
| -------- | -------------- | -------------------------------------------------- |
| 模组     | `mod`          | 游戏目录、版本 ID                                  |
| 资源包   | `resourcepack` | 游戏目录、版本 ID                                  |
| 光影包   | `shaderpack`   | 游戏目录、版本 ID                                  |
| 数据包   | `datapack`     | 游戏目录、版本 ID、当前存档 ID                     |
| 原理图   | 暂无支持       | 推荐隐藏在线搜索按钮；本地安装、目录与预览继续保留 |

沿用现有 `instanceKey`／`parseInstanceKey` 协议处理实例目标，不另写路径匹配算法。数据包增加明确的 `world` query 协议；必要时支持 `q` 初始搜索词。

**下载页改动**：

- `Download.vue` 观察并校验 `route.query.tab`，支持页面已挂载时从外部切换分类。
- 搜索组件等待实例列表就绪再处理目标；等待该实例的存档列表就绪再设置数据包目标。
- 只在成功应用目标或明确判定目标失效后消费 query；失败提示后由用户选择目标，不静默安装到之前的实例。
- 快速连续切换实例／分类时使用请求序号或取消机制，避免旧请求写回新目标。
- 分类切换保留合法 query，清除不适用于当前类型的临时存档目标。
- 保留已有版本、加载器和下载源兼容筛选；安装成功后的资源刷新仍走原有事件／刷新通道。

若用户选择新增原理图在线下载，需要补充提供者、分类、版本与文件映射、许可及下载安装协议的专门设计，不在现有 `game_resource_search` 上忽略资源类型。

### 5.2 R04：Java 选择独立验收

新增共用 `JavaRuntimeSelector.vue`（建议放在 `features/settings/components/`），全局游戏设置与实例设置同时使用。组件负责列表展示、浏览、刷新、加载状态及路径回退；设置属于哪个作用域由调用方处理。

- 共用 `settingsStore.loadJavaInstallations()` 的缓存与并发请求合并，刷新显式强制重新扫描。
- 共用 `settingsApi.selectJava()`，移除实例 API 中重复的选择实现。
- 显示同样的 Java 主版本、类型、完整版本和架构；完整路径可在选项或提示中查看。
- 当前指定路径不在扫描结果中时保留该选项，避免选择被刷新清空；空结果替换旧列表，不显示过期成功结果。

### 5.3 配置模型与迁移

建议新增后端 `InstanceLaunchOverrides` 模型及前端对应类型，保存于原有 `.ecl/settings.json`，带 `schemaVersion`。模型区分缺省／继承与显式 `false`、空字符串等值；不能使用 `value || globalValue` 合并。

### 5.4 统一启动解析


随后沿用插件既有启动扩展和变量优先级；本次覆盖不得持久化到全局或实例配置。

- 初始化期间到达的请求等待就绪；重复点击对同一正在启动的实例合并／拒绝重复启动，并给出已有启动进度。
- 所有启动失败使用现有通知和启动进度反馈；不存在的实例、缺少 Java／账户等原因可见，不静默失败。
- 注册、队列、异步任务有明确退出清理，不用新开第二个主窗口规避单实例问题。

| 策略         | 有效节点计算                       | 失败行为                                     |

### 8.2 节点校验与实际生效

- 首版接收当前连接器允许的 `tcp`、`udp`、`quic`、`faketcp`、`ws`、`wss` URI；能否实际使用须以打包 EasyTier 版本的能力验收，不能仅因文档列出协议就承诺支持。
- 校验主机、端口、长度及合法路径部分，支持域名、IPv4 和带方括号 IPv6；按协议区分 WS 路径与裸连接地址。
- 拒绝无效协议、缺少主机、非法端口和不支持的凭据形式；保留原值用于编辑，并对规范化 URI 去重。
- 不把房间码、协调服务器地址或 HTTP 聚合列表 URL 当成节点 URI。
- 自建局域网节点是合法用途，不禁止私有网段。
- 在建房与加入前调用同一个节点解析策略，所有插件／连接扩展仍经过现有入口。
- 自动来源缓存与自定义配置分开；保存配置后使有效节点缓存失效，避免旧公共节点污染“仅自定义”。
- 本次会话使用开始时的节点快照。活动会话中可显示“下次连接生效”，不因保存设置自动断开房间。
- 状态页区分配置候选节点与本次实际采用的候选集合；只在底层能提供真实连接信息时标注已连接节点，不假装所有候选都已连接。

- 自定义下载服务封装下载专用模型及 Downloader 生命周期，不将游戏目录解析逻辑混入通用任务层。
- 持续进度快照保存字节数、总量和速度，不能只发一次细节事件、查询时却丢失详情。前端增加一个统一适配器将任务事件映射到 `useTaskQueue`。

若不采用通用任务提取，可以为下载器建立独立服务生命周期，但必须复用前端队列协议并说明额外任务注册／关闭机制的维护成本；不能直接让页面管理后台下载线程。

### 9.3 路径、网络与失败处理

- 用户明确选择的输出路径可以位于任意可写目录；服务验证最终路径、文件类型和写权限，使用同目录临时文件，完成后替换。
- 同一规范化输出路径禁止并发任务写入；取消、失败、启动器关闭都释放锁。
- 下载链接支持内网／自建服务器；验证 HTTP／HTTPS 和 URL 格式，跟随重定向时继续校验协议。
- 沿用启动器下载通道代理、限速及 TLS 设置；不能误用账户 API 代理或默认关闭证书验证。
- 明确适配 Downloader 的进度回调单位；已知总量显示字节进度，无总量显示不确定进度，不能显示虚假的 100%。
- 日志和任务展示避免输出 URL 中的凭据及敏感签名参数；显示可理解的来源域名和文件名。
- 失败保留用户已经存在的文件，清理本次临时文件或按下载器支持的恢复策略保留，并说明能否继续。首版“重试”允许重新开始，不承诺跨重启断点续传。
- 应用退出时先请求取消并完成下载器清理，再关闭任务执行器；不能遗留后台请求或无限等待。

| `--width <像素>`、`--height <像素>`                        | 本次窗口尺寸                                                                              |
| `--fullscreen`／`--windowed`                               | 互斥的显式显示模式                                                                        |
| `--isolation <inherit\|enabled\|disabled>`                 | inherit 表示不添加本次隔离覆盖，继续使用实例有效设置                                      |
| `--process-priority <现有优先级>`                          | 本次游戏进程优先级                                                                        |
| `--lock-memory`／`--no-lock-memory`                        | 显式覆盖内存锁定，未传入则继承                                                            |
| `--jvm-arg=<参数>`                                         | 可重复，追加一个 JVM 参数；使用等号允许值以 `-` 开头                                      |
| `--game-arg=<参数>`                                        | 可重复，追加一个游戏参数，保留传入的单参数边界                                            |
| `--launcher-visibility <none\|minimize\|quit>`             | 本次游戏启动成功后的启动器行为                                                            |
| `--open-page <games\|instances\|download\|settings\|more>` | 打开现有指定页面，由后端枚举映射实际路由，不接受任意 URL；与 `--launch` 首版互斥          |

快捷方式仅保存实例身份和必要数据目录信息，默认读取最新实例设置，不把上述临时参数全部固定到快捷方式。

第一阶段不默认添加无界面模式、账户密码／令牌参数、任意 IPC 调用、批量实例脚本、下载任务 CLI 或机器可读查询协议。需要这些能力时应先确定独立契约和验收范围。

### 10.3 解析与分发规则

- `--server` 与 `--world` 互斥且需要 `--launch`；验证空值及合法目标，不能让其中一个静默覆盖另一个。
- 实例启动参数需要启动目标；互斥参数与无效数值在 CLI 边界给出简短错误和非零退出码。
- 帮助／版本输出保持轻量，不加载桌面环境、游戏或联机依赖；CLI 单元测试覆盖这一点。
- 后端统一解析实例及有效设置；命令行值仅作为本次显式覆盖，不调用配置保存接口。
- 冷启动和转发到已运行启动器使用同一个有类型的启动意图模型。认证后的消息也需要字段、大小和枚举校验，不能信任原始 argv。
- 第一次启动可使用 `--data-dir` 等进程级选项；转发到现有进程时不更改其插件、前端或开发通道配置。对不可应用的组合明确拒绝／提示。
- 多次到达请求使用队列及按目标的启动守卫，等待服务就绪，不覆盖最初的启动请求。
- 解析失败可在新进程直接返回非零；转发成功与游戏最终启动成功不是同一件事，现有 UI 展示后续启动结果。首版不承诺可等待的自动化完成协议。
- 扩展 `--help` 和独立中文 CLI 使用文档，包含中文／空格路径、重复参数、同名版本定位和快捷启动示例。
