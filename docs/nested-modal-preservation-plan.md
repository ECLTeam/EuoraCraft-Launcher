# 全局父子弹窗保留实施方案

状态：方案 A 已按用户授权实施完成；检查、构建、桌面验收与日常目录同步通过，已提交前端，主仓库同步对应指针与本文。本次不推送远端。

## 需求与验收目标

在账户管理全屏页面点击“添加账户”时，小弹窗覆盖在账户管理上，账户管理继续显示为背景。关闭小弹窗后直接回到原来的账户列表，不重复播放全屏进入动画，不丢失滚动位置与页面状态。

修复通过共享弹窗机制覆盖同类嵌套场景，不在账户页面增加隐藏、重新打开父弹窗的专用逻辑。独立更新提示、错误提示和协议窗口继续服从现有优先级规则。

## 当前代码与原因

- `Game.vue` 的添加账户、账户详情 `Modal` 已位于账户管理 `FullscreenModal` 内；`openAddAccountModal()` 只设置添加弹窗可见，没有关闭账户管理。
- `useGlobalModalStack.ts` 从所有登记项中仅选择一个活动弹窗，尚无父子关系。普通窗口与全屏窗口默认优先级均为 80，同级采用后打开者优先。
- 添加账户成为活动弹窗后，`isFullscreenActive` 变为 false；`useFullscreenModal().currentId` 变为 null，`FullscreenModal.vue` 的 `v-show` 随之隐藏账户管理。
- 这也会清除全屏标题、切换主页面滑出状态。关闭添加账户后，上述状态恢复，触发全屏进入动画；账户管理的业务 `visible` 实际一直为 true。
- 类似问题影响衣柜内的编辑、上传、选项弹窗。实例详情的图标选择器以及账户登录、删除确认窗口在模板中与全屏窗口并列，需要显式说明逻辑归属，不能只依赖模板嵌套。
- 当前栈已有独立提示优先级、启动提示关闭阻塞、全屏级联关闭、路由清理等行为。现有测试明确要求错误抢占时全屏隐藏，修复需保留这些独立提示语义。

## 具体行为

### 父子关系与显示

- 全局登记项增加可选父弹窗标识；父弹窗必须存在，禁止自身归属与循环归属。首次打开确定关系，标题或其他属性更新不重新推断父级。
- `Modal` 和 `FullscreenModal` 通过共享上下文向实际嵌套的子组件提供自己的标识。Teleport 保持组件上下文，子弹窗无需业务组件手动切换父窗口的 `visible`。
- 对模板中并列、但属于同一操作流程的窗口，提供通用父级关联入口：账户登录/删除确认关联账户管理，实例图标选择器关联实例详情。避免把所有同级普通弹窗自动当成某个全屏窗口的子项。
- 活动项仍由既有优先级与打开顺序确定。允许显示的是该活动弹窗及其有效祖先；同一父级的其他子窗口等待，不同时堆出多个可操作窗口。
- 活动项为独立错误、协议、更新提示或启动提示阻塞项时，继续使用现有抢占与等待行为，不因后台仍登记全屏项就无条件展示它。
- 子窗口关闭后父窗口一直保持显示，因此不发生全屏退场、再次入场或主页面滑回再滑出的动画。小弹窗自己的动画继续沿用全局规范。
- 全屏切换全屏的既有路径保持当前表现，例如实例详情进入原理图、账户管理进入衣柜；本次不把所有全屏窗口都叠加展示。

### 交互、焦点与标题

- 把“显示中的背景全屏窗口”和“当前可交互弹窗”分别表达，避免复用 `activeModalId` 同时承担两种含义。
- 父窗口处于背景时使用 `inert` 等共享控制阻止鼠标和键盘操作；仅活动窗口对外表达 `aria-modal=true`，背景不重复表达活动模态语义。
- Esc 只关闭最上层可关闭窗口，不穿透关闭父窗口；不可关闭窗口继续遵循原设置。
- 记录触发子窗口的焦点，在关闭动画结束后恢复到仍存在的触发控件；触发控件失效时回退到父窗口可聚焦区域。子窗口打开时聚焦自身，Tab 不进入背景窗口。
- 必要的可聚焦容器属性与键盘处理通过共享组件/辅助逻辑完成，不在账户页单独实现。过渡期间不允许操作背景。
- 小弹窗显示时保留父全屏页面的标题和主页面滑出状态；顶栏全屏返回入口在子窗口阻塞期间不可误关闭父窗口。
- 滚动锁覆盖仍在展示的模态层，避免子项释放时提前解锁背景或全屏页面。父窗口关闭或路由离开后完整释放锁定。

### 关闭与清理

- 外部关闭或卸载父窗口时，关闭它实际关联的所有后代，不留下悬空子弹窗。
- 不用全局打开序号删除不相关的独立窗口；保留已建立的全屏层级回退规则，并用明确关系覆盖普通子窗口。
- 一次级联清理对每个后代最多触发一次关闭回调，避免重复取消登录、重复刷新或再次打开窗口。
- 全局 reset、全屏 reset 与路由清理同步释放相关子项、焦点记录和事件监听器；重复清理保持幂等。
- 添加账户成功、取消、登录窗口替换添加窗口等既有流程继续使用原业务状态，不改账户创建、身份认证或后端 API。

## 测试与桌面验收

- 账户管理 → 添加账户 → 关闭：背景全屏始终显示，列表滚动位置/状态保留；关闭仅小弹窗，没有父全屏退出/进入动画和主页面滑动。
- 鼠标、Tab、Esc：背景控件不可操作，焦点留在活动子窗口；Esc 一次只关闭子窗口，关闭结束后焦点回到“添加账户”。不可关闭登录窗口不被 Esc 关闭。
- 账户详情、删除确认、添加成功、添加切换登录：验证逻辑父级及原状态切换，没有遗留窗口；需要账户数据时使用隔离 fixture 或组件 mock。
- 衣柜编辑/上传/选项、实例图标选择器：验证全局修复生效；全屏切换全屏仍维持既有回退行为。
- 多层普通子窗口、同级等待、父窗口外部关闭/卸载、路由切换及重复 reset：没有悬空子项、重复关闭回调或滚动锁泄漏。
- 独立错误和协议仍能抢占；更新提示、启动提示关闭阻塞及待显示窗口恢复顺序保持原有规则。现有仲裁测试不能通过放宽断言掩盖变化。
- 默认主题/Folia、浅色/深色、常用与窄窗口，以及减少动效设置下检查焦点、动画、遮罩和顶栏返回状态。

## 风险与控制

- 把独立提示误当子项：使用明确组件上下文或显式父级关联，不根据“当前存在全屏窗口”无条件归属。
- 父窗口保留导致键盘穿透：显示状态与交互状态分离，结合背景禁用、活动 Esc 和焦点验证。
- 修改全屏接口影响顶栏与路由：保留既有调用接口，并分别覆盖背景标题、活动关闭和 reset 行为。
- 子窗口在关闭过渡期间解锁背景：覆盖关闭帧、焦点恢复时机和滚动锁测试，不仅检查动画结束后的静态画面。
- 层级清理误关其他窗口：基于有效关系清理后代，保留独立提示；测试明确检查未关联窗口不被删除。
