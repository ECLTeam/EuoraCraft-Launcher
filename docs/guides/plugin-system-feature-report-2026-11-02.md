## 1. 总体判断

当前插件系统已经具备较完整的本地扩展能力：第三方 Python 插件在独立 Worker 进程运行，通过受控宿主接口完成游戏、Java、资源、整合包、文件、联网、界面、登录和联机等操作；可信系统插件继续使用宿主内部扩展框架。

目前适合将其定位为“已有业务闭环、具备三平台基础与原生窗口验收记录的插件框架”。在线发现、可信签名及分发更新闭环仍未完成，不能据此称为已经具备完整插件商店或完整供应链信任体系。

需要优先理解四项边界：

1. Worker 进程隔离及 Host API 授权不构成恶意 Python 的操作系统沙箱。插件直接调用 Python 的文件、网络或进程能力，不由这些 Host API 权限自动限制。
2. 主窗口 HTML/Vue 注入和独立原生窗口是两种并存能力。主窗口注入仍可接触同页 DOM 与通用桥，独立窗口的隔离验收不能覆盖这条路径。
3. 跨插件命令调用已经实现，通用的跨插件事件发布与订阅尚未开放。
4. 三平台源码、原生监管、文件事务及窗口验证各有覆盖范围；不能将它们直接等同于所有处理器、所有浏览器版本和全部冻结发行物通过。

## 2. 系统结构与插件分类

### 2.1 可信系统插件

可信系统插件来自发行资源中的 `resources/system_plugins`，使用 `ECL.plugins.Plugin` 及内部框架，能够接入更完整的宿主领域对象。这些接口服务于发行物维护，不能作为第三方插件的公开契约。

当前内置示例为 `qomicex_compat`，用于读取 QomicEX 实例元数据。系统插件有单独的保护规则，不能通过普通用户插件流程覆盖；插件管理页面当前过滤系统插件，不把它们放入普通用户插件列表。

### 2.2 第三方 Worker 插件

第三方插件必须显式声明 `api_version: 2`，使用 `ECL.plugin_api.Plugin`。宿主不把 framework、配置服务或账户服务对象传入 Worker，跨进程只传递经过校验的 JSON。

主要调用关系如下：

```text
插件管理页 → 插件管理 API → PluginManager / PluginWorkerService
                                      │
                     审阅与授权、快照、依赖、生命周期
                                      │
                         WorkerSupervisor ↔ 独立 Python Worker
                                      │              │
                               PluginHostBroker ← HostClient
                                      │
                       游戏 / Java / 文件 / 网络 / 账户 / 联机服务
```

`PluginWorkerService` 维护运行对象、监测退出和收尾；`PluginHostBroker` 根据实际连接绑定身份，分派已实现方法，校验参数、授权和结果。插件不能通过请求体自报安装身份或任务所有者取得另一来源的权限。

接口缺失或当前宿主没有接入某项服务时，应返回明确失败。存在 SDK 方法或设计章节，并不单独证明该能力在所有运行环境可用。

依据：[管理器](../../ECL/plugins/manager/base.py)、[Worker 服务](../../ECL/plugins/worker_service.py)、[Broker](../../ECL/plugins/runtime/broker.py)、[第三方 SDK](../../ECL/plugin_api/plugin.py)。

## 3. 安装、更新与依赖

### 3.1 用户安装流程

插件页面支持搜索、全部/启用/禁用筛选、本地目录安装、归档安装、权限审阅、设置、面板、启用、禁用、重载和卸载。列表展示运行状态及待重启等信息。

归档安装的典型流程为：

1. 用户选择本地 `.eclplugin`。
2. 宿主预检归档、平台目标、依赖及来源信息。
3. 界面展示来源未验证，并由用户决定是否允许联网补齐依赖。
4. 安装准备文件与活动版本，不执行插件入口或自动授予权限。
5. 按安装结果完成重启，再审阅当前内容及权限并启用。

目录安装同样不会以执行入口验证安装成功；安装后仍须审阅并启用。基础插件点击启用确认当前内容；业务插件需要完成对应资源及站点范围的批准。

### 3.2 归档校验及本地更新

`.eclplugin` v1 是 ZIP 格式，包含 `plugin.json`、入口及资源、目标锁文件、可选 wheels，以及逐文件 SHA-256 与大小清单。

归档拒绝路径穿越、符号链接、大小写折叠后重名、加密条目及不符合格式的文件。当前不接受 `package-signature.json`，也没有签名或验签实现。

本地归档更新使用版本目录和活动指针，不直接对旧版目录进行无保护的增量覆盖。安装事务与故障恢复负责保护原有安装状态；更新后内容身份变化，需要重新审阅，不能继承旧代码的授权。

### 3.3 两类依赖

| 依赖类型      | 声明位置                                     | 行为                                                           |
| ------------- | -------------------------------------------- | -------------------------------------------------------------- |
| 插件间依赖    | `dependencies`                               | 版本约束、可选依赖、加载顺序与错误诊断；不是自动从商店安装依赖 |
| Python 库依赖 | `pythonDependencies` 及 `locks/<target>.txt` | 完整传递依赖精确锁定，以 wheel 摘要和宿主 ABI 校验             |

Worker 复用当前发行物的解释器；库安装到独立依赖目录，不为每个插件建立 venv，也不写入宿主或系统 site-packages。相同锁与 ABI 可以共享就绪库目录，不同 Worker 可以使用同名库的不同版本。

依赖优先从包内 wheel 和共享缓存取得。用户明确允许联网后，才能从固定 PyPI 来源补齐锁内兼容 wheel。不提供现场求解、源码构建、任意索引配置或私有索引支持。含依赖插件缺少当前目标完整锁时不能安装；不同 Python ABI 的锁不能冒充兼容。

wheel 的元数据、RECORD、Requires-Python 和传递依赖均需复核。`.pth`、启动定制模块及不支持的脚本布局会被拒绝；原生扩展仍受解释器 ABI 与动态库兼容性约束。

依据：[插件包协议](../protocols/eclplugin-package-format.md)、[归档校验](../../ECL/plugins/package_archive.py)、[安装事务](../../ECL/plugins/manager/install_transaction.py)、[依赖解析](../../ECL/plugins/dependencies.py)、[库环境池](../../ECL/plugins/environment_pool.py)。

## 4. 权限与内容审阅

### 4.1 授权对象

授权绑定宿主生成的安装身份、代码快照、权限清单、完整依赖锁及平台 ABI。卸载重装使用新的安装身份；重新批准不复活旧运行的任务、回调或资源引用。

可信主窗口负责管理授权。插件窗口和请求体中的自报字段不能替代主窗口身份。授权更新带内容摘要和并发版本，游戏、Java、账户候选分别使用自己的目录版本进行校验。

### 4.2 当前权限范围

| 能力                                 | 可用范围                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| 基础启用，内部为 `plugin.base`       | 自身命令、设置、有限事件、私有数据、固定来源公开目录等；不是插件清单中的用户授权项 |
| `instances.read`                     | 查看用户选择的游戏根及所属实例摘要                                                 |
| `instances.manage`                   | 包含同范围查看，以及安装、资料修改、启动、所属停止、资源和整合包管理               |
| `network.read`                       | 清单声明并经用户批准的精确站点                                                     |
| `java.read` / `java.use`             | 分别读取、验证或选用用户明确选择的已登记 Java                                      |
| `java.catalog.read` / `java.install` | 固定官方目录查询，以及安装并使用本运行安装的 Java                                  |
| `accounts.read`                      | 用户明确选择账户的最小摘要                                                         |
| `ui.inject`                          | 向主窗口插槽提交 HTML/Vue 内容                                                     |
| `ui.custom.execute`                  | 运行包内独立前端窗口                                                               |
| `auth.provider`                      | 注册第三方登录提供方                                                               |
| `connector.extend`                   | 补充联机展示状态                                                                   |
| `connector.manage`                   | 创建、加入、查询和退出自身联机会话及私有协议交互                                   |

当前代码还接受 `game`、`java` 合并声明，并展开为相应内部能力；它们与具体能力的对应关系以当前授权模型为准。启动钩子、崩溃分析和实例识别目前复用游戏权限准入，受管工具及跨插件命令复用基础启用准入，不能照抄旧 SDK 注释自行声明不存在的权限名。

游戏权限选择根目录，覆盖其中现有及未来新增实例。Java 与账户不继承游戏范围，也不自动选中全部或当前对象。`instances.manage` 包含同范围查看；只读权限不能用于写入或启动。

### 4.3 撤权与失效

撤权首先阻止新提交，并使原始授权代次下的引用和结果失效。已经接受的持久化或进程创建可能继续完成，宿主按真实效果报告结果。

任务本身的执行效果、结果是否仍可交付、资源是否清理完毕是不同状态。撤权不意味着已经提交的数据回滚，也不意味着已经启动的 Minecraft 自动被杀死。

依据：[授权模型](../../ECL/plugins/grant_models.py)、[授权存储](../../ECL/plugins/grant_store.py)、[管理 API 边界](../../ECL/api/plugins.py)、[前端授权界面](../../frontend/src/features/plugins/components/PluginPermissionsModal.vue)。

## 5. 命令、设置、事件及任务

### 5.1 自身命令与设置

命令支持同步和异步 Python 回调，回调留在 Worker；宿主依据登记的输入输出字段校验调用。基础字段类型为字符串、数字、整数和布尔，可设置必填、长度、范围和枚举，不提供任意嵌套 JSON Schema 或插件自定义验证器在宿主执行。

每组字段最多 32 项，单运行最多 64 个命令。设置支持布尔、字符串、数字和选择项，写入需要 `expected_revision`，通过定义校验后原子保存，避免旧页面覆盖新值。

### 5.2 事件与跨插件通信

当前 Worker 事件白名单为 `settings.changed` 和 `connector.changed`，分别用于自身设置及所属联机会话变化；不是宿主全局事件总线。单运行最多 32 个订阅，运行关闭后清理。

跨插件发现与调用使用 `plugins.list`、`plugins.call`。提供方必须以 `exported=True` 登记命令，双方运行均须有效；未导出命令不可发现或调用。调用在目标 Worker 执行，并继续使用目标命令 schema。

调用链设深度与等待限制，禁止通过跨插件接口调用自身。发现按调用时查询，不提供全局命令广播。尚无通用的 `plugins.emit`、`plugins.subscribe` 发布订阅能力。

### 5.3 副作用去重和自身任务

受回执机制管理的变更使用 `mutation_key` 去重。同键不同请求拒绝；等待超时应查询 `mutations.get`，不能换新键盲目重复提交。回执属于当前运行，授权代次变化及运行结束会限制其可用性。

长任务统一使用 `operations.get`、`operations.list`、`operations.cancel`。插件只能操作自身安装、内容和运行所属任务，没有通用 `operations.submit`，也不能指定宿主内部任务编号取得控制权。

任务分别表达排队、执行、提交、完成、失败、取消，以及 `cancellation_requested`、实际 `effect` 和 `cleanup_pending`。取消请求成功仅表示请求已受理；实际停止和资源释放必须继续查询。

典型业务流程是“提交业务操作 → 获得 `operation_ref` → 查询进度和实际效果 → 必要时请求取消 → 等待终态及清理完成”。游戏安装、资料修改、文件提交、下载及联机会话均使用所属任务机制。

依据：[Broker 控制方法](../../ECL/plugins/runtime/broker.py)、[任务适配](../../ECL/plugins/runtime/operation_adapters.py)、[跨插件契约](../designs/plugin-cross-plugin-invocation-design.md)。

## 6. 游戏与实例能力

| 功能         | 主要接口                                            | 实际能力及边界                                                     |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------ |
| 游戏目录发现 | `resources.list`、`instances.scan`、`instances.get` | 分页查看获准根和实例，返回运行内引用及白名单摘要，不返回宿主裸路径 |
| 实例资料修改 | `instances.profile_patch`                           | 修改别名、描述、收藏和标签；以完整资料 etag 检测并发冲突           |
| 公开版本目录 | `game.catalog`                                      | 查询 release/snapshot 版本；固定宿主来源                           |
| 加载器目录   | `game.loaders`                                      | Fabric、Forge、NeoForge、Quilt；按游戏版本查询                     |
| 安装         | `game.install`                                      | 原版及上述加载器，省略加载器版本时按既有规则选择兼容版本           |
| 启动         | `game.launch`                                       | 获准实例、内存及窗口选项；可传入经过 Java 权限验证的 `runtime_ref` |
| 查询自身游戏 | `game.running`                                      | 只查看本 Worker 运行创建的游戏记录及实际退出码                     |
| 停止自身游戏 | `game.stop`                                         | 按原始进程对象及所有者停止，不按裸 PID、名称查杀其他进程           |

资料修改不是通用配置编辑。当前只接受 `alias`、`description`、`favorite`、`tags`；保留其他合法原字段，损坏数据及版本冲突明确失败，不自动读新版本后强行覆盖。成功发布使用原子替换，已发布旧资料不保留专用备份，不承诺重启恢复旧补丁。

游戏安装拒绝覆盖已有用户实例，与界面及整合包基础安装共用目标占位。文件写入开始后失败，可能报告部分效果；插件关闭不会清除已经写入的游戏文件，新运行也不能随意接管旧残留。

直接启动选项包括内存、窗口宽高、全屏及受控 Java 引用，不接受裸 Java 路径、任意 wrapper、脚本或任意环境变量。独立的启动钩子另有受限参数补充能力，不能把这两种入口混为一谈。

宿主提供账户、下载源和其他启动准备服务。创建游戏进程前再次检查许可、取消、目标身份和账户变化；进程创建后撤权或关闭插件不自动终止游戏，已创建游戏仍纳入启动器正常进程管理。

依据：[游戏请求模型](../../ECL/plugins/runtime/game_models.py)、[游戏安装](../../ECL/plugins/runtime/game_install.py)、[游戏启动](../../ECL/plugins/runtime/game_launch.py)、[实例资料事务](../../ECL/plugins/runtime/instance_profiles.py)。

## 7. Java、账户摘要与公共配置

### 7.1 Java

Java 已形成“查询 → 验证或安装 → 获得运行时引用 → 启动游戏”的调用链。

| 接口                           | 用途                                                          |
| ------------------------------ | ------------------------------------------------------------- |
| `java.inventory`               | 查看获准已登记运行时的最后登记摘要，不隐式扫描磁盘或执行 Java |
| `java.validate`                | 对获准单目标执行固定参数、有时限的实际探测                    |
| `java.catalog`                 | 查询固定官方来源的 Java 包                                    |
| `java.install_plan`            | 根据当前包引用生成安装计划                                    |
| `java.install`                 | 通过所属任务安装、校验并登记 Java                             |
| `game.launch` 的 `runtime_ref` | 使用获准已登记 Java，或本运行在原安装许可下成功安装的 Java    |

用户及不同插件的在途 Java 安装相互隔离，冲突返回忙；不能复用、取消他人的任务。撤权后保留已经安装的文件，但旧运行引用不会因重新授权复活。不开放全局 Java 删除或清理权限。

### 7.2 账户与配置读取

`accounts.list`、`accounts.get` 只读取用户明确选择的账户，返回随机运行引用、别名、Minecraft UUID、类型和是否当前账户，不返回邮箱、令牌、宿主账户标识及提供方私有数据。

`config.public` 仅返回语言、主题标识、主题模式、强调色和默认内存等白名单字段。不存在宿主任意配置分区透传或通用配置写入接口。

第三方登录提供方对自身认证材料的访问是另一项独立能力，不能根据 `accounts.read` 推导出来。

依据：[Java 适配](../../ECL/plugins/runtime/java_api.py)、[公共查询](../../ECL/plugins/runtime/public_queries.py)、[Java 资源](../../ECL/plugins/java_resources.py)、[账户资源](../../ECL/plugins/account_resources.py)。

## 8. 模组、资源包、光影及整合包

### 8.1 资源管理

`mods`、`resourcepacks`、`shaders` 均支持列表、从插件私有文件安装、按原文件引用删除，以及 Modrinth/CurseForge 的搜索、版本和下载信息查询。只有模组提供 `mods.set_enabled`，使用明确启用/禁用目标状态，不以重复“切换”实现。

在线目录查询复用宿主固定来源，不接收插件指定的 API 地址或平台密钥。查询下载信息不会隐式授权站点访问；实际下载仍须批准 `network.read`，先下载到私有文件，再通过资源安装接口提交。

资源位置遵循实例现有隔离/共享规则。同名文件不覆盖，删除引用绑定原文件版本；外部替换后必须重新列举。当前资源安装接口上限为 64 MiB，但可用私有源文件还受到 8 MiB 单文件上限约束，不能将 64 MiB 描述为端到端可安装大小。

### 8.2 整合包

| 阶段     | 接口                                               | 行为                                   |
| -------- | -------------------------------------------------- | -------------------------------------- |
| 准备     | `modpacks.prepare`                                 | 从私有文件复制归档并调用既有整合包校验 |
| 查看     | `modpacks.get`                                     | 查看格式、版本、加载器及有限文件预览   |
| 安装     | `modpacks.install`                                 | 安装到批准根中的新实例，可明确排除文件 |
| 导出预览 | `modpacks.export_preview`、`modpacks.export_files` | 分页查看候选文件，不替用户自动全选     |
| 导出     | `modpacks.export`                                  | 只将明确选择文件导出到私有新 `.mrpack` |

导入保留实际 Minecraft 父版本及启动描述，不从自定义实例名猜版本。归档路径穿越、文件大小及格式校验沿用整合包领域实现。

清单中的各下载地址继续逐项校验站点、重定向、DNS 和连接，不借共享下载器绕过插件许可。当前整合包领域单文件下载上限为 128 MiB，与私有归档输入和最终私有输出的配额属于不同限制。

失败或取消可能保留已经安装的共享基础版本，按部分效果和实际清理状态表达，不承诺整个安装过程完整回滚。

依据：[游戏资源](../../ECL/plugins/runtime/game_resources.py)、[在线目录查询](../../ECL/plugins/runtime/resource_queries.py)、[整合包](../../ECL/plugins/runtime/modpacks.py)、[使用示例](../../examples/plugins/worker_game_tools/README.md)。

## 9. 私有文件、网络与下载

### 9.1 私有文件

基础启用后可取得本安装私有数据根引用，支持 `files.stat/list/read`、分块新建、按 etag 替换、按版本删除及上传中止。不提供任意用户路径访问，也不允许通过该接口创建子目录。

新建流程为 `files.write_begin → files.write_chunk → files.write_commit`，替换从 `files.replace_begin` 开始并复用后续上传提交；删除使用 `files.delete`。提交返回任务引用，需查询实际完成情况。

新建不覆盖突现目标；替换及删除核对原目标物理身份和版本，防止旧引用作用于外部新文件。不能仅靠字符串路径的前缀判断维持文件边界。

| 限制项             | 当前值                                          |
| ------------------ | ----------------------------------------------- |
| 私有单文件         | 8 MiB                                           |
| 单安装私有空间     | 64 MiB                                          |
| 单运行上传暂存预留 | 32 MiB，最多 4 项                               |
| 宿主暂存预留       | 128 MiB                                         |
| 单次原始读写块     | 最多 32 KiB                                     |
| 文件名             | 1—120 个受限 ASCII 字符；不接受路径组件及设备名 |

POSIX 文件操作要求允许的本地文件系统及可靠身份、出生时间和原生重命名接口；未知、远程或缺少必要能力时拒绝。跨平台实现不代表任意文件系统均可工作。

### 9.2 只读网络与下载

`network.request` 支持 GET/HEAD，不提供通用 POST、请求体、任意 Socket 或任意请求头。站点按协议、主机和端口精确批准；敏感认证头只允许 HTTPS，跨来源重定向剥离相关头，并逐跳复核授权及网络目标。

网络操作具有 DNS、连接、响应、总等待预算及清理责任，不能把调用超时当作实际后台工作已经停止。日志不直接输出完整 URL 敏感内容、认证头或响应正文。

`downloads.submit` 将网络读取与私有文件提交组成所属任务，遵守站点许可、空间预留、摘要校验、不覆盖目标和取消语义。当前单次私有下载受 8 MiB 上限约束，不能用于不受限大文件缓存。

这些约束适用于宿主网络接口；它们不等于限制 Worker 内 Python 自行创建网络连接。

依据：[文件 API](../../ECL/plugins/runtime/file_api.py)、[私有存储配额](../../ECL/plugins/runtime/file_storage.py)、[网络 API](../../ECL/plugins/runtime/network_api.py)、[下载 API](../../ECL/plugins/runtime/download_api.py)。

## 10. 三种界面扩展方式

| 方式         | 能力                                          | 权限与边界                                               | 适用场景                     |
| ------------ | --------------------------------------------- | -------------------------------------------------------- | ---------------------------- |
| 声明式面板   | 文本、分组、按钮、设置、列表、任务进度        | 基础启用；宿主渲染有限节点；按钮调用自身命令             | 设置页、任务工具、结构化信息 |
| 主窗口插槽   | HTML 片段、Vue 模板/脚本/样式、上下文与更新键 | `ui.inject`；同页 DOM 和 JS 运行时暴露，通用桥隔离未完成 | 需要修改主界面的可信扩展     |
| 独立原生窗口 | 包内预构建、资源内联的单文件 HTML，专用消息桥 | `ui.custom.execute`；独立来源、原生控制及桥白名单        | 复杂前端交互、独立工具界面   |

### 10.1 声明式面板

面板由 `define_panel` 注册，设置节点须提前定义，列表和任务数据通过回调拉取。当前单面板最多 48 个节点、嵌套深度 3，单运行最多 16 个面板。它不执行插件模板或脚本，外观由宿主组件维护。

### 10.2 主窗口注入

插件通过 `define_html_slot`、`define_vue_slot` 登记内容，宿主按来源清理；禁用、卸载及运行失效后撤销相应内容。

全局配置 `plugins.allow_ui_injection` 控制第三方注入，当前默认允许，界面入口位于开发工具面板。关闭后撤销第三方内容；当前代码在重新打开时重载仍启用且获准注入的插件，以重新登记内容。该操作可能重新触发插件生命周期，不能视作只切换 CSS 可见性。

主窗口注入与宿主同页执行。现有设计记录明确指出通用桥隔离尚未完成；不能宣称已通过 Broker 对这段前端脚本形成完整授权隔离。独立窗口上线没有自动关闭或修复主窗口注入路径。

### 10.3 独立原生窗口

清单 `custom_ui` 指定快照内 HTML 入口、标题和尺寸。入口最多 512 KiB，资源由作者预先内联；不能传任意外部 URL、宿主路径或动态 HTML 替代批准内容。

Worker 使用 `ui.windows.open/get/focus/close`。每次运行最多两个活动窗口、十六个累计引用。页面通过 `ECL.call` 使用专用桥，当前白名单为运行信息、权限视图、自身命令、设置及自身任务查询/取消。

原生层在执行插件脚本前安装来源、导航、网络、权限、文件选择及通用桥控制；关闭、撤权和 Worker 停止先使消息失效，再确认实际销毁。独立浏览器数据上下文及拒绝代理用于维持窗口边界。

当前要求维护版 `pytauri-wheel 0.8.0+ecl.2`。Windows/macOS 对引擎版本有明确固定条件，必要接口或版本不符时拒绝插件窗口执行，普通主窗口不受该插件专用门禁影响。

依据：[面板模型](../../ECL/plugins/runtime/models.py)、[面板前端](../../frontend/src/features/plugins/components/PluginPanelModal.vue)、[主窗口注入决策](../designs/plugin-main-window-injection-decision.md)、[配置响应](../../ECL/plugins/manager/base.py)、[独立窗口实现](../../ECL/plugins/runtime/custom_ui.py)、[原生运行时](../../native/pytauri-runtime/README.md)。

## 11. 生命周期扩展与工具进程

### 11.1 启动钩子

支持 `prepare`、`pre_launch`、`post_launch`、`exit`。第三方回调只接收版本、加载器及隔离标记等有限上下文；`prepare` 可按限制补充 JVM 参数、游戏参数和环境变量。

必要钩子在准备或启动前失败时可以阻止本次启动；启动后和退出阶段失败只记录。钩子能力与直接 `game.launch` 的选项限制应分别评估，不能据后者推导插件绝对不能影响启动参数。

### 11.2 崩溃分析

插件通过 `register_crash_analyzer` 补充分析摘要及原因，宿主发送有界退出信息、已有原因和最多 8000 字符输出。返回值只接纳允许字段，并限制原因数量和文本长度；单插件异常隔离，禁用后注销回调。

这是分析增强入口，不是任意日志或用户文件读取入口；有限输出仍属于插件可见数据，不能描述为完全没有信息暴露。

### 11.3 实例识别

第三方通过 `register_instance_source` 登记识别回调，管理器只对已索引且获准的实例投递有限版本、加载器和相对目录上下文，并净化返回元数据。

系统插件内部还有带路径和监听文件解析器的完整兼容扩展接口。第三方 Worker 的当前接口不等同于这套内部接口，不能直接使用系统插件示例取得宿主路径或注册同样的监听能力。

### 11.4 受管工具

支持 `define_tool`、`run_tool`、`stop_tool`，对应 `tools.register/run/stop`。可执行文件必须位于插件包内，固定和附加参数均有边界；进程交给宿主通用进程服务登记，停止前检查插件来源。

该入口不是通用终端，不接收任意系统可执行路径，也不能停止其他插件或游戏进程。若当前宿主没有接入进程服务，则明确拒绝。工具在各平台的二进制可执行性及完整退出行为仍须按具体工具和平台验证，不能仅凭 Worker 平台支持推导。

依据：[启动钩子](../../ECL/plugins/launch_hooks.py)、[崩溃扩展](../../ECL/plugins/crash_extensions.py)、[实例兼容](../../ECL/plugins/instance_compat.py)、[Worker 接线与工具](../../ECL/plugins/worker_service.py)、[管理器回调适配](../../ECL/plugins/manager/base.py)。

## 12. 第三方登录与联机

### 12.1 登录提供方

插件可登记登录名称、说明、最多六项文本/密码字段，以及认证和启动凭据解析回调。动态表单进入现有账户流程，不要求宿主为每个提供方新增硬编码表单。

认证返回账户标识、别名、UUID，可包含皮肤地址及本提供方私有字符串映射。宿主按安装身份和提供方分区保存，私有材料不进入普通账户摘要，也不交付给其他提供方。

启动凭据解析可取得本提供方自己的已保存数据，返回玩家名称、UUID、访问令牌、用户类型和可选认证服务器。输入输出严格校验，回调前后复核原许可；撤权、禁用或重载后移除注册，重新授权须重新登记。

已有真实 Worker 登录和重启往返记录。但 `worker_auth` 使用合成测试令牌，只验证契约和数据生命周期，不能据此声称某个外部认证服务已经接入或通过实服登录验收。

### 12.2 联机与私有协议

状态补充和会话控制分别由 `connector.extend`、`connector.manage` 授权。

会话接口包括创建/加入 `connector.open`、查询 `connector.get`、退出 `connector.leave`、登记私有协议 `connector.protocols.register`、房客向房主请求 `connector.request`，以及设置有限状态文字 `connector.status.set`。

应用维护唯一联机服务，插件会话绑定安装、内容、运行和服务代次。用户已有房间时插件不能抢占；旧插件会话的迟到清理不得关闭后来创建的用户房间。会话在存续期间保留所属任务，可信任务中心可以请求取消。

私有协议按名称隔离，每运行最多八项，请求及响应各不超过 16 KiB；回调只处理 JSON 载荷，不获得通用网络或其他会话控制权。`connector.changed` 只向所属 Worker 投递。

已有两个真实 Worker 经本地 EasyTier 中继建房、加入、协商 JSON 回声及确认退出的记录。该记录不覆盖公共互联网复杂网络环境，也不等同于真实 Minecraft 多人游戏联机验收。

依据：[登录与联机契约](../designs/plugin-auth-and-connector-extension-design.md)、[认证注册表](../../ECL/plugins/auth_providers.py)、[联机适配](../../ECL/plugins/runtime/connector_api.py)、[登录示例](../../examples/plugins/worker_auth/README.md)、[联机示例](../../examples/plugins/worker_connector/README.md)。

## 16. 插件开发与评审参考

### 16.1 SDK 与开发入口

Python Worker SDK 提供 `HostClient.call/call_async`、本地回调注册、自身命令、面板、插槽、跨插件调用及各类扩展注册方法。生命周期可覆写 `on_load`、`on_enable`、`on_frontend_ready`、`on_disable`、`on_unload`，同步及异步处理由 Worker 执行。不是每个 Host API 都有专门的 Python 包装方法，业务接口通常通过 `host.call` 使用。

主窗口另有 `frontend/src/plugin-sdk`，与 Python Worker SDK、独立窗口 `ECL.call` 是三套不同边界：

| 前端 SDK 模块          | 已有功能                                                       |
| ---------------------- | -------------------------------------------------------------- |
| `ui`、`dom`、`widgets` | 提示、确认、弹窗、通知、菜单、DOM 工具及控件                   |
| `component`、`state`   | 组件封装、状态与响应式辅助                                     |
| `router`、`events`     | 主窗口路由及前端事件辅助                                       |
| `theme`、`hooks`       | 主题 token、模式变化、生命周期及清理辅助                       |
| `transpile`            | 注入脚本的 TypeScript 转换                                     |
| `api`                  | 插件命令与设置，以及主窗口配置、游戏、Java、账户和文件接口封装 |

这些主窗口 API 封装直接依赖主窗口业务层，存在超出 Worker 白名单的配置和文件操作入口。因此不能将前端 SDK 当作第三方 Worker 的权限受控替代接口，也不能把这些辅助函数描述成独立窗口全部可用的能力。

已放置的主窗口插槽覆盖标题栏、侧栏、内容顶部/底部、实例与管理区域、插件页工具栏/列表、设置区域、任务队列和部分弹窗及在线资源区域。例如 `plugin-slot-content-bottom`、`plugin-slot-plugins-toolbar-after`、`plugin-slot-task-queue-item-actions`。插槽是否出现及其上下文由实际页面决定，不是向任意路由自动挂载完整插件页面的承诺。

制作归档可运行 `python packaging/build-eclplugin.py <插件源目录> <输出.eclplugin>`；输出不得位于插件源目录内。制作工具生成归档清单，不替作者求解或准备完整依赖锁和 wheels。

依据：[Python SDK](../../ECL/plugin_api/plugin.py)、[前端 SDK 导出](../../frontend/src/plugin-sdk/index.ts)、[前端 API 封装](../../frontend/src/plugin-sdk/api.ts)、[注入桥](../../frontend/src/composables/usePluginBridge.ts)、[制作工具](../../packaging/build-eclplugin.py)。

### 16.3 推荐评审顺序

1. 确认插件属于第三方 Worker API v2，使用当前能力名及目标 ABI。
2. 根据实际业务请求最小权限，区分游戏根、Java、账户和精确站点。
3. 确认是否需要可执行前端：简单界面使用面板，复杂界面评估独立窗口；涉及主窗口注入时明确其同页能力。
4. 所有具有副作用的调用按各自契约管理回执、去重键、任务状态及失败后的查询，避免超时盲目重放。
5. 覆盖拒绝、撤权、冲突、取消、重启和资源清理，分别记录模拟、真实 Worker、原生平台和冻结产物证据。
6. 将本地安装可用、平台验收、远端交付、版本发布和线上商店运营作为独立结论记录。

本报告是指定提交的功能快照。现行运行契约以代码和[插件包协议](../protocols/eclplugin-package-format.md)为准，历史实施记录用于了解证据及其限制。
