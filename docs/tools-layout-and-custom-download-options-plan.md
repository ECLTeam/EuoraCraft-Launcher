# 工具页布局与自定义文件下载实施方案

## 状态与需求

- 方案日期：2026-10-02；用户已确认实施，功能及桌面验收完成，本地 main 集成验证进行中。
- 用户要求修正工具页排版，自定义下载默认保存到数据目录下的文件夹，允许选择其他文件夹、使用原文件名或自定义名称，并支持自定义 UA 和请求头。
- 用户已选定布局：下载主卡铺满可用宽度，NAT 检测改为下方紧凑横条。
- 「参数头」按其他 HTTP 请求头处理；已有下载地址可以直接包含 URL 查询参数。本次不额外引入查询参数编辑器。

## 现状与影响

`ConnectToolsTab.vue` 将自定义下载与 NAT 放进同一个 `connect-tools-layout`，该布局在 `Connect.css` 中固定使用最大 340px 的单列。此约束源自此前的 NAT 小卡片设计；新增下载表单也被挤进小列，造成截图中的大片空白和输入框拥挤。

`CustomDownloadCard.vue` 当前输入地址和完整保存路径，浏览按钮调用 `select_save_file`。没有默认目录、独立命名模式或请求头设置。表单和任务由 Pinia 保留在本次会话内，切页后可以继续取消／重试。

后端 `CustomDownloadService` 使用 `OperationManager` 与公开 Core 下载器；已有进度、取消、重试、同目标并发保护，以及同盘临时文件和原子提交。Core 下载器已有公开 `headers` 属性，预检查、普通 GET 和分片请求共用 HTTP 客户端头部，因此本次可以在主仓库接入 UA／请求头，不修改 Core 子仓库。

默认目录必须由后端从实际 `state.data_path` 计算，避免前端猜测便携版、沙箱和不同平台的数据位置。

## 下载目录与命名

### 默认目录及目录选择

1. 默认目录为 `<实际数据目录>/downloads`。
2. 新增 `custom_download_defaults` IPC 返回默认目录和默认 UA，前端只在本次表单尚未选择目录时初始化，不能覆盖用户已经选择的文件夹。
3. 浏览改为系统文件夹选择器，标题为「选择下载文件夹」，首次从默认目录打开，之后从当前选择目录打开；取消选择保留原值。
4. 复用 `select_directory`，增加可选的 `custom-download` 用途及初始目录；旧的无参数调用仍按原有游戏目录选择逻辑运行。
5. 默认目录在开始下载或用户打开对应文件夹选择器时按需创建。初始化表单不创建目录；自定义目录不可写或实际指向文件时给出具体错误。
6. 目录和命名选择在当前启动器会话内保留，不新增全局设置或跨次启动的历史目录。用户重启后的初始目录仍为数据目录下的 `downloads`。

### 原文件名模式（默认）

自动名称顺序：响应 `Content-Disposition` 的有效 `filename*`、`filename`，随后使用重定向后的 URL 最后一段，最后回退到 `download.bin`。优先处理 `filename*` 是为了正确识别中文等编码名称，规则依据 [RFC 6266](https://www.rfc-editor.org/info/rfc6266/)。

- 名称解析在后台任务内进行，表单点击开始后立即获得任务 ID，不让界面等待网络探测。
- 元数据探测使用与下载相同的 UA、请求头、代理和有限超时。优先 HEAD；服务不支持 HEAD 时用流式 GET 读取响应头后关闭响应，不把探测正文全部加载到内存。
- HEAD 成功但缺少可用文件名时按 URL 回退；探测网络失败时不无限重试，使用可取得的 URL 名称，再由正式下载返回实际错误。
- 界面在任务开始前可以显示 URL 推测名称，但标为预估；任务确定名称后显示实际文件名及目标位置，完成结果使用最终落盘路径。
- 服务端名字仅作为单一文件名使用，去除路径前缀并处理 Windows 非法字符、保留名、尾部空格／句点、空名等情况；最终路径必须仍位于用户选择的目录内。

### 自定义名称模式

- 文件名按用户输入原样保存，包括用户自己指定的扩展名；空名称或非法名称阻止提交并显示字段错误。
- 只接受单个文件名，拒绝路径分隔符、相对目录跳转、Windows 保留名及非法字符。修改保存文件夹通过目录字段完成。
- 自定义名称不需要为获取名字单独探测网络。

### 覆盖、并发与重试

- 保留现有「允许覆盖已有文件」选项，默认关闭；冲突时失败并说明，不自动覆盖，也不自动改成带序号名称。
- 自动名称在后台确定后，再按最终规范化路径登记写入锁，两个任务不能同时写同一文件。
- 重试保留原任务的目录、命名意图、UA、请求头与覆盖选择；已确定的目标位置可以固定复用，避免重试时保存到其他名字。
- 沿用同盘临时文件、取消清理与原子提交，失败时保留已有目标文件。

## UA 与请求头

- UA 单独输入，留空时沿用现有 `EuoraCraft-Launcher` 默认值。
- 其他请求头通过可增删键值行填写，例如 `Referer`、`Authorization`、`Cookie`、`Accept`。
- 字段名按 HTTP token 规则校验，值拒绝换行和控制字符；大小写不同的同名键按重复处理，给出字段错误。全空行可忽略，只有值没有字段名则报错。
- `User-Agent` 统一由 UA 字段设置，头部列表填写同名键时提示使用 UA 字段，避免两个入口互相覆盖。
- 请求头条数和总大小有明确上限（最多 64 个头，总字符最多 32 KiB；单个 UA 最多 4 KiB），不限制普通自定义业务头名称。
- 在启动下载器前设置其公开 `headers`，使预检查、正式下载和分片请求使用一致的请求设置；不修改其他游戏下载的默认头部。
- 请求设置仅在当前会话的表单和重试意图中保存，不写入任务持久化快照，不记录敏感头部值。

## 模型与兼容性

- 扩展 `CustomDownloadRequest`，新增下载目录、命名模式、可选自定义文件名、UA、请求头，并使用明确类型及互斥校验。
- 保留旧 `target_path` 调用兼容入口。完整目标路径与新目录／命名模式不得混用，避免歧义；已有任务和外部调用不因前端表单升级而失效。
- 使用内部已解析下载意图保存最终路径和不可变请求设置；不修改调用方传入的模型或字典。
- `CustomDownloadService` 显式注入应用数据目录，不借用操作管理器的私有路径属性。现有测试下载器注入方式保留。
- 更新 IPC 注册表、请求 schema、前端命令类型和 showcase 返回结构，覆盖新默认配置读取与目录选择字段。
