# 工具页紧凑工作台实施方案

## 状态与目标

- 日期：2026-10-03。
- 用户已选择本轮方案 A「紧凑工作台」。本文件供实施前审阅，功能代码尚未修改。
- 目标：建立清晰的页面标题、下载主工具与网络检测辅助工具层级，改善图片背景下的阅读体验。
- 本轮方案更新了旧文档中的左标签表单与 NAT 横条设计；旧文档仅保留历史记录，其中的实施、同步及推送授权不作为本轮授权。

## 当前实现与影响范围

工具页入口为 `/more/tools`，由 `ConnectToolsTab.vue` 渲染，外层沿用「更多」的 `SectionLayout`。当前 `connect-tools-layout` 为铺满内容区的单列网格，上方是 `CustomDownloadCard`，下方是 NAT 横条。

下载卡片使用 96px 标签列与可伸缩输入列，基本输入及辅助按钮高度为 29px，开始按钮高度为 36px。高级设置采用 `details/summary`；表单和下载任务由现有会话 store 保留。NAT 已支持待检测、检测中、成功、失败、再次检测以及卸载后忽略迟到响应。

卡片复用 `UiCard` 和主题变量；Folia 皮肤的默认卡片表面更透明，背景图片会明显透入。模糊还受 `data-aurora-blur` 等已有开关控制。因此阅读体验应在工具页内调整，并沿用主题能力。

本次修改前端模板、工具页样式、六种语言文案及相关测试。下载参数、目录选择、命名规则、覆盖保护、取消、重试、轮询、会话状态和 NAT 后端调用均沿用当前实现。

## 选定设计

### 页面结构

```text
工具
文件下载与网络检测

┌ 自定义下载 · 下载图标 ───────────────────────┐
│ 下载地址                                    │
│ [ https://example.com/file.zip             ] │
│                                             │
│ 保存设置                                    │
│ 下载文件夹                                  │
│ [ 当前保存目录                    ] [ 浏览 ] │
│ 保存名称                                    │
│ [ 原文件名 | 自定义名称 ]                    │
│ 名称提示，或自定义名称输入与提示             │
│ ☐ 允许覆盖已有文件                          │
│                                             │
│ › 高级设置                                  │
│ 展开后显示 UA、请求头及相关校验反馈          │
│                                             │
│ 按需显示错误、进度、任务消息和目标位置       │
│                        [取消/重试] [开始下载]│
└─────────────────────────────────────────────┘

┌ NAT 类型检测 · 网络图标 ─────────[ NAT 检测 ]┐
│ 检测当前网络的 NAT 类型                     │
│ 尚未检测                                    │
│ 完成后：类型标签 / 公网地址 / IPv6 状态      │
└─────────────────────────────────────────────┘
```

示意中的分组通过留白和文字层级表达，保存设置不再包一层卡片。进度与结果区域仅在相应状态出现，卡片自然增高。

### 页头与空间

1. 复用现有 `PageHeader`，标题为「工具」，说明为「文件下载与网络检测」，使用工具图标。
2. 页头放在工具页现有滚动容器内，与两张卡片一起滚动，避免新增固定头部挤占小窗口。
3. 两张卡片继续铺满内容区并对齐左右边缘；宽窗口仍为单列。
4. 卡片之间的间距初始为 16px；标题与正文的间距、卡片内边距以 16px 为基准，窄容器可降为 12px。
5. 不设置固定卡片高度，不用空白填充撑满页面；只有一个页面纵向滚动容器。

### 下载工具

1. 使用 `UiCard` 的标准图标和标题能力，统一下载与 NAT 的标题字号、字重和图标尺寸。
2. 下载地址独占一行，标签在输入框上方，作为首个主要输入；继续使用 `UiInput`。
3. 保存设置为轻量分组。目录输入独占可用宽度，浏览按钮与其同高，固定自然宽度，长路径在输入框内滚动。
4. 保存名称的标签在控件上方，保留现有分段单选、原文件名提示及自定义名称输入。名称输入始终属于保存设置，不随高级设置折叠。
5. 覆盖复选框移到命名区域下方，保留完整可点击标签和「失败时保留原文件」说明，默认仍为关闭。
6. 高级设置默认折叠。UA 与请求头采用上标签布局；键名、值和删除按钮在空间足够时同一行，窄容器下换行。折叠不清空字段，不隐藏页面级阻断错误。
7. 高级设置及操作区主要通过间距区分，去除当前连续横线；页内错误与下载任务反馈放在操作区上方。
8. 开始、取消、重试仍位于卡片右下方，统一为现有 36px 按钮；输入和浏览等辅助操作保持现有 29px 规格。
9. 沿用全部禁用、加载、错误、完成与重试条件。整理模板时避免重复展示同一条校验错误。

### NAT 工具

1. 改为与下载一致的独立卡片标题区，检测按钮放在标题右侧，保持辅助按钮视觉权重。
2. 正文首行显示「检测当前网络的 NAT 类型」，下方显示当前状态。待检测状态只保留短文案，不使用大型空态插画。
3. 检测中显示现有加载指示及提示，按钮禁用；再次检测立即清除旧结果，保持现有互斥状态逻辑。
4. 成功时分层呈现类型标签、公网地址和 IPv6 状态；地址与 IPv6 可在宽容器并排，窄容器上下排列。标签保留当前状态色映射。
5. 未知类型、地址缺失和 IPv6 未检测到使用当前准确文案，不改写为检测失败。
6. 失败时显示简洁标题及具体错误，保留重新检测入口。长地址、端口范围和错误均可换行。
7. 保留状态区的 `role="status"`、`aria-live`、`aria-busy` 以及卸载后的响应保护。

### 主题与可读性

1. 仅作用于工具页两张卡片，使用语义明确的工具卡片类；不调整全局 `UiCard`、主题配置或其他页面卡片。
2. 背景初始使用 `color-mix(in srgb, var(--card-bg) 80%, var(--bg-elevated) 20%)`，以主题表面色提高遮盖程度，避免硬编码纯白。这个局部混色会保留少量底色，是本轮设计的一部分。
3. 继续响应浅色、深色、经典及 Folia 皮肤和透明度配置；在透明度 0、50、100 的代表值下检查实际表现。若主题设计器存在页面覆盖，应验证它仍能生效。
4. 模糊复用现有主题变量，并在 `data-aurora-blur="0"` 时关闭本次新增的工具卡片模糊；不改变背景媒体本身的模糊值。
5. 圆角复用同一主题变量，移除 NAT 独立固定 8px 圆角。卡片边框、输入框焦点、按钮与选中态沿用项目规范。
6. 字段标签使用主要文字色，说明使用次要文字色；小字号提示需保持可读，避免在复杂背景上过度降低对比度。

### 响应式与键盘操作

1. 以工具卡片实际内容宽度进行容器适配，不以整窗宽度推断可用空间。
2. 小于 520px 时请求头和操作区允许换行；小于 450px 时 NAT 标题按钮可移至下一行，结果字段改为纵向排列。
3. 输入与分段单选保持明确标签关联；高级设置保留原生键盘折叠和可见焦点。
4. 自定义名称出现、折叠展开、报错及进度变化不主动抢焦点。开始后沿用原有焦点及任务行为。
5. 六种语言长文案允许换行，不截断按钮文字，不产生页面横向滚动。

## 测试与验收

### 自动检查

- 相关组件用例：原名与自定义名切换、精确文件名、目录选择取消、覆盖选项提交、UA 与请求头折叠后保留、下载中字段禁用、取消、重试及切页后任务恢复。
- NAT 用例：待检测、加载、成功、失败、未知结果、缺失地址、IPv6、端口范围、重复点击、再次检测及卸载后的迟到响应。
- 执行与 `frontend/.github/workflows/lint.yml` 一致的 `cd frontend && pnpm check`，包括格式、ESLint、类型检查和完整前端测试。
- `pnpm check` 通过后执行 `pnpm build`；若现用产物目录被占用，使用 Vite 的独立输出目录，不停止其他开发服务。
- 主仓库提交前执行与工具页集成相关的现有测试，确认父仓库与前端配套；本轮无后端修改，不新增后端业务。

### 实际启动器验收

- 使用隔离数据目录启动 Windows Tauri/WebView2 启动器，加载本轮生产构建，进入「更多 → 工具」；保留截图及验证记录。
- 以截图接近的 960×600、宽窗口和实际允许的最小窗口为主要验收尺寸；另测窄卡片容器，不修改启动器全局最小宽度。
- 覆盖空表单、长路径、原名／自定义名、高级设置展开、多行请求头及长错误；确认页面只有一个纵向滚动区，所有控件可达。
- 在浅深色、经典／Folia、图片背景、模糊关闭及代表性透明度下检查阅读、焦点、悬停、禁用与加载；核对两张卡片标题、圆角和边缘一致。
- 本地 HTTP 测试服务配合真实后端完成下载，核对原始名称、自定义名称、UA／请求头、覆盖冲突保护；回归取消、重试和切页保留任务。
- NAT 状态布局可以使用受控结果覆盖全部边界，但真实探测需单独执行并记录；网络超时不等同布局失败，受控结果不作为真实联网成功证据。
- 回归联机页与插件页，确认工具页样式及进入／离开行为不影响其他页面和现有房间状态。
- Linux/macOS 若无设备验收，最终报告明确标注未实机验证。

## 完成标准与风险

完成标准：选定布局已实现，六种语言齐全，自动检查与构建通过，实际启动器操作及视觉验收完成，相关改动已分别提交。

主要风险：上标签布局和页头会增加高度，需通过紧凑间距与自然滚动控制；复杂图片下的表面调整可能影响透明主题的观感，需检查低透明度配置及设计器覆盖；长 NAT 结果和高级请求头展开会增高卡片，需验证滚动、焦点和窄容器。
