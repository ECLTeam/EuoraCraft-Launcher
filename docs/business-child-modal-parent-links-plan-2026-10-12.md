# 业务子弹窗父级关联补齐实施方案

状态：代码修复、完整检查及生产构建已完成；Windows 交互验收被用户实体 Esc 停止。用户于 2026-10-13 明确要求“提交然后推送”，现按该后续指令提交并推送，保留未完成交互验收的记录。

## 需求与验收目标

资源下载页选择实例后，点击具体版本打开安装确认框时，资源详情全屏页持续显示为背景。关闭确认框、进入“另存为”、取消保存或保存完成后，详情页状态连续，避免全屏退场及恢复入场。

同一要求覆盖仓库现有业务子弹窗：打开子窗口时，明确的父窗口及有效祖先保持显示，只有顶层窗口可以交互；关闭后恢复父级焦点、滚动位置与原有筛选。实际完成安装、删除实例等需要离开详情的业务操作，继续在成功时完成相应关闭。

“所有同类”指前端维护的业务窗口存在明确从属关系、但因并列渲染或事件转交缺少父级关联而导致父窗口隐藏的问题。排查同时覆盖普通窗口之上的普通子窗口。全屏页面之间的导航、独立错误/协议/更新提示的优先级及原生文件选择器继续使用各自现有机制。

## 调研结论

- `Modal.vue` 已支持 `parentId`，未显式指定时继承组件祖先提供的关系；`ConfirmDialog.vue` 已透传该属性。共享栈可保留普通子窗口的祖先展示链，并处理背景禁用、焦点、关闭过渡和级联清理。
- `FullscreenModal.vue` 已暴露 `modalId`；实例图标及崩溃日志选择器、账户登录及删除确认已有显式关联，可沿用同一做法。
- `OnlineModSearch.vue` 的资源详情全屏框与安装确认框并列渲染，安装确认缺少 `parentId`。点击另存为经过这个确认框时同样受影响。
- `ManageTab.vue` 的确认框位于实例详情组件之外。详情通过事件请求修复/复制时，确认框没有获得实际来源窗口的标识。详情删除还在提交确认前主动关闭详情，使取消后无法留在原详情。
- `InstanceWorldsTab.vue` 的备份列表与恢复确认框并列；二者目前继承同一个实例详情父级。恢复确认出现时，备份列表被当作同级窗口隐藏。
- `DevToolsPanel.vue` 的“全屏弹窗 → 嵌套弹窗”示例并列渲染且没有关联，与真实业务中的遗漏一致。
- 账户添加/详情、衣柜编辑/上传/选项、Java 管理删除、实例内模组/资源/存档/服务器/截图操作已位于父全屏组件的后代，普通窗口能够继承关系。需以真实组件回归确认，而不是重复添加关联。
- 原理图预览/材料审计、Java 管理及账户管理/衣柜之间使用全屏页面导航；共享栈已有全屏回退规则，本次验证其导航与关闭行为。
- 搜索普通、全屏、确认、错误、通知及包装组件调用，并检查 `NModal`、`useDialog` 和插件 SDK 弹窗入口。SDK 自建 DOM 窗口不注册共享栈，当前未发现它们触发本次父全屏隐藏的链路。

## 已选择方案及取舍

方案 A：在并列业务子弹窗入口显式关联真实父级，复用共享栈、组件上下文与既有过渡机制。

方案 B：调整模板，把确认窗口移入父组件内部，依靠上下文继承。用户已选择 A，因此实施以明确关联为主；只有当前实际嵌套的窗口继续使用既有继承。

预计复杂度中等：主要改动位于业务调用点。实例详情事件来源和存档备份的二级窗口需要精确区分，测试与运行验收覆盖共享模态交互。主仓库生产 Python 与后端协议预计无需修改。

## 具体改动点

### 1. 资源详情与安装确认

- `frontend/src/components/mods/OnlineModSearch.vue`：给详情 `FullscreenModal` 增加类型明确的组件引用，把其 `modalId` 传给安装 `ConfirmDialog.parentId`。
- 覆盖该组件共用的 Mod、资源包、光影和数据包版本确认入口，验证数据包存档选择及必需依赖展示。
- 另存为仅关闭当前确认框并打开原生文件选择器；取消选择、下载成功和失败时资源详情连续显示。安装成功时沿用明确的业务关闭。
- 审核“前置依赖详情”的切换流程，关联不会在切换项目后残留或错误引用旧详情。

### 2. 实例详情发出的确认操作

- `frontend/src/views/instances/InstanceDetailModal.vue`：通过类型明确的公开引用暴露实际详情窗口标识，供外层关联使用。
- `frontend/src/views/instances/ManageTab.vue`：区分实例列表操作与详情操作入口；确认动作携带明确来源父级，详情入口使用详情标识，列表及路径操作保持独立。
- 父级标识在开始操作时捕获。修复需要等待文件检查接口，返回后须确认来源详情仍然有效，避免把过时结果挂到新打开的实例或重新弹出已取消流程。
- 从详情删除时，打开确认前保持详情；取消保留详情。删除成功再关闭对应详情，失败保持原详情和现有错误反馈。
- 修复、复制、删除共用确认入口要在每次打开时重设来源，防止上次详情操作的标识影响随后列表操作。

### 3. 存档备份列表与恢复确认

- `frontend/src/components/instances/InstanceWorldsTab.vue`：备份列表 `Modal` 增加组件引用；恢复确认明确关联备份列表，形成“实例详情 → 备份列表 → 恢复确认”。
- 列表上的存档复制/删除确认继续归属实例详情；每次设置确认来源，避免恢复确认的父级残留到其他操作。
- 核对实例切换、备份列表关闭和组件卸载时确认状态与回调的清理，确保没有旧存档动作残留。

### 4. 调试页嵌套示例

- `frontend/src/features/debug/components/DevToolsPanel.vue`：全屏示例增加引用，嵌套普通窗口显式关联示例全屏窗口。
- 调试页普通弹窗及危险操作确认沿用各自来源；嵌套示例可直接用于后续运行验收。

### 5. 全量回归与共享行为

- 复查全部 Vue 窗口调用与包装组件。若实测发现其他相同的遗漏，按相同明确来源方式补齐，并在本文实施记录列出文件、触发入口及验证证据。
- 使用共享背景禁用、焦点恢复、Esc、滚动锁及关闭过渡；现有栈测试仍需通过。
- 不根据“当前存在全屏窗口”将所有普通提示自动绑定为子窗口。独立高优先级提示、全屏导航及路由清理需要保持既有语义。

## 风险与控制

- 确认父级错误会影响级联关闭：来源显式传递，覆盖列表与详情两种入口。
- 异步操作返回时详情已切换：捕获来源及实例，完成时验证有效性，不以当前活动窗口临时猜测归属。
- 父窗口外部关闭后确认回调残留：取消与切换同步清理，验证关闭、卸载及重复清理。
- 成功删除引发确认与父级共同退出：通过现有共享退场与级联机制处理，覆盖成功、失败、取消三个结果。
- 新依赖版本可能影响检查：记录真实失败并处理相关问题，全部要求的检查通过后才提交。
