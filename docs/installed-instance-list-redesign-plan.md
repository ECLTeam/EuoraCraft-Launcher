# 实例管理列表样式调整实施方案

状态：用户已确认方案 B，已完成实施、验证和日常使用目录同步。

## 需求与现状

本次调整截图中的「实例管理」列表视图，使实例名称、运行版本与操作更容易阅读，保持启动器既有主题与交互风格。

当前 `InstalledInstanceList.vue` 将每行拆成实例、游戏版本、加载器、分类/标签、操作五列。名称字号约 11px，辅助信息约 9px；实例 ID 与游戏版本经常重复显示。操作列固定 132px，但六个 24px 按钮加间距需要约 159px，导致右侧拥挤。长实例名称又受到多列宽度挤压。

已讨论方案：

| 方案 | 调整方式 | 取舍 |
| --- | --- | --- |
| A | 保留五列表格，优化字号、列宽与按钮间距 | 变动较小，仍保留较多重复信息与操作 |
| B（已选择） | 改为主次分明的列表行，合并版本与加载器，收纳次要操作 | 名称空间更大、阅读更清楚；收藏、置顶、删除需打开更多菜单 |

## 选定设计

每行结构为「图标 + 名称与辅助信息 + 分类/标签 + 启动、详情、更多」。移除列表表头和原有五列布局。

示意：

```text
[图标] 生存服   ☆ 📌                   [模组] [#生存]    [▷ 启动] [详情] [更多]
       Minecraft 1.21.1 · Fabric v0.16.9
```

1. **名称**：字号约 13px，适度加粗，优先显示别名或展示名称；长名称单行省略，悬停可查看完整名称与实例 ID。已收藏、已置顶时在名称旁显示小图标，状态含文字提示。
2. **辅助信息**：字号约 11px，使用全局次要文字色。游戏版本与加载器信息放在同一行，例如 `Minecraft 1.21.1 · Fabric v0.16.9`；原版显示 `Minecraft 1.21.1 · Vanilla`。快照、预发布等类型保留可辨识信息。实例 ID 不再单独重复占一行。
3. **分类与标签**：分类继续使用已有分类颜色；没有分类时显示低强调度的「未分类」。标签最多直接展示两个，其余以 `+N` 提示，悬停可查看完整标签。标签与分类区域限制宽度，避免挤压名称。
4. **操作**：保留带播放图标与文字的「启动」按钮，以及详情、更多两个图标按钮。使用现有全局按钮与主题样式，启动文字复用 `versions.detail.launch`。损坏实例延续当前不可快捷启动的限制。
5. **更多菜单**：保留实例工作台、资源管理、打开文件夹、图标/别名/描述、收藏与隐藏入口；增加置顶/取消置顶及删除实例。删除放在分隔线后，并复用原 `remove` 事件与父组件确认弹窗。收藏与置顶仍调用现有配置接口，成功后更新当前状态。
6. **密度与响应式**：默认行高约 64–68px、图标约 38px；名称区域弹性伸缩，右侧操作不压缩。窄窗口将分类/标签移到信息区下方，允许行高增长，不产生横向滚动。
7. **主题与交互**：沿用全局背景、文字、分隔线、主色、圆角和动画变量，保留主题节点、选中标记、悬停反馈与右键菜单。更多按钮按按钮位置打开菜单，右键按鼠标位置打开。可点击控件具有文字提示、可访问名称和键盘焦点反馈。

## 影响范围与具体改动

- `frontend/src/components/instances/InstalledInstanceList.vue`：替换列表模板，组合辅助信息、标签与状态展示；补齐菜单入口和事件分发，区分按钮与右键菜单定位。
- `frontend/src/styles/components/instances/InstalledInstanceList.css`：替换旧表格列样式，增加列表行布局、信息层级、操作区和窄窗口规则。新增样式限定列表视图，避免影响卡片。
- `frontend/src/components/instances/InstalledInstanceList.test.ts`：更新旧表格断言，覆盖新布局下各项操作和状态。
- 本文：实施后记录验证结果与交付状态。

卡片视图、左侧路径栏、顶部筛选工具栏、实例扫描与启动逻辑保持现有行为。卡片与列表共用的更多菜单会同步获得置顶和删除入口；卡片原有直接操作保留。

## 实施步骤

1. 获得用户明确实施确认后，检查主仓库和前端子仓库工作区，保留已有无关修改。
2. 调整列表模板与局部样式，复用现有图标、按钮、翻译和主题变量。
3. 补齐更多菜单操作，删除接回现有确认流程；验证子按钮不会意外触发行选择。
4. 更新并运行针对性测试，再执行完整前端检查和生产构建。
5. 使用隔离配置实际启动 Windows 启动器，验证列表效果及交互，保存截图；根据结果修正布局。
6. 检查并提交同一功能的前端改动，主仓库提交对应子模块指针和实施记录。按本会话既有交付方式同步日常使用目录、重建前端并检查实际加载的新页面；保留该目录原有无关修改。不推送远端。

## 测试与验收

### 自动化

- 点击列表行仍选中正确实例；启动与详情指向正确实例，点击操作按钮不会选中其他行。
- 收藏、置顶、隐藏通过原接口更新，菜单文字与标记反映更新后的状态。
- 删除操作发出原删除事件，并验证父组件原确认入口可用，取消时不执行删除。
- 保留工作台、文件夹、资源管理等入口；原版不显示模组管理，模组实例显示。
- 损坏实例不能快捷启动；搜索、排序、筛选以及切换卡片视图继续可用。
- 必须先通过 `cd frontend && pnpm check`，再通过 `pnpm build`；涉及父子组件联动时运行相关现有集成测试。

### 实际启动验证

- 在约 960×600 的截图窗口尺寸和更宽窗口中验证；长名称、长加载器版本、多标签与空列表均不溢出。
- 验证明暗主题与复杂背景图，确认文字层级、选中态和按钮对比度符合全局样式。
- 验证按钮与右键菜单、收藏/置顶反馈、详情入口及删除确认/取消路径。
- 模拟实例仅用于可控 UI 验证，记录中明确区分模拟数据与真实游戏运行；不将界面点击测试表述为真实游戏启动成功。

## 风险与处理

- 次要操作收纳后增加一次点击：名称旁保留收藏、置顶状态标记，更多菜单明确显示当前动作。
- 新布局可能影响主题扩展：保留 `instance-row` 与 `instances.row` 节点，样式继续使用全局变量。
- 长文本或多标签挤压布局：名称省略、标签限量、信息区域可收缩，操作区域保留宽度。
- 用户运行页面与工作树构建不同：交付时核验日常使用目录与实际前端来源，避免仅修改隔离工作树而页面没有变化。
