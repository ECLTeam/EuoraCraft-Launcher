# 实例资源包图标读取与移除复选框实施方案

状态：用户已选择方案 1 并确认开始；代码、完整检查、生产构建与实际 Windows 启动器验证已完成。

## 目标与验收标准

实例管理弹窗的资源包页显示实际资源包中的图标，并移除用于批量选择的复选框。

- ZIP 资源包和文件夹资源包均读取根目录的 `pack.png`，无需联网。
- 资源列表返回图标数据，前端直接显示；刷新时重新读取，因此替换资源包后可更新头像。
- 没有图标、图片损坏、图片过大或读取失败时显示默认资源包图标，其他资源仍能正常显示。
- 资源包页移除行首复选框及顶部批量删除按钮，保留每行删除、删除确认弹窗和启停开关。
- 图标采用约 40px 的方形区域，保持比例，名称和操作按钮布局完整。
- 搜索、刷新、安装、在线搜索和导出清单继续可用。

## 当前实现与方案选择

`frontend/src/views/instances/InstanceDetailModal.vue` 的资源包页使用 `InstanceResourcesTab.vue`，限定资源类型为 `resourcepack`。同一组件也用于光影包、数据包和原理图。

`InstanceResourcesTab.vue` 当前没有资源头像，行首为 `NCheckbox`，通过 `selected` 保存选择；顶部删除按钮调用 `removeSelected()`。每行另有独立删除按钮。

后端 `ECL/services/game/resources.py` 的 `_parse_pack()` 只读取 `pack.mcmeta`；`list_resources()` 返回名称等信息。现有 `game_resource_list` IPC 已在线程中执行扫描，可继续承载图标读取。

| 方案 | 实现方式 | 权衡与选择 |
| --- | --- | --- |
| 1：随列表读取 | 扫描资源时读取图标，通过现有列表响应返回 | 接口简单，适合一般资源包数量；用户已选择 |
| 2：延迟读取 | 列表返回图标标识，按可见行请求图片 | 大量资源包时减少初始读取，但增加接口、缓存和状态管理 |

本次对复选框和布局的调整仅应用于资源包页；共用组件的其他资源类型维持现有选择及批量删除行为。

## 具体改动

### 后端：随资源列表读取图标

修改 `ECL/services/game/resources.py`：

1. 在 `ResourceCoordinator` 中增加带明确类型和中文多行 docstring 的私有资源包图标读取方法，返回 `str | None`。
2. ZIP 直接读取根目录成员 `pack.png`，不解压到磁盘；文件夹直接读取包根目录下的同名图片。
3. 仅在 `resource_type == "resourcepack"` 时读取，将结果以 `iconData` 字段加入列表条目；成功时使用 `data:image/png;base64,...`，无有效图标时返回 `None`。
4. 图标与元数据读取分别处理失败，避免缺失或损坏的 `pack.mcmeta` 阻止有效头像显示。
5. 限制图片输入为 1 MiB，检查 PNG 签名和尺寸头，尺寸须为正且单边不超过 4096px；ZIP 先检查声明的未压缩大小，再进行有上限的读取。
6. 文件夹图片须位于资源包目录内，解析符号链接后重新校验边界；读取失败只影响当前头像。
7. 沿用现有 IPC 的线程执行边界，不引入新的同步磁盘读取到 async 处理函数。
8. `export_resource_manifest()` 导出前从条目副本中移除 `iconData`，避免 JSON 清单写入大段图片数据；CSV 字段维持现状。
9. 本次增加的限值归属领域类，使用带类型的 `snake_case` 属性；修改所在模块时按项目规范检查相关类型、注释和文档。

不增加图标专用 IPC、磁盘图片缓存或图像处理依赖。完整图片解码失败由前端图片错误回退处理。

### 前端：头像与单项删除

修改 `frontend/src/types/instances.ts` 与 `frontend/src/components/instances/InstanceResourcesTab.vue`：

1. `GameResource` 增加可选的 `iconData?: string | null`，兼容没有图标字段的响应。
2. 资源包行首显示头像，默认使用项目现有的 `package` 图标；图片加载失败时回退，刷新后允许重试。
3. 使用资源包专用行布局容纳 40px 图标，图片保持比例；长名称省略显示，操作区域仍可点击。
4. 资源包页不渲染 `NCheckbox` 和顶部批量删除按钮，不增加点击行选择等替代选择行为。
5. 保留每行删除及现有确认流程，删除请求只传该资源的 ID。
6. 共用组件中保留其他类型所需的 `selected`、`toggleSelected()` 与 `removeSelected()`；资源类型切换时清理选择，避免跨类型残留选择。
7. 保留安装、搜索、刷新、导出和启停的既有接口及处理逻辑。

## 测试计划

### 后端回归与集成

新增 `tests/test_resourcepack_icons.py`，必要时补充现有 IPC 测试：

- ZIP 与文件夹资源包均能从列表响应取得真实 PNG 的 Data URL。

## 影响与限制

- 图标随列表一起传输，资源包数量很多时响应大小和扫描时间会增加；本次通过图片限值控制单张开销。
- 仅支持资源包根目录的 PNG 图标，超限或无有效图标的包使用默认头像。
- 资源包启停状态的现有计算规则不在本次改动中调整；实际运行中发现的相关问题单独报告。
- 资源包删除方式改为逐项删除，移除批量删除入口是本次明确的交互变化。
