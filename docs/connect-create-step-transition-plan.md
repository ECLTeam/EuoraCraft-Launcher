# 联机创建房间步骤切换动画实施方案

## 状态与需求

用户已明确范围：创建房间中“下一步 / 输入端口 / 上一步”的步骤切换，并要求根据全局动画进行设计。用户已确认实施方案 A，功能、测试、桌面验收和常用主目录前端同步已完成。

验收目标：从运行实例选择进入端口步骤、从手动端口入口进入端口步骤，以及返回实例选择时，都能看到与启动器现有风格一致的过渡动画。

## 当前实现与问题原因

- `frontend/src/views/connect/ConnectRoomTab.vue` 已有 `<Transition name="page" mode="out-in">`。
- 初始区域的根节点固定使用 `key="idle"`，而实例选择、端口输入两个步骤都属于 `idle` 状态。更新 `displayHostStep` 仅改变内部表单和加入房间卡片，未改变过渡观察的根节点标识，因此不会触发步骤动画。
- 进入端口步骤时，加入房间卡片直接隐藏；返回时直接显示，创建房间卡片的位置随之改变。
- 全局 `frontend/src/styles/animations.css` 已定义 `page` 动画：进入时淡入并从下方 12px 移入，退出时淡出并上移 6px；默认进入 250ms、退出 150ms，遵循全局动画变量和系统减少动态效果设置。
- 选择值、端口、扫描状态位于页面脚本及联机上下文，重新挂载步骤区域不会重新挂载整个页面或联机服务。

## 可选方案与取舍

| 方案 | 修改方式 | 取舍 |
| --- | --- | --- |
| A（采用）：整个步骤区域过渡 | 让现有过渡下的初始区域根节点标识包含 `displayHostStep`，复用全局 `page` 动画 | 实例表单、端口表单和加入卡片统一切换，改动集中，过渡期间新旧布局依次显示 |
| B（备选）：仅创建房间表单过渡 | 在创建房间卡片内部添加独立过渡，为两个表单分别设置标识 | 卡片标题保持静止，但加入房间卡片仍需单独处理显示隐藏和布局变化，改动较多 |

以下详细步骤按复用全局动画的方案 A 编写。

## 全局动画设计

动画来源以 `frontend/src/styles/animations.css` 为准，该文件由 `frontend/src/styles/main.css` 全局导入；时长和缓动变量以 `frontend/src/styles/base.css` 为准。

| 阶段 | 现有全局效果 | 使用的全局变量 |
| --- | --- | --- |
| 当前步骤退出 | 透明度从 1 到 0，同时上移 6px | `--duration-fast`（默认 150ms）、`--ease-emphasized-accelerate` |
| 下一步骤进入 | 透明度从 0 到 1，从下方 12px 移到原位 | `--duration-normal`（默认 250ms）、`--ease-emphasized-decelerate` |
| 减少动态效果 | 继承全局 `prefers-reduced-motion: reduce`，过渡时长缩短为 0.01ms | 现有全局媒体查询 |

- 使用现有 `page` 过渡类；步骤组件通过根节点标识变化触发动画，动画参数继续由全局样式统一维护。
- 维持 `mode="out-in"`：旧步骤退出完成后再显示新步骤，普通设置下完整切换默认约 400ms。
- 下一步、输入端口、快捷创建和上一步使用相同的全局过渡方向，保持页面切换的一致性。
- 过渡范围为 `.connect-idle-layout`：加入房间卡片与创建房间卡片整体过渡，侧栏和“更多”导航保持当前状态。
- 联机模式仍为 `idle`，仅用步骤标识区分实例选择和端口输入；联机服务和页面脚本继续保留，选中实例与端口值随现有页面状态保持。
- 端口扫描沿用现有步骤状态驱动，不将网络或扫描工作绑定到 CSS 动画结束回调；验收确认进入后能正确展示最新扫描状态，返回后能停止扫描。
- 初次打开联机页、联机页与其他更多子页之间的路由过渡沿用现有行为，本次验收聚焦用户明确要求的创建房间步骤切换。
