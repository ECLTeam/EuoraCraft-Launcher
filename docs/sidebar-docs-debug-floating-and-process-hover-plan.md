# 侧栏底部移除、调试常驻浮窗与实例进程按钮实施方案

日期：2026-10-07。

状态：用户于 2026-10-07 确认开始实施，并选择默认收起的小浮条；实施与验收已完成，2026-10-10 完成本地集成。

基线：主仓库 `57a92af`、前端 `5ea6c76`。本次调研时主仓库和前端工作区干净。

## 1. 需求与调研结论

本次处理三个明确问题：

1. 完全移除侧栏底部按钮区域及其分隔线；文档入口放到设置的关于页。
2. 开启调试模式后，调试工具常驻在主窗口内；设置页的按钮用于展开可拖动、缩放和收起的面板，不再切换到独立的 `/dev` 页面。
3. 游戏页的实例进程管理按钮在悬停时保持正常底色，移除悬停后明显变透明的效果。

实施前的基线实现：

| 位置 | 当前行为 |
| --- | --- |
| `SideBar.vue` | 底部有调试和文档按钮；调试按钮在 `launcher.debug` 开启时可见，点击跳转 `/dev`；文档打开 `URLS.docs`。 |
| `TitleBarTray.vue` | 顶部导航模式下另有调试和文档入口；调试动作也跳转 `/dev`，本次一并移除内置项。 |
| `AboutTab.vue` | 首张关于卡片已有检查更新、问题反馈和 GitHub 操作，适合新增文档入口。 |
| `DevTools.vue` | 以路由页承载工具、全局调试开关、组件示例、日志入口及危险操作；页内关闭按钮跳转主页。 |
| `useDevToolsState.ts` | 容器边界、动画开关与倍速已由共享状态管理，适合在保留当前页面时实时观察。 |

| `Game.css` | 无运行实例时按钮使用 `--control-bg`；`.running-instances-trigger.inactive:hover` 改用 `--control-bg-hover`，该颜色透明度较高，造成悬停变透明。 |

此前比较悬浮面板、全屏弹窗和独立子窗口；用户选择悬浮面板。该方案让当前页面继续可见和可操作，也不需要新增宿主窗口、IPC 命令或跨 WebView 状态同步。

## 2. 文档入口迁移

- 删除侧栏底部文档按钮及其明确不再使用的点击方法、导入。
- 关于页首张卡片的现有操作区增加文档按钮，使用相同图标、尺寸和外部链接打开方式，目标继续使用集中定义的 `URLS.docs`。
- 按用户实施中的补充要求，完整删除侧栏底部按钮容器、调试按钮、分隔线和专属样式；插件底部插槽继续使用原位置。
- 顶部导航模式的托盘同时移除重复文档入口；该模式下也统一从关于页进入文档。
- 文档操作文案归属关于页，补齐项目六种语言；不对整份语言文件进行无关清理。

## 3. 调试工具悬浮面板

### 3.1 入口、内容与状态

- 设置 → 启动器 → 开发者分组在调试模式开启时显示“打开调试工具”按钮，展开唯一浮层。重复点击不创建第二份面板，不改变当前路由、页面表单和主内容区滚动位置。
- 同步删除顶部托盘的内置调试和文档项，保留插件托盘能力；所有导航模式均从设置展开工具、关于页打开文档。
- 移除 `/dev` 路由；调试内容迁到独立组件，由应用壳挂载浮层。旧地址按现有未知路由规则处理，不增加专门的跳转或迁移层。
- 工具浮层在启动器调试模式开启、用户协议已确认时自动常驻，默认收起为小浮条；自动出现不抢当前页面焦点。关闭调试模式时完全隐藏。
- 保留已有工具能力与危险操作的确认、后端权限检查；全局调试开关仍由现有共享状态拥有，不建立第二份调试配置。
- 收起及 Esc 只回到常驻浮条，不提供关闭常驻入口的按钮；不自动改动容器边界、动画倍速等调试开关。
- 窗口状态只维护关闭、悬浮和收起三种形式。位置和尺寸在当前应用会话中保留，不新增全局配置保存、配置广播或旧数据兼容逻辑。

### 3.2 浮层布局与操作

- 使用项目主题背景、边框、圆角和阴影；外层标题栏统一放置调试工具标题和收起 / 展开按钮，内容内部不重复显示同一标题及路由关闭按钮。
- 首次启用显示约 260×44px 的小浮条，完整面板初始尺寸约 640×440px，位于主窗口右上方、应用标题栏下方；最小尺寸约 420×280px，实际尺寸随可用视口收敛。
- 标题栏支持拖动，右下角支持缩放；位置限制在可用视口内，主窗口缩小时重新约束位置和尺寸，保证操作按钮可达。
- 内容区独立滚动，窄浮层内的工具说明和控件允许换行；控件根据浮层自身宽度布局，不能只依赖浏览器整体宽度的媒体查询。
- 收起后显示紧凑的调试工具条，可拖动或展开；收起时保留当前工具内容和窗口布局。
- 面板为非模态工具区，允许与当前页面交替操作；键盘焦点在浮层内且没有阻断弹窗时，Esc 可收起浮层，收起后将焦点交回原入口。
- 拖动和缩放在结束、取消、收起、禁用及卸载时清理监听器或指针捕获，不让拖动状态跨页面或残留。

### 3.3 与弹窗和日志窗的关系

- 新面板的层级低于现有阻断弹窗，不照搬日志窗的 `9999` 层级。
- 调试页中的确认、普通弹窗和全屏测试仍使用现有全局弹窗栈；阻断弹窗出现时，调试浮层暂停交互和拖动，关闭子弹窗后可以继续使用浮层。
- 全屏弹窗测试及其嵌套弹窗须保持正确的焦点、Esc 顺序与父子关系，不能因改换容器丢失现有行为。
- 启动器日志悬浮窗继续由原日志控制器管理，调试工具面板有自己的状态；同时打开时核对遮挡及操作可达性，不顺带重构日志窗。

## 4. 实例进程按钮悬停修正

- 取消无运行实例时 hover 规则对背景的高透明度替换，使悬停前后使用同一正常态底色。
- 保留主色运行态、无运行实例时的外观区分、悬停展开文字、边框反馈、键盘焦点及点击打开管理界面的行为。
- 本次移除的是额外悬停透明效果；用户主题中已经选择的卡片透明度与玻璃效果仍按现有规则生效。

## 6. 验收标准

- 侧栏展开、折叠及所有调试模式均没有底部按钮、分隔线或空底部残留；关于页文档操作使用正确链接，并在窄窗口可达。
- 顶部导航模式不再显示重复文档项，调试工具从设置展开常驻浮层，不发生 `/dev` 跳转。
- 从游戏和设置页打开调试面板，路由、页面编辑内容与滚动位置不被重置；重复打开只有一个面板。
- 拖动、缩放、收起、恢复及主窗口缩小后，标题栏和内容始终可达；收起或卸载时没有残留拖动监听器。
- 调试开关对当前页面真实生效；确认弹窗出现时主工具区停止交互，嵌套全屏测试及 Esc 顺序正确，关闭后恢复工具区焦点和操作。
- 调试模式关闭后没有悬浮面板残留，日志浮窗与工具浮窗互不覆盖状态。
- 实例进程按钮在没有运行实例时，悬停前后的背景计算值一致；有运行实例时仍保持原主色状态，点击仍打开管理界面。
- Classic/Folia、亮暗色及默认约 960×600px 窗口、820px 窄窗口均通过实际界面检查；不执行真实清空数据或删除插件等危险操作，仅验证确认与取消流程。
- 功能检查、构建及实机验收通过后才提交并报告完成；交付记录实际结果、提交信息和本地同步状态。
