# 游戏页启动按钮优先显示自定义名称实施方案

状态：用户已确认实施，代码修改与工作树功能验证已完成。

## 目标与验收

游戏页启动按钮的实例名称与实例列表使用相同的显示规则：

1. 优先显示实例自定义名称 `alias`。
2. 未设置自定义名称时显示默认显示名称 `displayName`。
3. 两者都为空时显示版本标识 `versionId`。
4. 当前实例尚未扫描到或数据暂时缺失时，显示原来的 `selectedVersion`，避免按钮名称为空。

例如，版本标识为 `1.21.1-Fabric`、自定义名称为“朋友生存服”的实例，启动按钮显示“朋友生存服”；点击后仍按原版本标识及游戏目录启动。

## 当前情况

- `frontend/src/components/game/GameLaunchBar.vue` 的 `.launch-version` 直接显示 `selectedVersion`，因此不会展示自定义名称。
- 同一组件的最近实例菜单已使用 `instanceDisplayName()`，匹配时检查版本标识及规范化后的游戏目录。
- `frontend/src/features/instances/model/instancePresentation.ts` 已有共用规则 `alias || displayName || versionId`，实例列表也使用该规则。
- `instanceStore.scannedVersions` 保存完整实例元数据；实例扫描及变更事件会更新该响应式数组，可以直接用于派生按钮名称。
- 当前名称样式已使用省略号并限制宽度，自定义名称较长时仍需保留紧凑布局。

## 方案选择

| 方案 | 名称优先级 | 取舍 |
| --- | --- | --- |
| 1（已选择） | 自定义名称 → 默认显示名称 → 版本标识 | 与实例列表和最近实例菜单一致，复用现有共用规则。 |
| 2 | 自定义名称 → 原版本标识 | 只新增别名支持，但没有别名时可能与实例列表显示不同。 |

## 具体改动

### 前端组件

在 `GameLaunchBar.vue` 中完成以下调整：

- 将既有实例匹配辅助函数整理为接收版本标识和游戏目录的形式，供启动按钮与最近实例菜单共用。
- 新增计算属性，以 `selectedVersion` 和 `currentGamePath` 为依据，查找 `instanceStore.scannedVersions` 中的当前实例。
- 路径比较继续使用 `normalizeGamePath()`，兼容 Windows 分隔符、大小写及尾部分隔符差异；不得仅凭版本标识匹配，否则不同目录中的同标识实例会串名。
- 匹配成功后调用 `instanceDisplayName()`；匹配失败时回退到 `selectedVersion`。
- `.launch-version` 改为显示计算得到的名称，并通过 `title` 展示完整名称，保留既有省略样式。
- 名称随着当前选择和实例元数据更新而重新计算；不保存额外的名称副本。
- 保留启动参数、版本选择、禁用条件、启动状态文案、最近实例操作及按钮布局。

本次不新增后端接口、配置字段或翻译条目，也不改写实例目录和版本标识。

### 回归测试

在 `GameLaunchBar.test.ts` 中补充实际组件渲染测试：

- 同时存在自定义名称和默认显示名称时，优先显示自定义名称；此用例在原版上必须失败。
- 无自定义名称时显示默认显示名称；两种名称都为空时显示版本标识。
- 未扫描到当前实例时回退到 `selectedVersion`。
- 不同游戏目录存在相同版本标识时，按当前目录显示正确名称。
- 游戏目录分隔符、大小写及尾部分隔符不同但规范化后相同时，仍能匹配。
- 修改扫描结果中的自定义名称或切换当前实例后，按钮名称响应式更新。
- 完整名称出现在 `title` 中；启动事件仍正常发出，名称展示不修改内部版本选择。
- 保持最近实例菜单原有显示及事件测试通过。
