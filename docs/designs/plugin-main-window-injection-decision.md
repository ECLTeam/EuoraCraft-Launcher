# 第三方插件主窗口界面注入决策

日期：2026-11-01，Asia/Shanghai。状态：用户已明确选择，本文件记录该选择及其约束。

## 1. 决策

第三方插件除声明式面板外，允许通过宿主注册 HTML 片段与 Vue 组件到主窗口插槽，与现有系统插件使用同一套插槽机制。目标是把界面拓展性与自由度交给插件作者，不要求界面只能由受限节点拼装。

本决策由用户在「独立 WebView 窗口」与「主窗口注入」之间明确选择后者，并已知悉它推翻[三批方案](../plans/plugin-three-batch-implementation-plan-2026-10-31.md)第 7 节「主窗口任意脚本注入」不作为缺陷补做的边界。该节对该能力的排除自本日起失效，其余边界继续有效。

## 2. 仍然不变的边界

- 插件仍运行在独立 Worker 进程，不取得宿主 Python 对象、IPC 句柄或实例/账户的裸数据。
- 业务能力仍由 Broker 按 `plugin.base`、`instances.*`、`network.read` 等能力校验；界面自由不等于数据自由。
- 不开放宿主配置任意读写、通用账号令牌导出、直接调用全部 IPC、任意用户路径操作、强制停止其他来源进程。
- 撤销授权、禁用、卸载后，插件注册的插槽内容必须失效，主窗口不得继续显示或执行旧内容。

## 3. 已知风险

| 风险 | 说明 |
| --- | --- |
| DOM 与运行时暴露 | 注入内容与主窗口同文档、同 JS 运行时，可读取页面上的账户摘要、实例列表等已渲染数据 |
| 通用桥可达 | 若注入内容能调用通用 IPC，等于绕过 Broker 的授权检查，插件取得其未被批准的能力 |
| 供应链 | 插槽内容随插件包分发，用户审阅时看到的是权限清单，不是注入内容本身 |
| 现有沙箱证据 | `tests/test_plugin_webview_gate.py` 已证明 sandbox iframe 无法阻止子 frame 自导航，不能把 iframe 当作隔离手段 |

这些风险是选择本路线时接受的代价，不通过「加一层 CSP」宣称已经解决。

## 4. 实施时必须具备的控制

| 控制 | 要求 |
| --- | --- |
| 权限门禁 | 新增独立能力（暂定 `ui.inject`），与业务权限分开审阅；未批准时注册失败，不是静默降级 |
| 来源与归属 | 每条注入内容绑定安装标识、运行代次与授权版本；代次变化后旧内容不可再渲染 |
| 通用桥隔离 | 注入内容只能通过宿主提供的受限消息通道调用其**已获准**命令，不接触通用 `invoke` |
| 失效与清理 | 禁用、撤销、卸载、Worker 退出时撤销插槽内容；主窗口按代次丢弃迟到注册 |
| 审阅可见性 | 授权界面明确告知「该插件可以修改启动器界面」，不把它并入现有权限文案 |
| 可关闭 | 提供用户级开关，关闭后不渲染任何第三方注入内容，已安装插件不受影响 |

## 5. 与声明式面板的关系

两者并存，不是替代：

- 声明式面板用于结构简单、需要宿主统一外观的场景，插件不写模板。
- 插槽注入用于插件需要自有布局、富文本、图表或复杂交互的场景。
- 同一次运行可同时使用；面板按钮与插槽内容都只能调用本插件已登记命令。

## 6. 验收口径

- 未批准 `ui.inject` 的插件注册插槽失败，主窗口不出现任何第三方内容。
- 批准后插槽内容按代次渲染；禁用插件后主窗口立即移除，重启用出现新代次内容。
- 注入内容无法调用未获准的 Host API，越权调用返回稳定错误码。
- 六语言、亮暗主题、最小窗口下布局与键盘焦点可用。
- 关闭用户级开关后，任何插件都不能向主窗口注入内容。

## 7. 实施状态

已实现：`ui.inject` 独立权限与审阅入口、`ui.register_html` / `ui.register_vue` 边界校验、按安装的插槽清理、用户级总开关 `plugins.allow_ui_injection`（关闭后拒绝注册并撤销已注入内容）、清理事件下发到前端。

未实现：第 4 节要求的「通用桥隔离」。注入内容与主窗口同页运行，仍可访问页面上的通用桥；这是本路线已知且未被消除的风险，不作为已完成项对外描述。真实桌面端到端验收也尚未执行。
