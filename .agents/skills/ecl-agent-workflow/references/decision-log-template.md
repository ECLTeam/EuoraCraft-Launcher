## 示例

```markdown
# ADR-017：导出实例统一 Modrinth 格式并移除私有 ecl 导出

- **日期**：2026-08-20

- **状态**：已实施

- **决策者**：AI agent

## 背景

ECL 导出实例时同时支持私有 `.ecl` 格式和 Modrinth 格式，维护两套导出逻辑成本高。

## 选项

### 选项 1：仅保留 Modrinth 格式

- 优点：标准化、社区兼容、减少维护量

- 缺点：不支持导出私有元数据（如 Java 参数、内存设置）

### 选项 2：保留两种格式

- 优点：功能完整

- 缺点：维护两套序列化/反序列化代码

## 决策

选择了**选项 1**。

理由：

1. Modrinth 是社区标准格式，其他启动器（Prism、ATL）也采用

2. 实例私有设置可通过 `ecl.json` 伴随导出，不依赖私有格式

3. 减少约 40% 的导出维护代码

## 影响

- 正面：统一导出格式，减少维护负担

- 负面：旧版 `.ecl` 文件需手动转换

- 风险：用户可能依赖旧格式

- 缓解：在 UI 中添加提示和转换说明

## 涉及文件

- `ECL/services/game/export.py`：移除 `.ecl` 导出分支

- `ECL/api/models.py`：移除 `EclExportModel`

- `frontend/src/features/instances/api/instanceRuntimeApi.ts`：移除 `.ecl` 导出 API 调用
```

## 快速参考

- 编号：从 `.memory/INDEX.md` 中最大的决策编号 +1

- 状态流转：提案 → 接受 → 已实施

- 废弃的 ADR 标记为"已废弃"，不要删除
